# Stable route interfaces before implementation

Core is read-only to every route. Its finalized API has Field p,quadratic,degree,order/q,zero/one,counter; coerce/add/sub/neg/mul/inv/pow/elements/key/encode. Elements are tuples, None is O. Curve has field,A/B,a/b aliases, O-first lex points,is_on_curve/add/neg/mul. Counter.inc(name,n=1), phase(name) context and snapshot()->{operations,phases}; field.counter and curve.counter are the same. Leaf-exclusive operation allocations and inclusive phase timings must not be double-summed. select_prime_subgroup returns admitted,reason,order,factorization,r,P,G,certificate, with JSON factorization string prime keys. encode_point(field_or_curve,point) is stable.

Every driver exports run_experiment(seed), check_result(result), main(argv=None), accepts --seed 1729 --output-dir <run_dir> and --check <raw-result.json>, and writes exactly raw-result.json + manifest.yaml through truthful core.write_artifacts. A checker verifies certificate substance and exact planned case coverage. It must reject deleted controls, tampered point/ring products, incorrect source parameters or false acceptance; it need not rerun costly LLL to check emitted lattice membership and norm/root witnesses. It cannot treat its own boolean checks as independent review.

Factorbase additionally exports auxiliary_catalog(p=97,depths=(0,1,2,3)); it runs only when called, returns exact curve/map/kernel/fiber certificates including all finite fibers, and accounts its own costs on every call. Catalog entries identify d,a_j,kernel rational points, full-degree admission, finite image B, source rational fiber points and complete intermediate x paths, target subgroup and actual list/map/chain target bases. No unavailable complete-rational-kernel cell is silently replaced. Repeated rebuilding in a later admitted combined run is charged again.

Polynomial exports build_shift_lattice(polynomials,variables,p,weight_bounds,t,L,arm), reduce_and_certify(lattice), extract_and_verify(equations,variables,root_boxes,verification_context). Inputs use Sympy expressions/Poly, ordered explicit symbols, positive weight_bounds and explicit integer root_boxes. Verification context identifies curve,G,target and all source equations/lifts; exact return dictionaries preserve weighted integer rows/basis, support exponent tuples, original shift family, integer-lattice equivalence/membership certificates, n,D,Gram determinant, reduced vectors/polynomials, strict exact norm margins, ideal dimension, extracted roots, actual lift/sign/subgroup witnesses, phase costs and unpriced_work. Multi-polynomial dense system shifts use all nonnegative exponent vectors with sum<=t and p^(t-sum). Sparse-support comparison is the explicit single-polynomial arm in prospective-protocols.json. No arbitrary rational row dropping. These are software sharing interfaces, not commitments that sufficient certified equations exist.

An unsupported required interface/panel is returned to Coordinator before approval. Do not execute full study fixtures in development: p5/p7/p11 arithmetic and invented toy polynomial/ring counterexamples only; unit tests cannot call full run_experiment on study curves. No source record edits, Git writes or official statuses by implementers.
