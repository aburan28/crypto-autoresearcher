Read-only source finding: the current ARM port supplies separate PMULL product and polynomial reduction calls. The IC combined n53 predicate and specialized compact dual-sign query batch are x86-only. The rho raw_inverse is a 53-bit binary exponentiation loop; it is not already Itoh-Tsujii. These facts are in the pinned parent rank/rho fixture source. The proposed architecture work must therefore strengthen common field primitives in rho as well as IC and show both rho comparisons openly.

Four frozen arms are proposed: ic_baseline = validated P2 doubled-capacity full-rank IC; ic_candidate = P3 target-certificate IC plus the exact P2 x_only capacity doubling and the ARM optimizations below; rho_baseline = existing common-PMULL rho; rho_candidate = the same rho algorithm with the common ARM fused primitives and n53 inversion chain. Every arm is one worker and every process is cold in the solver-state sense. All complete output/certificate/group verification stays charged. Parent rho walk semantics and IC generation prefixes are invariants, not performance knobs.

Common ARM primitive work: add guarded aarch64 PMULL multiplication plus the exact fixed two-fold reduction modulo x^53+x^6+x^2+x+1 in a target-feature function; squaring uses the same primitive. Add the existing n53 Itoh-Tsujii exponent chain 1,2,4,8,16,32,48,52 followed by one square, with zero rejected, to both candidate IC and rho. Keep generic n13/other-degree and existing x86 paths. Do not broaden the old x86-only combined predicate into paths that would reach x86-only unreachable branches; use separate ARM guards. Use truthful product/reduction/inversion backend fields.

IC-only kernel work: port the existing x86 specialized compact dual-sign batch to an ARM target-feature function using the common fused primitive and inverse. Move feature checks to the batch entry. Preserve compact key encoding, exceptional point cases, sign order, x-filter behavior, lazy y recovery, exact lookup semantics, point/witness order and rank targeting. Record actual ARM query-branch use for n53; n13 must use its valid generic path. Preserve the inherited RNG domain identifiers while assigning new receipt identifiers independently.

Native controls before solver processes: all 53-by-53 basis products (2,809) against an independently implemented bitwise product/reduction oracle; all 53 basis squares, zero/one/max/alternating-bit edges, and 256 nonzero SHA256-derived 53-bit field values for inverse identity against the generic binary inversion reference and product oracle. Values derive from CSIC53-ARMCOMPOSE-v1-field-XXX (000..255), full digest little endian, modulo (2^53-1), plus one. Prove the exponent-chain arithmetic symbolically in the control record. Check the exact P3 certificate unit suite at moduli 17 and 21044858204113, including the K75 row74 weights/ranks and negative controls.
