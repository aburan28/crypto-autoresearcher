# Compatibility controls before curve-order execution

Frozen 24 October 2026 UTC before the produced ECPP/BigNum binaries are executed. This is build admission, not the candidate-selection experiment. The first four compilation attempts and their amendments remain immutable.

1. Use the built Linux x86/musl static code and a digest-pinned local Linux/386 Alpine image. Start a fresh isolated container for each executable call, with network disabled, read-only mounts/root, all capabilities dropped, no-new-privileges, one CPU, 128 MiB and a bounded process count. Record exact commands, compiler/source/input/binary/image hashes and stdout/stderr. A 30-second per-control watchdog protects the machine; it is not historical runtime.
2. Arithmetic control: verify 4-byte int, long, pointer and BigNumDigit. Compare sum and product for the two initial fixed integers. Then compare add, subtract, multiply and Euclidean divide/remainder for positive-divisor vectors spanning 1 through 521 bits, with exact word-boundary values and a fixed Python fixture seed 0x1997. Fix all vectors and expected integers in a fixture before execution. This checks these paths; it does not certify every arithmetic function.
3. Small classifier controls: default proving enabled, original full catalog and parameter files; run fresh 101, 65537, 15 and 341 inputs. Require correct prime/composite labels and retain certificate output separately. A label is not a general certificate-validation result.
4. Force the named exhaustion path with a copy of the data directory containing an empty discriminant catalog, both N−1/N+1 options disabled and known prime 101. Record the printed label and termination exactly, including a crash or cleanup failure. This is an induced software-failure control; it supplies no frequency or result for the unmodified catalog. A separately missing catalog is a dependency/error control. Neither is a mathematical rejection.
5. Do not admit named NIST/ANSI orders until the actual certificate checker, malformed-certificate and fail-closed launcher gates in REPLAY_REQUIREMENTS.md are complete. A failed control is diagnosed and preserved under a new attempt; a compiler/build failure is not evidence about a curve. No official hypothesis or goal status changes.
