What I expect to be broken, and why:

1. Protocol freeze order (B6). The PR is 17 commits over ~11 hours; PROTOCOL.md
   (05a0ebd92, 16:55) and the amendment (d1be0c1c8, 17:35:49) sit close to the
   session commits. Same-timestamp commits (d1be0c1c8 and fed341c5d both at
   17:35:49) suggest an amendment committed together with, or right after,
   data. I expect at least one session whose first raw-output commit is not a
   strict descendant of the amendment, or an amendment that changes a
   criterion after a session was seen.
2. "Planner validated" wording (B8). Six sessions at toy sizes (24-30 bits)
   are a small-N check of a cost model; I expect wording that generalises
   ("the planner picks the best configuration") beyond the six cells, and a
   best-of-k headline.
3. Matched rho (B5). I expect rho.negation to be the matched reference for
   prime curves (negation map applies to all short-Weierstrass curves), but
   I expect the rho interpolation tables in planner.rs to be unsourced or
   sourced from a different instrument than the sessions' measured rho.
4. Planner evidence citations (B1/B7). A planner with hard-coded rules citing
   research files: I expect at least one citation that does not support the
   rule (different curve family, different size, or a stale file), and the
   Koblitz kappa = 0.6 to be a fitted or recalled constant, not a measured one.
5. The 12 restored plan.json files (B7). "Restored" files added after the
   sessions were sealed are the classic reseal risk. I expect the hashes to
   match (otherwise the PR would not be green), so the question is
   legitimacy: if plan.json is regenerated by current code, a hash match
   proves the current PlanDoc expansion equals the old one, which is fine; if
   it was hand-edited to match, it is not. Expect: legitimate but weakly
   evidenced.
6. Leaderboard (B8). A post-merge commit (6a3605965, "refreeze it as
   pre-gate") already touched the planner row, so I expect the merged row to
   differ from what main now shows, and possibly an "advance" class or a
   progress point (ec-cold 14.39) that reads as a gain when it is an
   engineering/planning change.
7. Workflow (B7). RUNPATH symlinks and zstd in a SAT runtime step: I expect
   the change to keep the hash gate on the interpreter but possibly to make
   the symlink target unhashed.
