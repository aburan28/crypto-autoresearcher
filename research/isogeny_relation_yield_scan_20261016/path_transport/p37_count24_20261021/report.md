# P37 vertex 24 public targetwise count control (2026-10-21)

This report records an implementation control, with no hypothesis-status or performance verdict. It asks whether the complete signed source `low_x` base and its saved transport through 24 degree-7 edges give identical exact ordered three-point counts on the same 128 public target scalars. These points are excluded from graph-wide discovery and confirmation inference.

## Observations

The [source counts](source.count) and [transported counts](transported.count) are byte-identical, SHA-256 `f799d1cd80cdacd125d4ad0e1681ce5e704da836c569b3e12b11763ba144d473`; that digest also matches the earlier first-check P37 source count file. All **128/128** targetwise ordered counts agree. Seven targets are nonempty, with **48 ordered relations** total: indices 9, 27, 32, 104, 117, and 127 have six each, and index 18 has twelve. The [comparison record](comparison.json) has `status: pass`. The [SVG](counts.svg), regenerated by [render_graph.py](render_graph.py), plots the recorded counts on both endpoints.

The source counter meter recorded **26.24 s wall, 3.48 s user CPU, 0.14 s system CPU**, and **289,685,504 bytes maximum RSS**; the transported counter recorded **8.01 s wall, 4.75 s user CPU, 0.11 s system CPU**, and **289,587,200 bytes maximum RSS**. Both had zero swaps. Raw meter logs are [source](source.time.stderr) and [destination](transported.time.stderr). These host-contended wall times are descriptive and do not support a relative speed claim.

## Scope and next check

This control checks targetwise equality for exactly these 128 public points and this saved path endpoint. The same counter implementation ran on both endpoints; its completeness over the full large group is not certified by this equality alone. The independent small-group exhaustive oracle and earlier first-check control cover narrower counter checks. The post-freeze discovery stream, graph-wide native-base comparison, useful-rank replay, and full same-point ECDLP costs remain unmeasured.
