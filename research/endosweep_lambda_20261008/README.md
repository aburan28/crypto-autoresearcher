# λ-coordinates on the NIST binary curves, and a binary GLS curve with λ-coordinates

**Question.**  [`../endosweep_nist_20261006`](../endosweep_nist_20261006/README.md)
counted scalar multiplication on the ten NIST binary curves in López–Dahab
(LD) coordinates. Its best-TNAF to best-wNAF ratio on the K-curves was
2.55–2.91 with squarings free and 1.61–1.64 with S = M. This directory
answers three questions:

1. Do the λ-projective formulas of Oliveira, López, Aranha and
   Rodríguez-Henríquez ("Lambda coordinates for binary elliptic curves",
   CHES 2013 / JCEN 2014) cost what the paper says?
2. What do they change when they replace LD on every NIST binary curve? We
   were handed a hypothesis to test: *λ mainly saves squarings in additions,
   so the S = M TNAF/wNAF ratio rises to ≥ 1.70, while the S-free ratio moves
   by less than 3 %.*
3. The binary GLS gap. What does the paper's own setting, a GLS curve over
   F_{2^254} with ψ and 2-GLV in λ-coordinates, cost when it is built and
   counted here? How does that compare with the Koblitz curves' TNAF?

Everything is regenerated by two commands. The first takes about 10 minutes
under `nice` on a loaded machine, the second about 6 minutes:

```sh
python -m harness.endosweep.lambdacoord --std-curves STD_CURVES_CHECKOUT \
    --out-dir research/endosweep_lambda_20261008
python -m harness.endosweep.gls --m 127 \
    --nist-json research/endosweep_lambda_20261008/lambda.json \
    --out-dir research/endosweep_lambda_20261008
python -m pytest -q tests/test_endosweep_lambda.py
```

`STD_CURVES_CHECKOUT` is J08nY/std-curves at commit
`77fe6e3585ca2c2225b59d7df24b7c775437276f`, recorded in `lambda.json`. It is
the same checkout the earlier NIST run used.

**Sources.**
* The literature notes [KN-LIT-4623] (λ-coordinates) and [KN-LIT-6732]
  (Taverne et al., carry-less multiplier) quote only the abstracts. They give
  no operation counts.
* The counts quoted below come from the paper itself: the CHES 2013 archive
  PDF, <https://www.iacr.org/archive/ches2013/80860113/80860113.pdf>, sha256
  `6fc2c8e9…a16ac` (full hash in `lambda.json`). This file is the "local
  copy" `80860113.pdf` that KN-LIT-4623 names.
* The quotes are from Theorems 1–3, Table 3, §3.2, §4.3 and Appendix B.
* The JCEN 2014 version was not read.

## What is checked

* **Every λ formula against the affine group law.** The checks use
  `binary.BinaryCurve`'s affine `add`/`dbl` on random points with random
  projective scalings, on K-163, B-163 and K-283 (tests) and on all ten NIST
  curves (`formula_checks` in `lambda.json`). The formulas checked are:
  * the curve equation (L² + LZ + aZ²)X² = X⁴ + bZ⁴;
  * the conversions, and negation (λ → λ + 1);
  * doubling, both the Theorem 1 formula and the alternative L_2P;
  * full addition (Theorem 2) and mixed addition (Theorem 2 with Z_P = 1);
  * doubling-and-addition 2Q + P (Theorem 3);
  * the Frobenius map (X², L², Z²).

  The edge cases checked are P + (−P) = O, P + P = 2P, 2Q + (−2Q) = O,
  2Q + 2Q = 4Q (where Theorem 3's B = 0, so the code falls back to a doubling
  and a mixed addition) and O inputs. All pass on every curve.
* **Operation counts are measured.** Each formula is run once, and the field
  operations it executes are counted (`op_counts`).
* **Counted scalar multiplication on all ten NIST binary curves.**
  * Configurations: wNAF and width-w TNAF (on the K-curves), widths 2–7,
    32 scalars, in LD and in λ, plus λ wNAF with the doubling-and-addition
    fused into the main loop ("wNAF+DA").
  * The λ code mirrors `binary.mul_wnaf_counted` / `mul_tnaf_counted` step
    for step: the same precomputation order, an affine (here λ-affine) table
    from one batched Itoh–Tsujii inversion, and the same final conversion.
  * The LD numbers come from `binary.py`, unchanged, on the same scalars
    (the same seed). They reproduce `endosweep_nist_20261006/nist.json` to
    the digit.
  * For every scalar, all 30 configurations (18 on a B-curve) return the
    same point. The first two scalars are also checked against affine
    double-and-add.
* **The GLS curve's group order is proven, not assumed.**
  * The trace of E/F_q comes from Mestre's AGM. The AGM agrees with
    brute-force point counts at m = 7, 11 and 13.
  * The twist formula #Ẽ(F_q²) = (q − 1)² + t² agrees with a brute-force
    count over F_q² at m = 5 and 7.
  * The order of the full-size curve is then proven by `binary.verify`:
    r is prime, r > 4q, and a point is killed by 2r but not by 2.
  * As a further check of the AGM, points of E/F_q are killed by q + 1 − t,
    and points of its twist by q + 1 + t.

## Results

### 1. Per-operation counts: measured vs the paper's Table 3

Table 3 is stated over F_{q²}. In the measured column, m_c is a
multiplication by a curve constant, which the harness counts separately.

| operation | paper (Table 3) | measured on B-163 (a = 1) | measured on K-163 (a = b = 1) | measured on the GLS curve (F_q² ops → F_q ops) |
|:--|:--|:--|:--|:--|
| λ full addition | 11M + 2S | 11M + 2S | 11M + 2S | 11M + 2S → 33M + 4S |
| λ mixed addition | 8M + 2S | 8M + 2S | 8M + 2S | 8M + 2S → 24M + 4S |
| λ doubling (Thm 1) | 4M + m_a + 4S | 4M + 4S (m_a free, a = 1) | 4M + 4S | 4M + m_a + 4S → 12M + 8S (m_a = ·u is free) |
| λ doubling (alternative L_2P) | 3M + m_a + m_b + 4S | 3M + 1 m_(a²+b) + 4S | **3M + 3S** (a² + b = 0) | 3M + m_a + m_(a+1) + m_(a²+b) + 4S → 11M + 8S |
| λ doubling-and-addition 2Q + P | 10M + m_a + 6S | 10M + 6S | 10M + 6S | 10M + m_a + 6S → 30M + 12S |
| λ Frobenius / ψ | — | 3S | 3S | ψ: 0 (conjugation and additions) |
| LD doubling | 3M + m_a + m_b + 5S | 3M + 1 m_b + 5S | 3M + 5S | 3M + m_a + m_b + 5S → 11M + 10S |
| LD mixed addition | 8M + m_a + 5S | 8M + 5S | 8M + 5S | 8M + m_a + 5S → 24M + 10S |

**Every count of Table 3 is reproduced.** Two remarks:

* **The alternative doubling needs T = L·(L + Z) + aZ².**
  * The 3M + 4S of the alternative doubling is reached only if T is computed
    this way, which is one multiplication. Computed as in Theorem 1,
    L² + L·Z + aZ² costs one squaring and one multiplication.
  * With the Theorem 1 form of T, the alternative doubling costs
    3M + 5S + m_a + m_b. The fifth squaring is Z⁴, needed for (a² + b)Z⁴.
  * The paper does not say which form it uses. The implementation here uses
    L(L + Z).
  * Where a² + b = 0 (K-163, a = b = 1), the Z⁴ term disappears altogether,
    leaving 3M + 3S. Where a² + b = 1 (K-233, K-283, K-409, K-571, all with
    a = 0), the multiplication is free but the squaring stays: 3M + 4S.
  * On the B-curves, m_(a²+b) is a full multiplication, so both doubling
    formulas cost 4M + 4S. The code uses Theorem 1.
* **On the GLS curve, the constants are cheap** (a′ = u, b ∈ F_q):
  * multiplying by u, or by a + 1 = u², costs no F_q multiplications;
  * multiplying by b ∈ F_q costs 2;
  * multiplying by a² + b = (1 + b) + u costs 2.

  So the alternative doubling is 11M + 8S in F_q against 12M + 8S. The code
  picks the cheaper doubling per curve from these costs.

The paper's §4 "Lambda Coordinates Aftermath" estimates the 2-GLV
double-and-add main loop for a 254-bit scalar with 4-NAF at
**872m̃ + 889s̃ (LD)** and **823m̃ + 610s̃ (λ)**. They count m̃_b as 2/3 m̃
and exclude pre- and post-computation.

* Its own Appendix B formula reproduces both pairs exactly, with
  n = 254, w = 4, m̃_b = 2/3 m̃, and the Theorem 1 doubling (4m̃ + 4s̃) on
  the λ side.
* The counts executed here, on the curve below (w = 4, mean of 32 scalars),
  are **857.8m̃ + 872.2s̃ (LD)** and **784.2m̃ + 597.1s̃ (λ with DA)**. These
  are 1.6 % / 1.9 % and 4.7 % / 2.1 % lower than the estimates.
* Two things account for the difference:
  * The executed half-scalars have about 126 bits, not 127, so there are
    fewer iterations.
  * On the λ side, the cheaper alternative doubling is used. Using it in the
    paper's formula instead of the Theorem 1 doubling gives 795.9m̃.

With squarings free (M + m_c):

* λ and LD are identical to within the final conversion (+1M). Every λ
  formula has the same M count as its LD counterpart on these curves. This
  holds for the doubling as well, because m_b is counted as an M on the
  B-curves (Theorem 1 doubling 4M against LD's 3M + m_b).
* Only the doubling-and-addition saves multiplications. On a B-curve it
  replaces 12M with 10M, and on a K-curve 11M with 10M.
* As a result, λ wNAF+DA is 3.4–4.0 % cheaper than LD on the K-curves and
  5.8–6.7 % cheaper on the B-curves.
* The S-free TNAF/wNAF ratios are 2.542 / 2.610 / 2.679 / 2.796 / 2.907
  (λ), against LD's 2.547 / 2.614 / 2.682 / 2.799 / 2.909.

`lambda.md` has all four columns per curve and every configuration. The
four columns are S free or S = M, each with the input point given λ-affine
or affine.

**The input-conversion caveat.** LD takes the affine input (x, y) as is. λ
needs (x, x + y/x), which costs one inversion: 1I + 1M, the inversion being
Itoh–Tsujii, about m − 1 squarings.

* The paper's precomputation accounting (one ĩ for the whole table) assumes
  the base point is already λ-affine. The primary columns above do the same.
* If the conversion is charged, then at S = M the λ TNAF becomes *more*
  expensive than LD TNAF on every K-curve: by 4.3 % (K-163), 5.0 %, 5.3 %,
  5.5 % and 6.1 % (K-571). There are only about m/(w+1) additions, each
  saving 3S, which is roughly 0.6m squarings, less than the m − 1 squarings
  of the inversion.
* With the conversion charged, the λ wNAF saving at S = M shrinks to
  3.9–12.7 %, and 5.6–12.7 % with DA.
* An implementation could fold x_P⁻¹ into the table's batched inversion
  (about 4M) if it used P projectively before the batch, which costs 3M
  more per precomputation addition. That variant was not implemented.
  Charged that way, the cost would sit close to the primary columns.

All the numbers are in `lambda.md` (the "conversion included" tables).

### 3. The binary GLS curve (built, proven, counted)

**The instance.** It is constructed here, because the paper does not print
its b.

* The field is the paper's tower: F_q = F₂[x]/(x¹²⁷ + x⁶³ + 1) (checked
  irreducible) and F_q² = F_q[u]/(u² + u + 1).
* The curve is Ẽ: y² + xy = x³ + u·x² + b with
  b = `0x5f23a6ac3d9b2dea0a4daed45ce6b2e9` ∈ F_q. This b is the 30th
  candidate of a seeded stream (seed 20261008). The search took 131 s of AGM.
* The trace of E/F_q is t = 20 251 382 237 556 413 037.
* #Ẽ(F_q²) = (q − 1)² + t² = 2r, with r prime and log₂ r = 253.0. This is
  proven: r > 4q and a point is killed by 2r. The generator G and r are in
  `gls.json`.

**ψ.**

* The map is ψ(x, y) = (x^q, y^q + u·x^q). In λ-affine form it is
  (x^q, λ^q + u). This is the paper's ψ(P) = ((x₀+x₁) + x₁u, (λ₀+λ₁) + (λ₁+1)u),
  and it costs no field multiplication.
* ψ² = −1 holds on random points, and ψ is additive.
* ψ(G) = [δ]G with δ² ≡ −1 (mod r) and δ·t ≡ −(q − 1) (mod r). This is the
  expected relation, since ψ² − tψ + q = 0 and ψ² = −1.
* The 2-GLV lattice (`lattice.py`) gives a Babai bound of 127 bits. The
  largest coefficient over 256 scalars has 126 bits, against 126.5 for a
  perfectly balanced split.

**k·G**, mean F_q operations over 32 scalars, best width, input in the
method's own form. Every configuration agrees, and the first two scalars
agree with affine double-and-add.

| λ 1-D wNAF | 4127 (w5) | 16.31 | 6634 (w5) | 26.22 |

## Findings

1. **λ-coordinates cost exactly what Table 3 says.**
   * The full addition, mixed addition and doubling-and-addition have 2
     fewer squarings, 3 fewer squarings, and one multiplication less than
     doubling followed by mixed addition, respectively.
   * The alternative doubling reaches the stated 3M + 4S only with
     T = L(L + Z) + aZ². With Theorem 1's T it costs 3M + 5S.
   * The paper's 2-GLV main-loop estimates (872m̃ + 889s̃ for LD,
     823m̃ + 610s̃ for λ) follow exactly from its own Appendix B formula. The
     executed counts here are 2–5 % below them, for the stated reasons.
2. **The handed hypothesis is refuted.**
   * Its S-free half held: the ratio moved by −0.1 % to −0.2 %, well inside
     ±3 %. With the input conversion charged it moved −1.1 % to −2.1 %.
   * Its S = M half failed. The TNAF/wNAF ratio *fell*, from 1.61–1.64 to
     1.39–1.56, and to 1.34–1.48 with the conversion charged. It did not
     rise to ≥ 1.70 on any K-curve.
   * **Why it fell.** The premise "λ mainly saves squarings in *additions*"
     holds for TNAF, but λ also saves a squaring in every *doubling*: 4S
     against LD's 5S, and on K-163 3S against 5S. The m doublings dominate
     wNAF, while TNAF replaces them with Frobenius maps, which cost 3S in
     both systems.
   * Roughly, λ removes about (1 + 3/(w+1))·m squarings from wNAF and only
     3m/(w+1) from TNAF. Example for K-283: (3599 − 1.6·283)/(2210 −
     0.6·283) ≈ 1.54, against 1.548 measured.
3. **The absolute savings of λ over LD**, at S = M with the input λ-affine:
   * wNAF: 11.5–20.9 % (11.5–13.2 % on every curve but K-163);
   * wNAF+DA: 13.8–20.9 %;
   * TNAF: 7.4–8.7 %.

   With squarings free, λ saves nothing except through the
   doubling-and-addition (3–7 %). Charging the one-inversion input
   conversion turns the TNAF saving into a loss of 4.3–6.1 % on every
   K-curve.
4. **The binary GLS gap is closed at full size.**
   * A 253-bit prime-order subgroup on the paper's F_{2^254} tower was built
     with a proven order, a verified ψ (ψ² = −1, eigenvalue δ) and a 2-GLV
     split whose coefficients have about 126 bits.
   * Counted λ 2-GLV with doubling-and-addition costs 4015 F_{2^127}
     operations at S = M, or 15.9 per bit of r. That is 1.59× cheaper than
     λ 1-D on the same curve, and 16.5 % cheaper than LD 2-GLV.
5. **The comparison with the Koblitz curves' TNAF depends on the field-cost
   model.**
   * In each field's own multiplications, TNAF is 2.1–2.3× cheaper per bit
     at S = M (7.0–7.4 against 15.9) and 5–6× cheaper with squarings
     free. GLS needs about 127 doublings (each 11M + 8S over F_q), where
     TNAF needs only squarings.
   * Under the modelled word-Karatsuba weighting, GLS-λ costs about the same
     per bit as K-163 (15.9 against 14.1). It is cheaper than K-233 through
     K-571 (22–77), because their fields are 2–4.5 times as wide as F_2^127.
   * That conclusion is the model's, not the counts'. Halving (which the
     paper's fastest code uses) was not counted for either.

## Scope

* **Operation counts, not timings.** Squarings are bracketed (free, or as
  dear as a multiplication) rather than assumed.
  * Additions in F_q, and therefore ψ and the multiplications by u, are not
    counted.
  * A real carry-less-multiplier implementation (the paper's Table 5:
    S ≈ 0.14–0.21 M) sits between the two columns.
* **Halve-and-add was not implemented.** That is the paper's fastest
  method, where λ's advantage is largest: no conversion is needed for
  halved points. τ-and-add on GLS was not implemented either.
* **The paper's GLS curve is not reproduced.**
  * The CHES version does not print its b, so b here is our own.
  * The paper notes that b must be checked against the generalised GHS
    attack. **No gGHS check was done here.** This curve is a counting
    vehicle, not a recommendation, and nothing here is a security claim.
* **Not done:** the paper's precomputation with R, S = 2Q ± P, and its
  atomic 2Q + P_i + P_j (17m̃ + m̃_a + 8s̃). Instead, the precomputation
  mirrors `binary.py`'s, so the LD and λ columns differ only in formulas.
* **All measured results above are also modelled in one sense.** They price
  a constant multiplication by its real F_q cost: free when the constant is
  0, 1 or u, and 2M for an F_q constant over F_q². On the B-curves, one
  multiplication by b counts as a full M.
