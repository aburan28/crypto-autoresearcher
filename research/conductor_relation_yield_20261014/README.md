## Question and estimands

Does a native factor base on the floor of a large prime-conductor isogeny step produce a different **three-summand** relation yield from the crater, at fixed field, group order, target law, base cardinality and relation definition? The same analysis asks whether any observed change survives a random-point base and a coordinate-presentation null. The exact, targetwise equality of decompositions under an injective isogeny with a *transported* base is a correctness control, not a possible source of yield gain.

The oracle counts exact elliptic-curve group-law triples using a two-sum table. This isolates mathematical relation availability. It does not time a Semaev/Gröbner decomposition solver, and a rank increment alone does not certify completion of an index-calculus DLP pipeline.

For an endpoint `E`, a frozen set `F` of signed points and a uniformly sampled nonidentity target `R` in the prime-order group `G`, define `D_E(R)` as the number of **unordered multisets of three points** from `F` whose sum is `R`. Define an eligible useful triple as one with three distinct point IDs, no opposite pair, and a canonical nonzero relation row after sign folding. Record separately (1) the primary useful nonempty-target indicator, (2) raw `1[D_E(R)>0]`, (3) raw and useful multiplicities, (4) the ordered-triple count, and (5) distinct verified matrix rows and rank increments over `F_r`. Retain repeated and cancellation triples in raw counts and the conservation check even though they do not count as useful rows. The raw ordered mean is exactly `|F|^3/r` over all `R in G`; it cannot by itself establish a curve advantage. Nonempty probability and useful-rank yield can differ even when that mean is fixed.

For each endpoint choose one sealed nonzero scalar `k` and publish `Q=[k]G`, where `G` is the certified generator. The relation collector sees `G` and `Q`, never `k`. Generate SHA-256-derived coefficients `(a_i,b_i)` with an endpoint-domain-separated stream, `a_i` uniform modulo `r` and `b_i` uniform in `1..r-1`; set `R_i=[a_i]G+[b_i]Q`. Reject duplicate or identity `R_i` with a recorded rejection reason until the target quota is full. Marginally, each retained target is uniform over the nonidentity subgroup, while every accepted relation has a known symbolic right side `a_i+b_i k`. The points are **native marginal samples**, since no explicit connecting point map is supplied. Constructed-solvable targets are correctness fixtures only and never enter the yield estimate.

## Primary protocol to freeze

1. **Bind inputs.** Store the exact curve/field/generator specifications, `r` primality and group-order checks, conductor certificates, source commits, and input digests. Confirm the two endpoints in each pair have the same `p`, trace and `r`, and that `gcd(ell,r)=1`.
2. **Factor bases.** On each native endpoint, take the first `B` distinct rational abscissae in increasing integer order, include both signs as distinct points, and reject identity. Use `B=256` for P29 and `B=1600` for P37. A same-cardinality random-point base per endpoint uses a frozen independent seed. Save the complete point lists and hashes. Do not silently normalize by x-space dimension: actual signed cardinality is `2B` and every comparison within a pair uses it exactly.
3. **Targets.** Freeze `32768` distinct nonzero `R_i=[a_i]G+[b_i]Q` per endpoint, with `a_i,b_i` derived from SHA-256 seed `20261014` and unbiased modular rejection; `b_i` is nonzero. Seal `k` away from the collector. Record all generator, duplicate-target and identity rejections. The random-base control reuses the same endpoint targets. Targets are marginal samples on the two curves, not transported points. Keep a separate planted-sum control and an isomorphic presentation control; neither enters primary inference.
4. **Oracle.** Build a hash-indexed two-sum table for the complete signed base, retaining point multiplicity and original point IDs. For each target enumerate every third point, look up the residual, canonicalize a triple by sorted point IDs, and deduplicate. Recompute every admitted sum using an independent point-addition implementation or a separately checked path. Classify repeated-point and opposite-pair triples before useful-row counting. Count empty targets explicitly. At P37 the ordered pair table has at most `3200²=10,240,000` rows before compression; this and peak RSS are first-class feasibility metrics.
5. **Relations and rank.** Give each factor-base abscissa one fixed logarithm column, fold signs into coefficients, and add one common `Q` column. A triple for `R_i` gives a row with three factor-base coefficients, `-b_i` in the `Q` column, and known right side `a_i` (with signs fixed by the chosen group equation). Do not introduce one new column per target. Independently replay accepted rows in the group, hash canonical rows, and measure rank increments modulo `r` in the preregistered target order. The planted `k` is used only by a post-run verifier. Report raw hits, duplicate rows, new-rank rows and cost per new-rank row separately.
6. **Resource accounting.** Record setup, factor-base generation, pair-table build, every target probe, verification, deduplication and rank work, CPU/wall time, memory peak, failures and retries. A process watchdog and memory ceiling protect the host; they do not change the scientific sample count. A censored arm stays visible and yields no completed-arm-only advantage claim.

The exact m=3 occupancy calibration is **not** the ordered mean `|F|³/r` interpreted as a success probability. The ordered means for the two panel sizes are approximately 0.419 and 0.401. Permutations of a typical distinct triple account for six ordered representations. The rough random-group expectation for nonempty targets is therefore `1-exp(-|F|³/(6r))`, about 0.067 and 0.065, respectively. This approximation is for power planning only. Torsion, repeated points, sign symmetry and collisions are resolved by the exact oracle and recorded, not fitted away after observing results. At 32768 targets, an occupancy near 0.066 yields roughly 2160 nonempty targets per endpoint; the unclustered binomial relative standard error would be about 2%, before target and base dependence are considered.

## Predeclared comparisons and interpretation

Primary contrasts are the floor-minus-crater log ratio of **useful** nonempty-target yield **within each pair** under native bases. Report a 99% target-sampling interval for each pair, with the exact numerator/denominator counts and random-base differences. The fixed target lists are independent marginal draws across endpoints, so use a valid two-sample interval rather than a paired target bootstrap. Report raw nonempty occupancy alongside the primary metric. The point estimate and interval for rank-increasing rows per attempted target are co-primary for usefulness. Since each pair has only one chosen floor, target sampling describes this fixed-pair target law and does not estimate variation among all floors or all conductor gaps.

The positive control must recover every planted triple and the same-curve independent oracle must agree on a fixed validation subset. The isomorphic-presentation control uses `u=2` in each prime field, with `x'=u²x`, `y'=u³y`, `a'=u⁴a`, `b'=u⁶b`; transported points, base and targets must conserve `D_E(R)` target by target. A certified isogeny-map transport arm, if later implemented, must likewise conserve each decomposition count exactly when `gcd(ell,r)=1`; a mismatch invalidates the instrument. Native bases need not conserve targetwise counts because they are different sets.

Nominate a native-base lead only if both pairwise 99% intervals exclude one in the same direction, both point estimates exceed a 20% floor/crater ratio shift in that direction, all controls pass, and the rank-usefulness contrast does not reverse it. An interval containing one does not establish equality. If only one pair moves, report pair-specific heterogeneity. If random bases move similarly, attribute no endpoint-native-base mechanism without further controls. A lead then requires a new certified pair, an explicit map/dual and complete target-transfer and recovery pricing before any claim about ECDLP cost. No arity-3 yield result by itself supports an end-to-end speedup.
