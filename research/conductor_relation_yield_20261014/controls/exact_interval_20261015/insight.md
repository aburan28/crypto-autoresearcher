# Exact finite-population interval control

- **Question:** Can the stated 99.75% endpoint intervals be inverted with integer hypergeometric tail decisions at the full P37 population and 32,768-draw scale?
- **Workload and controls:** `test_exact_interval.py` compared 133,137 tail decisions with direct integer binomial-coefficient sums on small populations and checked interval boundaries. A separate synthetic workload used `N=81,640,511,860`, `n=32,768`, and `x=16,384`; this count was chosen for algorithm feasibility and is not a relation-yield measurement.
- **Method:** `exact_interval.py` sums integer hypergeometric numerators and compares them with `C(N,n)/800`. An exact geometric upper bound on the remaining decreasing tail can end a decision early. A complement identity handles the opposite tail. Binary search inverts the integer decisions, with inclusive boundary rules. The four real primary endpoints will each use this 1/800 tail, giving at least 99% simultaneous coverage by Bonferroni.
- **Raw evidence:** The exact commands, source hashes, versions, elapsed times, exit codes, raw RSS field, and stdout/stderr digests are in [receipt.json](receipt.json). The small-case [stdout](0.stdout) and [stderr](0.stderr), and the synthetic full-size [stdout](1.stdout) and [stderr](1.stderr), are retained. Both commands exited 0. A prior uncaptured exploratory full-size invocation also succeeded; it is not the archived timing receipt.
- **Cost and limits:** The captured full-size inversion took the elapsed time in the receipt on one macOS host. Its count is synthetic, so it supports implementation feasibility only. The algorithm has no floating-point tail decision; decimal fractions in the JSON output are display values derived from integer interval endpoints.
