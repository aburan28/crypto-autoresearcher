## Contribution
**Weak keys in the McEliece cryptosystem** — identifying secret keys that,
though generated by the legitimate procedure, admit substantially cheaper
attacks than a typical key.

## Key claims (as reported)
- A class of McEliece keys is weaker than average.
- Weakness arises from properties of the chosen Goppa polynomial / support rather than from implementation error.

## Relevance to this program
Weak-key analysis is the **distributional** question that average-case security
statements can hide: a scheme can be secure for a random key and insecure for a
non-negligible subset of keys, and the key generator is what stands between the
two.

For this program the parallel is direct. An evidence record reporting a solver's
performance over sampled instances describes a distribution, and a claim about
that distribution's mean says nothing about its tail. Rule 4's scoping
requirement covers instance distribution, not only parameter size.
