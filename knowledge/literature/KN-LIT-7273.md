## Contribution
SFE requires expensive public key operations for each input bit of the function. This cost can be avoided by using tamper-proof hardware.

## Key claims (as reported)
- However, all known efficient techniques require the hardware to have long-term secure storage and to be resistant to reset or duplication attacks.
- This is due to the intrinsic use of counters or erasures.
- Known techniques that use resettable tokens rely on expensive primitives, such as generic concurrent ZK, and are out of reach of practice.
- We propose a truly efficient String Oblivious Transfer (OT) technique relying on resettable (actually, stateless) tamper-proof token.
