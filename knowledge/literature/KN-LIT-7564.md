## Claim as stated by the source

The paper proposes augmenting Pollard's rho for ECDLP with "alternative
collisions". Alongside the usual match `R_i = R_j`, each iterate
`R_i = [a_i]P + [b_i]Q` is additionally tested against the fixed set
`{O, P, Q, -P, -Q}`. When a hit occurs the discrete logarithm is read off
directly by solving the resulting linear congruence, e.g. `R_i = O` gives
`k = -a_i/b_i (mod n)` when `gcd(b_i, n) = 1`, and similarly for the other four
cases (attributed to a theorem of Sadkhan and Neamah, 2011). A "reverse
collision" `R_i = -R_j` is also proposed.

The paper claims that because a cyclic group generated by `P` always contains
`O, P, Q, -P, -Q`, these collisions "have always occur[ed]" and "the probability
of a collision has also increased five times compared with original method", and
reports operation counts falling from 18 to 1 (or 12) in a first worked example
and from 48 to 2 (or 38) in a second.

## Independent assessment (this repository, not a ledger-backed finding)

Recorded because the headline claim does not survive checking. This assessment is
analysis performed here; it is **not** promoted evidence and has no EV/DEC record.

**The five-point test contributes Θ(1/√n), not a factor of five.** Rho succeeds on
any repeat among ~√(πn/2) iterates, i.e. Θ(n) candidate *pairs*. The proposed
test succeeds only on 5 fixed targets out of n, so the expected number of hits per
run is `5·√(πn/2)/n = Θ(1/√n)`: about `2^-29` at `n = 2^64`, `2^-61` at `2^128`,
and `2^-125` at `2^256`. The resulting speedup factor is `1 + Θ(1/√n) -> 1`.
Obtaining constant success from the five-point test alone would need `Θ(n)` steps,
worse than rho itself. Since the test adds point comparisons to the inner loop —
which distinguished-point implementations deliberately keep minimal — it is a net
constant-factor *cost* at cryptographic size.

**Both worked examples are determined by their starting points.** Verified by
recomputation: in example 1 (`y² = x³ + 130x + 565` over `F_719`, `ord(P) = 233`,
`k = 158`) the chosen `a_0 = 2, b_0 = 87` satisfy `a_0 + b_0·k = 13748 ≡ 1
(mod 233)`, so `R_0 = P` identically — the start already encodes the answer, and
the "18 operations to 1" is an artifact of that choice rather than a property of
the method. Example 2 behaves the same way at the first step
(`a_1 + b_1·k ≡ 1 (mod 1007)`, so `R_1 = P`). Under random starts these events
have probability `5/233 ≈ 2.1%` and `5/1007 ≈ 0.5%`. No averaging over random
`(a_0, b_0)`, no distribution of iteration counts, and no asymptotic analysis is
reported.

**Example 2's group is composite.** `ord(P) = 1007 = 19 × 53`, so Pohlig–Hellman
resolves that instance in roughly `√19 + √53 ≈ 12` group operations, beating both
the original and the proposed method; it cannot demonstrate an advance.

**What is correct.** The case analysis itself is sound — each case is the linear
congruence `a_i + b_i·k ≡ c (mod n)` solved when the iterate is a known multiple;
all five formulas check out against the paper's own worked values. The "reverse
collision" `R_i = -R_j` is real and useful, but it is the **negation map**, worth
the well-known `√2`, and already present in the paper's own bibliography
(Wiener–Zuccherato 1999; Wang–Zhang 2012). The abstract advertises addressing
fruitless cycles, yet the negation map is precisely what introduces them, and no
cycle-escape mechanism is given.
