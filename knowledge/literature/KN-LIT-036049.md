## What it is

The instance factory behind the SAT-versus-Gröbner point-decomposition (PDP)
comparisons of Trimoska–Ionica–Dequen (`KN-LIT-102cdb`, `SRC-SATIC-TRIMOSKA-2019`).
It fixes the curve

    E : y^2 + xy = x^3 + x^2 + 1   over F_{2^n}   (a = 1 Koblitz-family form),

a factor base V_l = {P : deg x_P < l} (x-coordinate as a polynomial in the Conway
generator), m − 1 = 3 factor-base points, and the **fourth summation polynomial**
S_4(x_1, x_2, x_3, x_R). For a SAT instance it samples P_1, P_2, P_3 ∈ V_l, sets
R = P_1 + P_2 + P_3, and records (n, l, modulus, x_R, x_1‖x_2‖x_3) in an `INFO` file;
for an "UNSAT" instance it draws x_R uniformly and records no certificate. A C program
then Weil-descends the symmetrised S_4 (in the elementary symmetric variables
e_1, e_2, e_3 with the linking equations e_i = σ_i(x_1, x_2, x_3)) and emits the same
system in four formats:

| file | format | consumer |
|---|---|---|
| `Xn*l*-id-{S,U}.anf` | ANF (WDSat dialect: `x .d lits ... T 0`) | WDSat |
| `Xn*l*-id-{S,U}.dimacs` | CNF-XOR DIMACS (`x` lines) | CryptoMiniSat, WDSat |
| `n*l*-id-{S,U}.dimacs` | pure CNF (XOR → CNF by `XORtoCNF.sh`) | any CNF solver |
| `n*l*-id-{S,U}.in` | Magma `BooleanPolynomialRing(N,"grevlex")` + `Variety` | Magma F4 (or any GF(2) Gröbner engine, with field equations added) |

Shipped cells: (n, l) ∈ {(15, 5), (17, 6), (19, 6)}, 20 instances each, ids 1–10 `S`
and 11–20 `U`. Magma-form sizes: 42 variables / 43 equations at l = 5, 51 / 52 at
l = 6 — the "51 variables, 52 equations" of the CP 2020 slide.

## Why it matters to this program

1. **It closes a stated gap.** `RQ-SATIC-1ae57a` and `SRC-SATIC-TRIMOSKA-2019` record
   that every Trimoska number is *reported, not reproduced*, and that WDSat had never
   been fetched, built or run here. With this generator, WDSat
   (`SRC-ICPERF-TRIMOSKA-WDSAT-2024`), and the Gröbner and SAT engines installed on
   this machine, the comparison can be **measured in-repo** on the *same* instances the
   authors used, rather than re-implemented from a description.
2. **It is the PDP anchor for a phase-decomposed cost boundary.** The user's
   `RQ-ICPERF-94c86e` asks for concrete per-phase costs (relation search / PDP,
   linear algebra, descent) for Koblitz, binary and prime-field index calculus. This
   set supplies the PDP phase for the binary Koblitz-form family at l ≤ 6 with a
   certificate per SAT instance, and the generator extends it to any (n, l) once Sage
   (or an equivalent point sampler) is available.
3. **Certificates are explicit.** Each `S` instance carries x_1, x_2, x_3. That makes
   the program's certificate rule (`docs/claims-and-verification.md`) directly
   applicable: a solver's answer is checked against the curve with independent
   arithmetic, never trusted.

## Limits, stated plainly

- The `U` label means "random x_R"; unsatisfiability is **not certified** upstream. A
  Gröbner engine returning the unit ideal is the natural certifier and is part of the
  planned protocol; until then UNSAT is a solver report.
- Only l ≤ 6 is shipped, and WDSat's static `config.h` is sized for exactly that.
  The reported Gröbner memory wall (200 GB at l = 8, claim C5 of
  `SRC-SATIC-TRIMOSKA-2019`) is *outside* the shipped range and cannot be tested from
  these files alone.
- The hard-coded S_4 in `find_points.sage` / `semaev.c` has not been re-derived here;
  the regeneration check shows determinism, not correctness of the formula. The
  certificate control tests instances, not the formula.
- Magma is not available in this repository. Any in-repo "Gröbner baseline" is a
  different engine (Macaulay2 F4 over ZZ/2 with field equations, Singular `std`,
  msolve where characteristic permits) and must be labelled as such; it is **not** a
  reproduction of the Magma column.
