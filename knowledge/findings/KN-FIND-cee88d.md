**Verified provenance, not cryptanalysis.** Nothing here changes the ECDLP,
any attack cost, any twist or invalid-curve analysis, or the safety of any
curve. It does not show that any curve is weak, and it does not show that
none is.

## Finding

These hold for the published parameters (FIPS 186-2, SP 800-186, OpenSSL
3.0.13; prime192v2/v3 and prime239v1-v3 from OpenSSL only). Each was
re-derived by an implementation built from POSIX, FIPS 186-2 and SP 800-186
text that never read the producer's code (EV-SCURVE-e9d71b,
DEC-20261016-82753f).

1. **Prime-curve seeds (replicated).** Each of the ten X9.62 / FIPS 186-2
   prime-curve seeds is one 20-byte block of `(int)(drand48() * 256)` output
   after `srand48(t)`. The first generated byte is the first seed byte.

   | `t` (UTC) | curves (1-based block) |
   |---|---|
   | 863711343 (1997-05-15 15:49:03) | prime239v1 (2185), prime239v2 (2320), prime239v3 (3048) |
   | 863966734 (1997-05-18 14:45:34) | P-192 (139), prime192v3 (5228), prime192v2 (6013) |
   | 871002724 (1997-08-08 01:12:04) | P-521 (1136) |
   | 871696354 (1997-08-16 01:52:34) | P-256 (1842) |
   | 872952608 (1997-08-30 14:50:08) | P-384 (2688) |
   | 891607927 (1998-04-03 12:52:07) | P-224 (7026) |

   The X9.62 seed-to-c map gives `c * b^2 + 27 = 0 (mod p)` with the
   published `b` for all ten. In the controls, the adjacent blocks, the same
   block at `t +/- 1`, reversed seeds and the identifying X9.62 variants all
   fail.
2. **Binary-curve seeds (replicated).** B-233, B-283, B-409 and B-571 are five
   consecutive `lrand48()` words (forward order, big-endian) after
   `srand48(s)`, with `2s` on 1998-04-17 between 15:24:18 and 15:32:08 UTC.
   This is the only matching member of a declared 8-member reading family,
   so the chance bound is about 2^-104 per seed. B-163 is not explained.
3. **Timestamp attribution (strong).** For all ten prime seeds, lattice state
   recovery from the seed bytes alone gives a 48-bit state that regenerates
   all 160 bits. The walk back over 8,000 blocks meets exactly one
   block-aligned `srand48`-form state, and it is the `t` above. A random
   48-bit state regenerates 160 bits with probability 2^-112. Six
   independent 1997-98 dates arise by chance with probability about 10^-11.
   Block-aligned `srand48` states are at least 16,384 blocks apart, so "at
   most one within 8,000 blocks" holds by arithmetic.
4. **Census of the six runs (strong).** Up to each run's last published seed
   there are 21,753 blocks, and 11,042 of them have `-27/c` a nonzero square.
   An independent early-abort re-census agrees with the recorded orders row by
   row (0 mismatches). Under the criteria prime `n`, `bitlen(n) <= bitlen(p)`,
   `n != p`, and `p^k != 1 (mod n)` for `k < 2^10`, the counts are: 21
   accepted (10 published, 11 skipped); 17 rejected because `n` has more bits
   than `p`; 47 where only the twist has prime order. The accepted list
   matches both primary posts 21 of 21. Every prime order used is certified by
   `N * P = O` independently of SEA.
5. **Fixed root (replicated, with a correction).** On all nine published
   `p = 3 (mod 4)` curves, `b` is the `(p+1)/4` root (2^-9 by chance). So the
   1997 code never tried `-b`, which gives the quadratic twist. In the five
   `p = 3 (mod 4)` runs, 31 candidates have a prime-order twist. Five of those
   twist orders have more bits than `p`, so **26**, not 31, would have passed
   the stated criteria (CORR-20261016-10d498; the bundle README says "31 seeds
   were lost" in "four" runs). Whether any of the 26 would have been
   published is unknown. P-224's `b` is the negative of the Tonelli-Shanks
   root taken with the smallest non-residue, 11. Its sign depends on that
   choice.

## Not covered by this finding

- What the native Rust tests in aburan28/crypto check, and the census.sh
  byte-for-byte re-run. These were not examined, and stay preliminary.
- The skip rule: why 11 of 21 accepted candidates were skipped (open:
  `problems/nist-seed-selection-rule-unexplained.md`). The bundle's skip-filter
  screen and generator scans ran outside the repository. Its preregistration
  is self-dated and was first committed together with the census data
  (DEC-20261016-82753f, ruling j7).
- Base points (FreeLIP or otherwise), the B-163 seed, the about-30-bit
  freedom figure (Valsorda; KN-LIT-d2f917), and the bundle's security table.

## Basis and limits

- Proof status: certificate for the regeneration, X9.62, state-recovery,
  root and prime-order facts. Empirical only for the composite (early-abort)
  census rows, whose status rests on two SEA runs sharing PARI/GP.
- Single independent reviewer with no red-team pass. One harness-injected
  file in the reviewer's context was ruled immaterial (DEC-20261016-82753f).
- Census counts are stopped samples: each run ends at its last published seed.
- Relevance: for these historical curves the seed half of "unexplained seed"
  is explained. The selection among accepted candidates is not, and neither are
  the base points of P-224, P-256, P-384, P-521 and the binary curves, so the expected SafeCurves `rigid: false` for P-224, P-256
  and P-384 is unchanged (CORR-20261016-0bf0b2).
