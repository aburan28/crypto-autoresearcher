## 5. Anything unexpected

   caveat for the evidence review. Relatedly, two population rows have
   |D_K| ≤ 20 with `f_E: unresolved` and no crater reached: bls/Bandersnatch
   (D_K = -8) and mnt/mnt1 (D_K = -19). The instrument certifies f_E = 1 only
   for j = 0 or 1728 roots. As a result:
   - their crater or non-crater status, which the arm-A falsification clause
     depends on, is not resolved by this run;
   - their own non-unit endomorphisms are also absent from the baseline.

   I report this descriptively and apply no label.
2. **Dirty flags disagree.** `raw.provenance.dirty` is true but
   `manifest.repository_dirty` is false. run.py's flag checks only
   `git status -- harness`. isomodel's own flag checks the whole tree, which
   included the untracked run directory at launch. The harness sources were
   clean, and the three hashed sources match the run commit. The other harness
   modules are not hashed individually.
3. **No memory record.** Neither the manifest nor the receipt records peak
   memory. The spec cap is 2 GB and the trial-plan watchdog is 2048 MB. Wall
   time is recorded.
4. **Untracked file in the shared working tree.** `harness/endosweep/isoglv.py`
   was untracked when I started, with mtime 19:29Z, after the snapshot commit at
   19:26Z. During this validation another lane committed it in `3a1813d95`
   (EXP-ENDO-7494e7), and HEAD moved on to `f41fa9abb`. It is not in the
   snapshot, and none of my checks imported it, because they ran from
   `git archive` trees. I did not read it.
5. **Ascent control f_E.** The control+ascent row reports `f_E: unresolved`
   although it was built with f = 11. The contract requires only D_K and the
   crater GLV, so this is not a failure.
6. **Receipt status.** The receipt has `published: false` and status
   `output_validated`, which is consistent with a pre-review receipt.
