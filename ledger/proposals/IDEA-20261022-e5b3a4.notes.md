## 3. Matched rho, [derived]

Rho on a group of order r with an automorphism group of order |Aut|: about sqrt(pi r / 4) / sqrt(|Aut|) group additions
(KR-RHO-13bf67, KR-RHO-0528e7). BN and BLS12 have j = 0 so |Aut| = 6.
- BN-254, log2 r about 254: 2^127 * 0.886 / 2.449 = 2^(127 - 1.47) = 2^125.5.
- BLS12-381, log2 r about 254.85: about 2^125.95.
Sanity check against KN-LIT-24b9c7 (114-bit BN, order-6 automorphism, about 2000 cores for 6 months): 2^57 * 0.362 =
2^55.5 steps; 2000 cores * 1.6e7 s = 3.1e10 core-s = 2^34.8 core-s, so about 2^20.7 steps per core-second.
That is a rate of order 10^6 steps/s/core, consistent with KR-RHO-825bca (about 1129 cycles per step). [derived, rough]

## 4. The band, [derived]

AGENTS.md 5a: price every unpriced native operation at w in {0, 0.1, 1} GAE, same way on every arm; rank only where the
order holds at every w. The NFS arm performs no group additions: all of its work is native non-group work. Let C be the
model cost in model operations and N the rho step count with c_native native operations per step.
S_T(w) = w*C, S_rho(w) = N*(1 + w*c_native). The ratio S_T/S_rho = (C/N) * w/(1 + w*c_native) is increasing in w, so
"transfer below rho" holds across the band iff it holds at w = 1; "rho below transfer" holds across the band iff it holds
at w -> 0, which is never (S_T(0) = 0). Therefore the only rankable outcome is transfer < rho, and everything else
is reported "unresolved". Reading: w = 1 charges one point addition per model operation. If a model operation is a
cycle-scale word operation (H3, to be read from BD19), w = 1 over-charges the transfer arm by about 10^3, so the
w = 1 verdict is conservative for a "transfer < rho" claim and generous to rho.
At w = 0 the transfer arm costs zero by construction; report it but never rank on it.

## 5. k* (transfer threshold), [proposed]

Define k*(w, r) as the largest k for which C_model(log2 Q = k * log2 p, variant) * w <= S_rho(w) with log2 p = log2 r *
rho_ratio (rho_ratio 1 for BN, about 1.5 for BLS12-381). Report k* for each variant and each w, and the difference
from `deployed-table.md` (9, 12, 17 for GNFS, exTNFS, SNFS/STNFS at 256-bit l). The prediction is only "different by at
least one on the SexTNFS column"; a sign is not predicted.

## 6. Negative controls

- P-256: ord_n(p) = (n-1)/3, 255 bits [repo, RESEARCH_NIST_CYCLOTOMIC_POINT_HEIGHTS.md section 2.1, exact from the
  complete factorisation of n-1]. P-192 is (n-1)/10, P-224 is (n-1)/3 there.
- secp256k1: ord_n(p) = (n-1)/3 [repo, RESEARCH_SECP256K1_CM.md line ~509, PARI znorder; the note says "253 bits"; recompute]. The
  brief placed this in the cyclotomic note section 2.1; it is not there (that table has P-192, P-224, P-256 only).
- Curve25519: only a lower bound k > 10^6 from direct exponentiation (RUN-ECDLP-393d10); no exact value is claimed.
- Rule: a row whose k exceeds a cap (field element size above 2^20 bits) is refused as "undefined (route does not
  exist)", not priced by extrapolating L-notation to log Q about 2^262, which would print a large finite number and
  look like a price.

## 7. What would make a row measured

Nothing in this repo implements (S)exTNFS or Joux-Pierrot SNFS in F_{p^k}; ecbench has no F_{p^k} NFS (survey T2).
Upgrade path, smallest first: (1) measured norm sizes for the BN/BLS polynomial pairs at toy p (polynomial
selection only, as EXP-ECDLP-2535ec counts doubly-smooth yield for x^d - c at toy p); (2) a counted relation-collection
yield at toy size to test the smoothness law of H1; (3) a full TNFS implementation, a separate multi-month study. Until
(2), no row is `measured`.

## 8. Could it move the baseline?

No. It is an accounting table. A pairing-friendly curve with transfer < rho would be a curve where the best known
ECDLP attack is the transfer (KR-RHO-53c89f), which is a known fact about small-k curves, not an improvement over
the index-calculus baseline in this repository (success criterion, CLAUDE.md).
