## 1. Step count

Domain D: canonical h-tuples of signed base indices, |D| ~ (2U)^h / (h! 2^h) up to the exact
canonical form. f(d) = x-key of the signed sum. H: F_p -> D a hash. s = H o f : D -> D.

* s-merges (s(d) = s(d'), d != d') among t visited points: ~ t^2 / (2|D|).
* A merge is TRUE (f(d) = f(d')) with probability P(f equal) / P(s equal) = (kappa/N) / (1/|D|)
  = kappa |D| / N for non-equivalent tuples.
* True merges found: t^2 / (2|D|) * kappa |D| / N = kappa t^2 / (2N). Setting this to n gives
  t = sqrt(2 n N / kappa), independent of |D| while t << |D|. This equals the table size S needed for
  n coincidences, as it must (same pair count).
* Replay cost: each merge is located by replaying two trails of length ~L, so total replay
  work is L * t^2/(2|D|). It is <= t/10 iff |D| >= 5 L t, hence the stated |D| >= 10 L t.
* Memory: the n certified rows plus the DP store (one entry per distinct DP reached, ~ t/L entries
  if every DP is kept; vOW keeps w entries and pays a time overhead when w < t/L). The claim uses
  memory O(n), which assumes the DP store is capped at O(n) with the standard overhead folded into c_vow.

## 2. Where it sits on the Dinur curve

KR-RHO-7d93f6: C collisions need T^2 S ~ C^2 N. With C = c U = B this is (T, S) = (sqrt(BN), B):
S = B and T^2 S = B N * B = B^2 N. The table has S = T = sqrt(BN) so T^2 S = (BN)^(3/2), larger than
B^2 N by (N/B)^(1/2) > 1. The lean point is on the curve; the table is not. For h = 2, B = N^(1/3):
memory N^(1/3) against N^(2/3), time N^(2/3) in both.

## 3. Why this is not a route past rho

Plain rho finds one collision (the answer) in sqrt(pi N / 2) steps with O(1) memory. The lean harvester
needs n = c U collisions, so t ~ sqrt(2 c U N) >= sqrt(N) for U >= 1. It is the multi-instance rho of
Kuhn-Struik / Yun with a linear-algebra back end, and it is dominated by rho for the ECDLP itself. Its use is
(a) a concrete (T,S) point for the program's own memory column, (b) an instrument that does not hold a table,
so it can be pointed at bases whose table would not fit, and (c) a control for the harvester: if the lean run
and the table run disagree on rows per step, one of them has a counting error.

## 4. Base enlargement

For h = 2 the table-optimal base has |D| ~ t, so the lean condition |D| >= 10 L t needs the base enlarged by
(10 L)^(2/3) in B (|D| ~ B^2). With L ~ 32 this is a factor ~47 in B and ~7 in t. For h = 3 the factor is
(10 L)^(2/5) ~ 8.8 in B. The exponent is unchanged; the constant is the price of not storing the table.

## 5. Symmetry bookkeeping

f(i,j) = f(j,i) and f(-d) = f(d) in the x-key. Canonical form: sort the unsigned indices, normalise the sign
of the first. Without it every tuple merges trivially with its reorderings and the true-merge fraction is
inflated by the symmetry factor (up to 2^h h!). The random-mapping control (replace f by a hash of the
canonical form) isolates this.
