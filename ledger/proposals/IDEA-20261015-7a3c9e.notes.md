## 1. The two online costs at equal precomputation time

Let the quotient have size `r/A` (A = 2n signed-Frobenius classes on a Koblitz
curve with Frobenius of exact order n; A = 2 on an ordinary curve).

**BL** (KR-RHO-ea34b8, KN-LIT-7cc07f Table 4.1, abstract level): table `T`
entries, precomputation `P_steps ≈ 1.2 T²`, online `≈ 1.77 T` steps. Eliminating
`T`: online steps `≈ 1.77 · (P_steps/1.2)^{1/2}`... but the tradeoff we need is
the one §23.2 of the boundary ledger states, `O · P ≈ 1.93 · 1.21 · r/A`, i.e.
`online_steps ≈ c_BL · (r/A) / P_steps` with `c_BL ≈ 2.1–2.3`. In time, with
`P_steps = P / c_step`:

    BL_online_time ≈ c_BL · (r/A) · c_step² / P.

**Folded pair-state IC** (crypto `research/n83_dense_root_20261013`): `#states`
stored states, each representing the `A` sums of one signed-Frobenius class;
the descent walks the target on classes and probes the table by equality. A
probe hits with probability `A · #states / r`, so

    probes_per_target = r / (A · #states),
    IC_online_time    = r · c_probe / (A · #states),
    P                 = #states · c_state   (setup time per state, by definition).

Substituting `#states = P / c_state`:

    IC_online_time = r · c_probe · c_state / (A · P).

**Ratio** (both `r` and `A` cancel):

    IC_online / BL_online = c_probe · c_state / (c_BL · c_step²).

`c_probe` is tens of ns, `c_state` is a batched addition plus canonicalization

## 4. Why A cancels, and the ordinary-curve control

Folding divides the table by `A` and multiplies each state's coverage by `A`;
the probe probability `A · #states / r` is unchanged by folding. BL gets the
full `A` in its online cost through the quotient size. At equal `P`, IC's
`#states = P/c_state` is also unchanged by `A`, so IC's online is
`r · c_probe · c_state / (A P)` — the `A` here is the quotient the walk lives
on, the same `A` BL enjoys. Hence an ordinary curve (A = 2) and a Koblitz curve
(A = 2n) of the same `r` should show the same ratio up to the per-operation
prices. A large measured difference would mean the probe model is wrong.

## 5. The BSGS identity

BSGS on the quotient with a `T`-entry baby table: online `(r/A)/T` lookups.
Folded IC with `#states = T`: online `r/(A · T)` probes. Same count. The
difference is only (a) `c_state` versus one stride addition per entry and
(b) that the IC's base is "implicit" (a prefix predicate on x) — an advantage
it does not use at probe time, since every state is stored. Memory: IC stores
`P/c_state` entries; BL stores `sqrt(P/1.2)` entries. At n = 83 that is 8 GiB
versus megabytes.

## 6. What this does not say

Nothing about m ≥ 3 (Semaev/SAT/Gröbner oracles), where a probe is a solve and
the table stores `B` points but matches `B^m` sums — the only regime in which
index calculus has an exponent argument of its own. On Koblitz curves that
regime is where KN-FIND-b9a41d (subspace net loss at n = 131), KN-FIND-47da4e
(orbit-union SAT cost-neutral) and GOAL-FROB-6333a9 (WDSat pruning, open) sit.
