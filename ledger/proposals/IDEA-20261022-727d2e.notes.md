## 3. The two classes and why two floors

Class E (radix, exact). Look for J*N = sum_{i<=d} c_i m^i with 1 <= c_d <= Clead, |c_i| <= C, J <= Jmax. Since
c_d m^d <= J*N < (c_d+1) m^d (1 + o(1)) the integer m lies within about 2C/d + 2 of (J*N/c_d)^(1/d), so the scan is
Jmax * Clead * window integer d-th roots plus balanced base-m expansions, no lattice. Generic floor for the max digit:
about m/2 = N^(1/d)/2 (digits of a random integer in base m). Planted or designed: the digits are the coefficients.
Examples [derived from algebra; to be confirmed by running]:
- Curve25519 p = 2^255 - 19 = x^5 - 19 at x = 2^51: max digit 19 against a floor of about 2^50.
- Ed448 p = 2^448 - 2^224 - 1 = x^2 - x - 1 at x = 2^224.
- P-192 p = 2^192 - 2^64 - 1 = x^3 - x - 1 at x = 2^64.
- P-521: 2^521 - 1 is x - 1 at 2^521 (degree 1, trivial) and 16 p = x^5 - 16 at x = 2^105 (J = 16).
- BN: p = 36u^4 + 36u^3 + 24u^2 + 6u + 1 (lead 36, d = 4). BLS12-381: 3p = u^6 - 2u^5 + 2u^3 + u + 1 up to the sign of u
  (J = 3, d = 6), from p = (u-1)^2 (u^4 - u^2 + 1)/3 + u [recalled; recompute before relying]. Take p from the parameter
  specifications, not from this note.
- P-256, secp256k1 (d = 8 at m = 2^32), P-224 (d = 7), P-384 (d = 12): outside d <= 6, so with the brief's cap they would
  not flag. Class E is free (digit expansions), so this draft proposes d <= 12 there and keeps the brief's d <= 6 for the
  lattice class. That is a refinement of the brief, flagged for the coordinator.
Class L (lattice, congruence). L_m = {c in Z^(d+1) : sum c_i m^i = 0 mod N}, determinant N, so lambda_1 is about
sqrt((d+1)/(2 pi e)) * N^(1/(d+1)) (Gaussian heuristic); this is the brief's "N^(1/(d+1))" floor, and it is the floor for
one m. Scanning |M| values of m lowers the generic minimum by about |M|^(1/(d+1)), so the null must be taken with the same
scan (H2). L admits any cofactor J = f(m)/N, which E caps at Jmax. m ranges over {2^k, 8 <= k <= n/2} and powers of 10.
Report per (N, d): h_E, h_L (max |c_i| of the shortest vector), the floor, and log2 of the null probability.

The statistic that makes the detector calibrated is the null probability, not the raw height: class E has an analytic
count, class L an empirical null from random primes with the same scan.

## 4. The brief's positive control, honestly

The brief asks that a planted FGHT-style prime be detected. The repo toy builds p = f(m) exactly with g1 = 1 (a conspicuous
trapdoor); class E detects that by construction. An FGHT hidden prime is p = Res(f, g) with g = g1*x - g0 [retrieved: KN-LIT-7635
PDF sec. 4 "Heidi hides her polynomials": Heidi publishes only the resultant], so p = F(g0, g1) = sum c_i g0^i g1^(d-i),
a binary form value with g1 > 1 in general. For such p there is no integer m, and classes E and L (which assume the SNFS
root m is an integer of a searchable shape) are expected to be blind once g1 exceeds the scanned window; that is the
point of the trapdoor (abstract: "detecting that p has this trapdoor seems out of reach"). So the plan has three planted
controls, not one: (i) g1 = 1, J <= Jmax: must flag (the instrument works); (ii) J larger, class L only; (iii) g1 beyond the
window: must NOT flag, and the g1-bit at which power falls to 0 is the census's measured detectability edge. A result "no deployed
prime flags except the designed ones" is only as strong as that edge. An optional class E2 (scan g1 <= G by extracting
digits g1-adically, cost G * window) would push the edge to log2 G bits; not proposed here.

## 5. Null calibration [derived]

Counting bound for class E among integers below 2^n, writing m = (J N / c_d)^(1/d) roughly 2^(n/d): the number of
(m, c_0..c_{d-1}, c_d, J) tuples is at most Jmax * Clead * (m-range) * (2C+1)^d, but m is determined by N up to the window, so
the probability that a uniform n-bit integer is in the class is about Jmax*Clead*(2C+1)^d*window / m^d-ish, i.e.
Jmax*Clead*(2C+1)^d * 2^(-n(1 - 1/d)) up to the O(d) window factor. Worked example, Curve25519, d = 5, C = 19, Jmax = 2^8,
Clead = 2^6: log2 = 14 + 5*log2(39) - 255*0.8 = 14 + 26.4 - 204 = -163.6. Random 256-bit primes: expected false flags
among 1e5 samples about 1e5 * 2^-163 = 0. The empirical negative control therefore tests the implementation, not the
statistic; the statistical content is H1 (primes are not over-represented in the class beyond the 1/ln density), which the
exhaustive n <= 32 enumeration tests directly (about 2e8 primes at n = 32; class E digit scans cost under 1 microsecond each).
For class L the null is continuous and is built from random primes (H2); validate against random-a lattices, then compare
the lower tail (smallest 10 of 1e5 ratios lambda_1/GH vs order statistics of the reference).

## 6. Which integers matter

- N = p: companion F_p^* and F_{p^2}^* DLP (SNFS applies to the characteristic). Consumer exists (FGHT; pairing transfer).
- N = p-1, p+1: no SNFS consumer (SNFS applies to p, not to the group order); their structure matters for Pohlig-Hellman and
  cyclotomic-subgroup attacks, already partly in the slot program (S6). Descriptors only.
- N = r (curve order), t (trace): no known SNFS consumer. Kept because the brief asks and they are free; flags would be
  anomalies to log, not findings.
