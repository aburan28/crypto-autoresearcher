# IDEA-SATIC-m4 notes (derivations, matrix, decision table)

Companion to `IDEA-SATIC-m4.yaml` (id minted by the Coordinator). Question RQ-SATIC-1ae57a, goal GOAL-ICPERF-e6b6a4.
Nothing here is evidence. The m4-sat-cost-pilot numbers are exploratory (its own README says so) and are used only to set
predictions and the instrument gate; none is cited as a result.

## 1. Why alpha < m/2 - 1 is the decision threshold (derivation)
Take l = n/m (the largest l at which a relation exists with constant probability). A target has a decomposition into m
factor-base points with probability ~ 2^{ml}/(m! 2^n) = 1/m!, so ~m! attempts per relation. A relation-collection phase needs
~2^l relations (one per factor-base column, ignoring large primes) so total attempts ~ m!*2^l. Each attempt costs 2^{alpha l}.
Total ~ 2^{(1+alpha)l} = 2^{(1+alpha)n/m}. Rho costs 2^{n/2}. Break-even: (1+alpha)/m < 1/2, i.e. alpha < m/2 - 1.
Values: m=3: 0.5; m=4: 1; m=5: 1.5; m=6: 2. This ignores linear algebra, yield loss from l < n/m, large primes (which change
relations per target: closure-rescope-audit on KN-FIND-aa2efc) and the Frobenius/negation speedups of rho. It is the program's
per-attempt criterion (ctrial-harvest), not an end-to-end claim. At the predicted alpha = m the total exponent is (m+1)n/m
(1.25n at m=4, 1.2n at m=5) against rho's 0.5n.

The competing per-attempt reference points: (m-1)-fold enumeration with an F_2-linear membership test for the last point
costs 2^{(m-1)l}/(m-1)! (IDEA-20260904-96c4f3), i.e. alpha = m-1, so DPLL at alpha = m is dominated by one factor 2^l; the
measured chained-S_3 MITM at m=4 has alpha 2.32 (ctrial-harvest). All three are above m/2-1 for every m>=3 (m-1 > m/2-1,
2.32 > 1). The measurement can therefore only move the program if some configuration is far below every known reference.

## 2. What is already known and what is new (corrections to the handoff wording)
- Trimoska-Ionica-Dequen 2019 (KN-LIT-92b022; `inputs/SATIC-TRIMOSKA-2019/paper_fulltext.md` l.647-649): all experiments at m=3
  (fourth summation polynomial). 2020 version (KN-LIT-102cdb): S_3 (m=2) benchmarks plus the same m=3 work. No m>=4 numbers found.
- Galbraith-Gebregiyorgis 2014 (`inputs/GG-2014-806/paper_fulltext.txt`): MiniSat was run at m=4, l up to 7, but Table 1 is
  "when there exists a solution", with an early-abort protocol; l.1017: "SAT solvers are usually slow when no solution exists".
  Groebner at m=4 reached l in {3,4}, on binary Edwards curves with invariant (symmetric) variables. So "no SAT solver has ever
  been run at m>=4" is true of this program's corpus and of XOR-aware solvers on UNSAT instances, not of the literature.
  The delta of this idea is the UNSAT conflict law in l (the quantity the relation-collection criterion needs, since most attempts
  are UNSAT), XOR-aware, m=5, and the presentation axis.
- The pilot's 63-bit enumerator limit (m4-n23-k5 not labellable) is a tooling gap closed in Stage 0.

## 3. Stage 0 (no claim attached; each item is a gate)
G1 Instrument gate: paper instances Xn15l5, Xn17l6, Xn19l6 (m=3, `-b`), >= 4 UNSAT each; fitted alpha within 3.0 +- 0.05 and
   ratio to 2^{3l}/3! in [0.95,1.1]. Pilot value 2.981 and 1.006-1.023 is the reason the window is that tight; the gate is
   re-run on the frozen build, it is not inherited.
G2 Direct S_5 builder. Specification: S_5(x1..x4,z) = Res_X(S_3(x1,x2,X), S_4(x3,x4,z,X)); Weil-descend each coordinate over
   a polynomial basis of F_{2^n}; Boolean-reduce c^2 = c. Output WDSat ANF with the core bits first (so `-b -m 4 -l l` is
   complete). Correctness: (i) exhaustive over all x-tuples in V^4 at n=13, l<=3 comparing "descended system satisfied" with
   E3, the group-law brute force that enumerates all unordered 4-subsets of {P : x(P) in V} (both y lifts) and tests
   +-P1 +-P2 +-P3 +-P4 = +-Z; this is independent of Semaev; (ii) 10^4 random tuples at n=19. Record per l: number of monomials,
   Boolean degree, build time. A streaming monomial counter that finishes is a deterministic fact; a memory abort is
   infrastructure and does not close the direct presentation (AGENTS rule 3). Expected risk: S_5 has degree 8 in each variable,
   so Boolean degree up to 3 per x-block and large ANF; direct S_6 (m=5, degree 16 per variable) may be infeasible beyond l=2.
   If so, the m=5 presentation axis is chained vs S_4-split only and the report says exactly that.
G3 S_4-split presentation (cheap middle arm; S_4 builder exists from the paper's m=3 instances): m=4: S_4(x0,x1,x2,u)=0,
   S_3(u,x3,z)=0 (one auxiliary field element); m=5: S_4(x0,x1,x2,u)=0, S_4(u,x3,x4,z)=0. Same E1-E3 labelling.
G4 Enumerators: E1 curve-level root solving (pilot2 `chain_solutions`); E2 Boolean count (pilot2 `boolean_count_chain`, widen
   63-bit masks to 128-bit; labelling cost is ~2^{ml}, the same order as the solver, so it is budgeted); E3 above. Labels from E1
   and E2 must agree on every instance; a disagreement voids the instance and is logged.
G5 Completeness gate per configuration: on every UNSAT-labelled instance the solver says UNSAT; every SAT answer carries a
   model that, mapped back to an x-tuple, is verified on the curve. Stock `-b` on chained m>=4 fails this by construction
   (pilot: SAT with undefined bits); it is recorded as `incomplete`, never fitted, never counted as UNSAT.

## 4. Stage 1 matrix (frozen quantities; the executor may not tune after launch)
Cell = (m, presentation, config, curve, n, l). Curves: per n in {13,17,19,23,29,31}, one Koblitz (b=1) and one random
ordinary curve with #E = 2q or 4q, q prime (pilot pick_curve rule), seeds fixed. >= 20 certified UNSAT instances per primary
cell; targets drawn as subgroup points x(kP). SAT-labelled instances: measured and listed separately, never fitted.
- m=4: l=3 (n=13,17), 4 (n=17,19), 5 (n=23), 6 (n=29,31). Required n >= 4l+3 so P(SAT) is small: l=6 needs n >= 27.
- m=5: l=2 (n=13), 3 (n=17), 4 (n=23); l=5 (n=29) declared extension, in the report whether or not it finishes.
- Fixed-n sub-ladders (n=31 at m=4, l=3..6; n=23 at m=5, l=2..4) separate l- from n-dependence.
- Configs: xg (all-variable branching, no pruning), pruned complete (symfull on chains; `-b` on direct and on S_4-split when
  the aux variables are linear given the core, else symfull), stock `-b` on chains recorded incomplete. Unpruned xg capped at
  l <= 5 at m=4 (about 0.5*2^{4l} branch points: 5e5 at l=5, 8e6 at l=6, over any sane budget); the cap is declared, not found.
- Controls (10 instances/cell): CryptoMiniSat (with and without Gauss) and CaDiCaL on the CNF-XOR export, with and without lex
  symmetry clauses on x-blocks; their own conflict counters, compared by slope only.
- Null: support-matched random system per shape (same monomial supports, coefficients resampled, constants chosen so the
  system is UNSAT w.h.p., checked by E2-style count); unpruned configs only because a random system has no S_m symmetry.
  Prediction: null unpruned alpha within 0.3 of structured unpruned alpha. If the null is cheaper by more than a constant, the
  structure of S_{m+1} (not the size ml) is doing work; if equal, size explains the cost, consistent with the backdoor reading.
- Cost estimate (indicative; 1 ms/branch point, from the pilot): pruned m=4 l=6 about 7e5 nodes = 12-25 min/instance, 20
  instances x 2 curves x 2 n = 10-20 CPU-h; unpruned l<=5 about 8-10 CPU-h; m=5 pruned l=4 about 9e3 nodes (seconds); l=5 about
  3e5 nodes (5 min/instance); controls 5-10 CPU-h. Total about 40-60 CPU-h, 4-way parallel. Timeouts are censored and reported
  as such, per-instance budget set so that expected pruned cells complete (3600 s at l=6).

## 5. Statistics
Joint fit log2 c = a_curve + alpha*l over completed UNSAT rows of one (m, P, config) group; 95% CI by cluster bootstrap
(resample instances within cell, then curves; 2000 draws, fixed seed). Also report local slopes (consecutive l), the
scale-free ratio median/(C(2^l+m-1,m)), per-cell max/median, and the n-fixed fit. Censored cells are listed, not imputed
(censoring biases toward index calculus, ctrial-harvest). Alpha from 3-4 l values is a slope over a window, not a law;
the local slopes are the check.

## 6. Decision table (what each outcome means)
| outcome | reading | consequence |
|---|---|---|
| all pruned cells alpha in [m-0.3, m+0.1], ratio in [0.5,2] | H_enum: DPLL is an exhaustive S_m-quotient enumerator at m=3,4,5 | closes DPLL per-attempt route at the tested cells; with (m-1)-fold enumeration dominating, SAT is not the instrument for relation collection |
| alpha in (m-1.3, m-0.3) at some pruned cell, stable across presentations | propagation prunes part of the last block (H_ideal side) | still above m/2-1; identifies the config to extend to larger l |
| alpha(direct) and alpha(chained) differ by > 0.3, pruned | H2 fails: presentation is a lever | tells which presentation to carry to n=131-scale cost extrapolation; ANF cost charged |
| any CI upper < m-1 | H_sub: tree pruned above leaf depth | replicate at larger n and l; check against E3 and null before anything else |
| any CI upper < m/2-1 | criterion met per attempt | escalate to RQ-RELN-001 (yield, linear algebra, rho baseline); not a claim in this record |
| gate G1 or G5 fails | instrument invalid | no fit published; fix and re-run as a new record |

## 8. Expected information gain
The prior from the pilot is strong (alpha 3.82 at m=4 under pruning), so a null outcome is the likely one. The value is
(a) the first m=5 data and the first direct S_{m+1} data point, which is the one axis where the m=3 pilot already shows
presentation moves alpha by 0.4-0.7 unpruned; (b) turning the m >= 4 side of the harvest's gap 1 from extrapolation into a
measured, CI-bearing closure of exact cells; (c) the null and controls that separate "backdoor size" from "XOR/Gauss machinery".
Cheapest first test: Stage 0 G2, because every other arm already runs and G2 alone decides whether the presentation axis exists.
