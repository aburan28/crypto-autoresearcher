## Observation and independent replay

The [frozen manifest](../../../experiments/EXP-FROB-91ee9c/runs/TASK-20260914-7119f2/manifest.yaml)
has SHA-256 `d00b959a892795a9ac8ec853c9839be4f9fb464f30a7fc4d2993dbd6aec32284`.
All **14** named artifacts match both their recorded hashes and sizes; their
combined size is **566,042 bytes**. The separate
[`command.txt`](../../../experiments/EXP-FROB-91ee9c/runs/TASK-20260914-7119f2/command.txt)
and [`environment.json`](../../../experiments/EXP-FROB-91ee9c/runs/TASK-20260914-7119f2/environment.json)
also match their manifest pins.

The archived pure-Python checker (SHA-256
`1aee486fedc6c5da1cfa433466fe49e7461b0cccc849b9c6af8901da6cc47651`)
was run against a temporary copy of the frozen run directory. Its regenerated
[`work/checker-report.json`](../../../experiments/EXP-FROB-91ee9c/runs/TASK-20260914-7119f2/work/checker-report.json)
is byte identical to the archive (SHA-256
`89b4466afba599877aca7733cb39b17d332c97cdedb78a1f19205f4154a3df05`).
The checker independently matches all three reported trace-kernel dimensions
and checks six orbit-divisibility values. Its output calls six entries
`tuple_sum_reverifications`, but [source review of the checker](../../../experiments/EXP-FROB-91ee9c/runs/TASK-20260914-7119f2/checker.py)
shows that its three `ok` entries reconstruct a curve point and check
`[N]G=O`, a probable-prime test for `N`, and the Frobenius action. This audit
also confirms those three `N` values prime by exact trial division. The
checker skips the other three entries for size. It does **not** recompute
tuple sumsets, `p_m`, or any C2/C3/C4 control arm, despite comments in its
source suggesting a broader re-enumeration. The three core cells are recorded
as completed; the extension cell is recorded
as `not_run_resource` after its 540-second checkpoint.

The [frozen specification's C8 control](../../../experiments/EXP-FROB-91ee9c/specification.yaml)
requires independent rechecking of every accepted tuple sum, slot membership,
subgroup order, Frobenius order, and rational identity. This checker covers
only a subset, so **C8 has not passed the specified gate** on this evidence.
The experiment's success criterion is therefore unestablished; this is an
instrument-validation gap, not a falsification of the mathematical hypothesis.
The [specific obstruction](../../../problems/frob-c8-independent-recheck-incomplete.md)
records the exit conditions.

The [raw-curve inventory](audit.json) records two eligible curves per core
cell, with subgroup orders `1051/10061`, `30841/3701`, and
`206461/117991` in cell order. Object-arm records retain aggregate partition
counts and ratios, not per-residue lists. C2 and C3 records exist only for
curve index 0 in each cell, as the original run report discloses. A full
independent C8 recheck must reconstruct the underlying subgroup and slot
membership rather than merely compare stored aggregate fields.

The audit independently recomputes the stored arithmetic on all **23**
`status: ok` partition records: eight object, three C2, six C3, and six C4.
For each it checks `p_m`, `U_neg`, tuple-count products, and the exact reduced
cost ratios for extras 0, 8, and 32. All match. An in-memory changed-ratio
control is rejected. These are aggregate identities; they do not validate
the counts from points, tuple sums, or slot membership.

The separate [FROB-SPLIT object replay](split-object-replay.json), generated
by [`recheck_split.py`](recheck_split.py), reconstructs the q11n5 Frobenius
eigenspace coordinates and both eligible order-`N` subgroups without importing
the Sage driver or its enumeration code. It reclassifies **11,110** nonidentity
subgroup points, reproduces every object-arm partition status, base size,
distinct target count, `p_m`, `U_neg`, and cost ratio, and checks **1,030**
tuple identities. Of these, **100** are nontrivial two-slot point sums; the
other 930 are singleton membership and lookup checks. Exact primality,
`[N]G=O`, and Frobenius action are checked for both stored generators. Three
in-memory mutations (target count, slot size, generator x-coordinate) are
rejected. The replay uses the archived checker's independent finite-field and
elliptic-curve primitives and the stored generator coordinates; it does not
independently establish their original execution custody.
Its deterministic receipt is regenerated with `python3 recheck_split.py --write`
and compared byte for byte with `python3 recheck_split.py --check` from this
report directory.

The generalized [core object-arm replay](core-object-replay.json), generated
by [`recheck_core.py`](recheck_core.py), independently constructs the kernels
of the frozen Frobenius factors for all three core fields. Across all six
eligible curves it classifies **370,100** nonidentity subgroup points and
matches all **36** object partition records (eight populated and 28 empty).
It checks **20,960** tuple identities, including **400** nontrivial multi-slot
point sums; the others are singleton checks. Every recorded object-arm count
and exact ratio matches. The q11n5 mutations above test the related
single-cell implementation; the generalized q13/q19 paths have no separate
mutation battery yet. Run `python3 recheck_core.py --write` or `--check` from
this directory to regenerate or compare the deterministic receipt.

The separate [C2/C3 control replay](c2-c3-control-replay.json), generated by
[`recheck_c2_c3.py`](recheck_c2_c3.py), covers the **first eligible curve in
each core cell**, the only curves with archived C2/C3 records. It independently
reconstructs **238,350** nonidentity subgroup points, verifies the first
non-Frobenius-stable coordinate subspace selected at dimension four, and
matches all three archived C2 residue lists byte for byte as integer lists.
The C2 lists have **102**, **2,370**, and **10,770** members respectively;
**13,242** archived C2 singleton tuple identities, counts, and exact ratios
pass direct point addition. Changing an archived C2 residue in memory is
rejected by the same membership checker. No C2 multi-slot partition was
populated on these first curves.

The replay also checks the six archived C3 aggregate partition records against
valid seeded, negation-closed samples of the required sizes and verifies
**26,620** singleton sums on those newly generated samples. **Those are not
checks of archived C3 tuple identities:** the frozen raw output contains no C3
sampled residue lists. All populated C3 partitions have one slot, so the
recorded target counts and ratios depend only on cardinality and cannot
identify which sample was used. The original source-custody gap compounds that
limitation.

The [C4 null-geometry replay](c4-null-geometry-replay.json), generated by
[`recheck_c4.py`](recheck_c4.py), independently checks lexicographic null-curve
selection on all three core cells. It reconstructs each accepted
`A'=z+a, B'=z+b`, checks nonsingularity and that `j'` is outside `F_q`, and
finds exact point-order witnesses. Combining those orders with Hasse's
interval leaves **one possible curve order** in each accepted case:
`160644`, `370420`, and `2476660`. The same method certifies the two earlier
rejected candidates' recorded orders (`370778`, `2475000`) and their lack of
a matching prime-order factor. The accepted subgroup orders are **1217**,
**18521**, and **123833**, all exact primes; independent nonzero points have
those orders. A wrong-order mutation is rejected in each cell. The replay
enumerates **143,568** nonidentity null-subgroup points and checks six
aggregate rows and **26,620** singleton sums on valid generated samples.
The frozen C4 sampled residue lists were **not** retained, so these sums
cannot be attributed to the historical run. The
[Lean target](../../../formal/targets/frob-c4-null-curve-order.yaml) proves
that each of the five recorded Hasse intervals and point-order divisors
forces exactly its archived order. The [exact verification receipt](c4-order-lean-verification.json)
binds source commit `6b31a306c2854b15439ac3f8ef8fd925300dd9c3`, Lean
`4.35.0-rc1`, the target and theorem hashes; its full build and target axiom
audit passed with no forbidden constructs. Independent semantic review is
pending. The Lean theorem assumes the intervals and divisors; it does not
formalize Hasse's bound, the elliptic-curve arithmetic, or the historical
sample identities. Full C8 remains open.

## Provenance finding and boundary

The manifest records `code.head_commit=cb06b8c20c2d6559041c45c4a4b29dd7f132fdf5`
and says the run directory was untracked at execution start. The referenced
[`implementation.py`](../../../experiments/EXP-FROB-91ee9c/runs/TASK-20260914-7119f2/implementation.py)
is **absent** from that commit; `git cat-file` confirms the commit exists and
the driver path does not. The current run schema's `code.commit`,
`code.command`, and `environment` fields are also absent from the frozen
manifest. The separate command and environment files preserve useful evidence,
but they do not turn the pre-run HEAD into a commit containing the executed
driver. The extension-cell command file also distinguishes its illustrative
shell line from the command it says was used in practice.

The archived checker replay validates its stored checks and hashes. The new
object-arm replays cover all three core cells, the C2 replay covers the
archived first-curve control lists, and the C4 replay certifies null-curve
geometry and group orders. C3/C4 sample identities remain unbound to the
frozen run, so the specified C8 recheck is incomplete.
None of these replays reruns the Sage generator, establishes original
execution-source custody, or certifies a performance or discrete-log claim.
Later FROB reviews and run directories are separate evidence and are not
adjudicated by this audit. No frozen run bytes or
historical result were changed.
