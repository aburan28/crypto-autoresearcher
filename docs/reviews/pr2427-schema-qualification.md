Two historical BINSTD stage records name `integer_catalog_check` in their nested certificate kind. Their archived `certificate.yaml` files explicitly declare observational scope, with `discrete_log: false`, `decomposition: false` and `key_recovery: false`. The ledger schema accepts `discrete_log`, `decomposition` or `none`; its `none` category therefore describes these records' canonical certificate scope.

The additive files under `experiments/EXP-BINSTD-fdd2d9/corrections/` copy each prior nested schema record, set the canonical kind to `none`, retain `integer_catalog_check` as `observational_kind`, and bind both original manifest and prior schema bytes. Both historical native receipts retain `output_validated` and null scientific conclusions. No outcome, validity reading, metric, execution receipt, source or scientific status is changed. The registry redirects the two BINSTD entries to these new exact hashes. The original flat manifests, nested v2 manifests and certificates remain unchanged.

The corpus regression now recognizes that exact vocabulary while checking the literal registry reference, direct original path, current replacement path/hash, original path/hash and both run identities. The regression recognizes those existing spellings with the same run-directory, hash and identity checks. It introduces no omitted-error list and changes no runtime validator. All of these original records remain unchanged.
