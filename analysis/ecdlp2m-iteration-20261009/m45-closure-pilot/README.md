# Pilot #2: bounded-degree closure refutation of chained S_3 at m = t = 4 and 5

**Exploratory, hypothesis-generating pilot. Not program evidence.** No contract, no
run record, no ledger write, no status change. Toy sizes (n = 7..13) only; it says
nothing about ECC2K-130 or any cryptographic size.

Successor of pilot #1 (`analysis/ecdlp2m-iteration-20261009/m3-closure-pilot/`, m = 3),
whose code is copied here unchanged (`pilot.py`, `pilot_lib.py`, `worker.py`,
`myclosure.c`, `count_affu.c`, `vendor/`) and whose n=9 cell was reproduced
instance-by-instance before anything was extended (`results/repro-m3-n9-poly.jsonl`).

## Question
Pilot #1 found that the degree-4 mutant closure W_4 refutes every UNSAT chained-S_3
descent at m = t = 3 (n = 9, 11, 15). Relation collection can only beat rho if a
failed decomposition costs 2^(alpha*l) with alpha < m/2 - 1, which needs m >= 5
AND a refuting degree that stays bounded as m grows. This pilot measures the
minimal refuting closure degree at m = 4 and m = 5.

## Object (Object A, chained)
Chained S_3 with t = m: S_3(u_0,x_0,x_1) = 0, S_3(u_{i-1},u_i,x_{i+1}) = 0
(i = 1..m-3), S_3(u_{m-3}, x_{m-1}, z) = 0; u_i in F_(2^n), x_i in V = {deg < k},
k = ceil(n/m) unless the cell name carries `k<k>`; N = (m-2) n + m k Boolean
variables, n (m-1) cubic (last block: quadratic) Boolean equations. Built with the
vendored `boolsys` primitives (`pilot2_lib.build_chain`), which already support
general t (`boolsys.generate`); no builder change was needed. Curves as in pilot #1
(`pilot_lib.pick_curve`: y^2 + xy = x^3 + x^2 + b, #E = 2q, q prime, one curve per
n, seed 0; targets x(2P) from the same seeded stream, so cells at equal n share
targets with pilot #1).

Object B (direct S_{m+1}) was NOT run: the repository has S_4 (m = 3) builders
(`experiments/EXP-SEMBIN-7e1371/code/eq4sys.py`, `experiments/EXP-BINSTD-89d952/implementation/s4_descent.py`)
but no S_5/S_6 Boolean builder; and at these sizes the paper's Boolean degree bound
m(m-1) (12 at m=4, 20 at m=5) meets or exceeds N = mk (12..16), so a closure-degree
measurement on it would be degenerate. See summary.md, deviations.

## Labels
Every target is labelled SAT/UNSAT by two independent exhaustive enumerators:
(1) curve-level root solving stage by stage (`pilot2_lib.chain_solutions`, numpy),
(2) a Boolean C enumerator over all x-assignments with sequential affine solves of
the u blocks (`count_chain.c`, new; cross-checked against pilot #1's `count_affu.c`
and `curve_solutions` at m = 3: 40/40). A third, point-level check lifts the x_i of
each recorded solution to curve points and verifies some sign pattern reproduces
u_0, ..., z (`point_check`); solutions that fail it involve x-values that are not
F_(2^n)-point abscissae ("twist" solutions of the polynomial system), which are
still genuine solutions of the Boolean system and are labelled SAT. A brute-force
point-sum enumeration (`checks.py`) confirms SAT = point-reachable, UNSAT = not, on
every cell where points exist.

## Closures
M_D plain Macaulay; W_D mutant closure to fixpoint (`vendor/closure.c`, M4RI
0.0.20200125, PLUQ, `-DECH_EVALCHECK` build on SAT instances with a known zero);
myM_D / myW_D the independent eliminator (`myclosure.c`, no M4RI).

## Controls
Support-matched null (same monomials, i.i.d. coefficients; labelled by
`count_chain`), dense matched null (`boolsys.matched_null`; labelled by 2^N
enumeration where N <= 24, otherwise recorded as `unenumerated` with the expected
number of solutions 2^(N - neq) of a uniformly random system), independent
eliminator cross-check, evaluation check at known zeros, codim(W_D) vs #solutions.

## Reading (derived; not a decision)

1. **Degree.** On every chained-S_3 cell with |V| = 8 (k = 3), the minimal
   refuting closure degree is 4 and plain Macaulay at degree 4 refutes nothing:
   m=3 (n = 9, 11, 15; pilot #1), m=4 (n = 9, 11; this pilot). The one m=5 cell
   with k=3 was run only at D=3 (0/30) because W_4 there needs about 112,000
   columns, beyond this host. So "degree stays at 4 as m grows" is measured at
   m = 3 and 4 and is **not measured at m = 5 with a non-trivial factor base**.
2. **The k=2 cells are degenerate and must not be read as a degree drop.** With
   |V| = 4 and m = 5 points, the m=5 n=9 k=2 system is refuted already by W_3
   (30/30) while the same n with k=3 is not (0/30). A factor base of four
   abscissae for five summands is over-determined enough that the degree-3
   closure sees the contradiction. The m=4 n=7 and m=5 n=7 cells (also k=2)
   needed W_4, not W_3, so they are less degenerate, but they are the smallest
   non-trivial instances and should carry little weight.
3. **Mechanism.** As in pilot #1, the support-matched null is refuted at the
   same degree and the dense null is not. The refutation follows the sparse
   bilinear-plus-affine support of the descended system, not Semaev's
   coefficients.
4. **Cost.** At fixed D = 4 the per-attempt cost is polynomial in
   N = (m-2)n + mk, but the constant is already prohibitive on toy sizes:
   the wall time and memory grow as roughly columns^2.4 to ^2.7 here
   (m=4: 3.5 s / 84 s / 311 s at 9k / 32k / 53k columns; m=5: 167 s / 980 s
   at 36k / 75k columns). Nothing here changes the ECC2K-130 verdict of
   `../wwit-ecc2k130/`: even with D = 4, no (m, D) cell beats rho at n = 131
   under any omega in {2, 2.37, 3} without the Semaev block heuristic.

## Limitations
- One curve per n, polynomial basis V only; the random-V cells were never run.
- m=5 has no k=3 closure at D=4; m=4 n=13 never ran. The W_4 sample at n=11
  (m=4) and n=9 (m=5) is 2 and 1 instances.
- Nulls at D=4 exist only at n=7 (support: 3 UNSAT; dense: 1 enumerated,
  6 unenumerated).
- The M4RI used is 0.0.20200125 (documented large-elimination defect above
  about 150k columns). The largest elimination here is 74,519 columns; the
  independent eliminator agrees on every cell where it ran (m=4 n=7 all
  tasks; m=5 n=7 and n=9 at D=3). The BRiAl cross-check
  (`../brial-engine-crosscheck/`) covered pilot #1 instances only.
- Up to 5 processes shared 4 CPUs; wall times are upper bounds.

## What a contract should freeze (IDEA-20261010-066c44)
- m in {3, 4, 5}, k >= 3 at every cell (|V| >= 8), so the degree reading is
  never confounded by an over-determined factor base.
- The m=5 k=3 W_4 cell (about 112k columns at n=9) needs either a host with
  more than 16 GB or a sparse/structured eliminator; it is the one cell that
  decides whether the degree stays at 4 at m=5.
- Both nulls and random V at every n; BRiAl step degree as the second engine;
  the independent eliminator primary above 1e5 columns while the host's M4RI
  is the 2020 release.
