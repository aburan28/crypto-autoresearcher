## Gain in the relation-collection phase, per V, relative to V_poly with negation only

Accounting (derived, see README): in the orbit-reduced matrix each decomposition is one row and the number of unknowns is `orbits`; the conjugate rows tau^j(rel) are the same row times mu^j, so they add no rank. Relations needed = orbits. Attempts needed = orbits/rpa. Baseline: V_poly, negation only (unknowns = FB_x_poly, rows per attempt = rpa_poly).

- `raw` = log2((rpa_V/orbits_V)/(rpa_poly/FB_x_poly)) at the sizes actually realised (|FB| differ slightly between V families at the same k); rpa counts distinct projected rows.
- `struct` = log2(g_V): the orbit-reduction factor alone (pure counting of the factor base).
- `dec` = log2(eff_V/eff_poly): change in decomposition yield at matched |FB| (measured; 0 means tau-friendliness does not change the decomposition probability).
- `matched` = struct + dec: the size-normalised gain. Bound: log2(n) for tau (negation is shared by all three V and is not counted).
- `unreduced check` = log2((rpa_V*2*shifts_V/|FB|_V)/(rpa_poly*2*1/|FB|_poly)): the same quantity computed in the UNreduced matrix (rows = all usable conjugates, unknowns = all points). It must agree with `raw` when the factor base is an orbit union; multiplying rows by conjugates AND dividing unknowns by orbits would double count.
