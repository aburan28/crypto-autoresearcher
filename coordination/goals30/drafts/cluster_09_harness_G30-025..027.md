## G30-025: Parameterized EXP registration and Sage environment capture
- **Cluster:** HARNESS
- **Type:** infrastructure
- **Long-term chain:** Every future measurement of Semaev/index-calculus scaling (G30-026 and later attack-probe clusters) must be runnable under a registered, auditable EXP definition; this goal gates the scale ladder, which gates any fully charged end-to-end cost comparison against Pollard rho. It protects the program from false positives by removing hand-edited entry points that silently diverge between runs.
- **Mechanism:** Replace the hard-coded `harness/run.py` EXP_ID gate with a registration API: an EXP module declares its instance generator, run builders, parameter schema, metric keys, and certificate kinds, and a generic `harness.run` dispatches through the registry with no experiment-specific branches. Extend `harness/runner.py::environment()` to capture `sage_version` by probing `sage --version` (cached per process, recorded as null when Sage is absent — never fabricated). EXP-SEMAEV-001 is re-registered through the new API as the parity reference; a second minimal probe experiment is registered to prove the path is generic.
- **Quantified prediction:** 16/16 cells of the b8/b10/b12/b14 × s3/s4 EXP-SEMAEV-001 matrix re-run through the registry reproduce the legacy path's discrete metrics (solved, decomposition_found, is_trivial_ideal) and certificate validity exactly; timing metrics within a 2x band; zero SEMAEV-specific code in the generic dispatch path; sage_version non-null on any host where `sage` is on PATH.
- **Test boundary / scope:** Toy fields 8–14 bits, seeds 3–4, factor base 14 (exactly the 2026-07-23 fresh-seed matrix); one synthetic probe EXP at 8 bits, seeds 1–2. No new curves, no new math.
- **Primary metric:** parity rate (fraction of re-run cells matching legacy discrete metrics + certificate validity) / **Secondary metrics:** timing ratio vs legacy path, count of experiment-specific branches remaining in generic dispatch, manifest schema diff vs v2, sage_version capture success on sage-present hosts.
- **Controls:** Legacy hard-coded path kept frozen and run in parallel as the matched control; byte-level comparison of manifest fields other than timestamps/RUN ids; the existing 14-test harness suite (determinism, tamper detection, immutability) must pass unchanged. Held-out rule: the probe experiment is written by an agent that did not see the SEMAEV registration, to detect hidden special-casing.
- **Falsification criteria:** Any discrete-metric or certificate-validity mismatch on a parity cell; any regression in tests/test_harness.py; the registry requiring a SEMAEV-specific conditional to express EXP-SEMAEV-001; sage_version recorded as a non-null value that does not match `sage --version` output (fabricated capture).
- **Negative-outcome value:** If parity fails or the registry cannot express the existing experiment without special cases, run.py stays frozen as the legacy entry point, all new EXP commissioning is deferred, and G30-026/G30-027 are blocked — the Coordinator does not scale measurements on an unaudited runner.
- **Budget:** wall_clock 8h, memory 4GiB, max_runs 40 (including parity re-runs and probe cells)
- **Stopping rule:** Stop when the parity suite passes on two consecutive clean invocations, or when the budget is exhausted. Any immutability- or tamper-detection test failure halts the goal immediately and is reported as an evidence-integrity failure, not a measurement.
- **Harness dependency:** Commissions cartography_harness gap #3 (generalized EXP runner) and gap #5 (Sage environment capture). Builds on existing harness/runner.py, harness/toycurve.py, harness/semaev.py, harness/rho.py.
- **Claim tier:** infrastructure
- **Dependencies:** none within G30; gates G30-026 and G30-027.

## G30-026: Semaev m=3/m=4 decomposition measurement and certified 40–64-bit instance ladder
- **Cluster:** HARNESS
- **Type:** measurement
- **Long-term chain:** This goal builds the measurement surface (m=3,4 ideal systems, certified instances to 64 bits) that any future summation-polynomial attack probe needs before it can charge relation collection honestly; it gates later attack-probe clusters' scaling studies, which gate any credible sub-rho claim. It also produces the censored-cost data that keeps toy-tier evidence from being misread as crypto-scale.
- **Mechanism:** Implement `harness/semaev.py::measure_sm_decomposition(m)` for m=3,4: build the ideal <S_m, x_1 - f_1, ..., x_{m-1} - f_{m-1}> over F_p with the factor-base ideal system, time the grevlex Gröbner basis, and emit decomposition certificates verified by the independent verifier. Commission a curated instance table at 40/48/56/64 bits (Schoof-lite point counting or precomputed entries): each row carries p, a, b, #E(F_p), a prime-order subgroup with generator, and an independently re-verified point-count certificate; rho baselines above 32 bits are budget-capped and recorded as censored, never as failures or as solved.
- **Quantified prediction:** At fixed factor-base fraction, m=4 Gröbner cost exceeds m=3 by ≥10x at 16 bits and ≥100x at 24 bits (direction: m=4 strongly super-linear in m, consistent with known Semaev degree growth); decomposition_found rate for m=4 ≤ m=3 rate at equal factor-base fraction; all 40–64-bit table entries pass independent point-count verification (target 9/9, 3 instances per size).
- **Test boundary / scope:** m=3: bits 8–32 via toycurve (seeds 1–4), plus 40/48/56/64 via the curated table (3 fixed instances per size). m=4: bits 8–24 only (infeasibility beyond that is itself a recorded outcome). Factor-base sizes {14, 20}; 60s wall-clock cap and 2GiB memory cap per run, inherited from EXP-SEMAEV-001 discipline. Claim tier remains toy: no instance exceeds 64 bits and results are labeled model-bound.
- **Primary metric:** groebner_seconds per (m, bits, factor-base) cell / **Secondary metrics:** groebner_basis_size, max_degree proxy (labeled NOT d_reg), is_trivial_ideal, decomposition_found rate, rho group_operations where solved, censored-run count, point-count certificate verification pass rate.
- **Controls:** Trivial-ideal control (random target outside the factor-base span) in every cell to distinguish "no decomposition" from a cheap solve; matched Pollard-rho baseline on every instance ≤32 bits, charged per the existing baseline discipline and never equated to Gröbner cost without a cost model; curated-table rows are quarantined until their point-count certificates pass independent verification; held-out rule — table instances are fixed before any measurement run and never re-selected after seeing results (no re-sorting of pools).
- **Falsification criteria:** Any curated-table instance whose point-count certificate fails independent verification (kills that size tier, table withdrawn for repair); m=4 cheaper than m=3 at matched parameters (indicates implementation defect — run invalid_measurement, not a math result); systematic trivial-ideal control failures indicating a broken ideal construction. A budget-censored run is not falsification and not evidence against any hypothesis.
- **Negative-outcome value:** If the 40–64-bit table cannot be certified, the program's evidence ceiling stays at 32 bits and the Coordinator defers every goal requiring larger instances. If m=4 is infeasible at ≥16 bits within budget, direct m≥4 Semaev decomposition is closed as a viable toy attack lane within the tested scope, redirecting attack-probe clusters toward representation changes (RT-1476-SUBRES-A1 line) instead of larger m.
- **Budget:** wall_clock 24h, memory 8GiB, max_runs 120
- **Stopping rule:** Complete m=3 across the full ladder and m=4 through 24 bits, or stop a cell after 3 consecutive budget-censored runs and record it as censored. Stop the whole goal early if any table certificate fails verification; the failure is reported as an evidence-integrity event.
- **Harness dependency:** Commissions cartography_harness gap #2 (measure_sm_decomposition for m=3,4 with factor-base ideal systems) and gap #6 (40–64-bit instance ladder via Schoof-lite or curated tables). Requires the G30-025 registry for EXP registration and Sage env capture for any Schoof-lite runs.
- **Claim tier:** toy
- **Dependencies:** G30-025 (hard); G30-027 validator coverage for the new modules may land in parallel or after.

## G30-027: Replication protocol, independent-verifier promotion path, and CI validator hardening
- **Cluster:** HARNESS
- **Type:** governance
- **Long-term chain:** No future sub-rho or frontier claim can be promoted without fresh-seed replication and a second, independent verifier; this goal turns that requirement from prose into an enforced gate, protecting the program from the recurring failure modes in cartography_closed (multiplicity crediting, fragile selectors, uncharged maps) by making unreplicated or unverifiable artifacts ineligible for ledger transitions. It gates every claim-tier transition the Coordinator will ever make.
- **Mechanism:** (1) `tools/replicate.py`: given an EXP id and its run receipts, re-executes the registered experiment on a disjoint seed window via the G30-025 registry and compares distributions with predefined tolerances — exact match for discrete metrics and certificate validity, order-of-magnitude band for timings — emitting a replication report record. (2) Independent-verifier promotion path: a claim may reach `replicated` only after a second verifier module (separate code path from the solver) re-checks every certificate and re-runs a seeded subsample; the path is encoded in tools/validate_ledger.py as a checked gate, not a convention. (3) Validator/CI hardening: extend tests/test_harness.py and check_run_immutability.py to cover the registry, measure_sm_decomposition, the instance table (hash-pinned), and Sage env capture, including manifest- and table-tamper detection tests.
- **Quantified prediction:** ≥95% detection on an injected-fault suite (doctored metric, seed reuse outside the declared window, certificate mismatch, manifest tamper, table-hash drift) with 0 false positives on 16 honest re-runs; fresh-seed replication of EXP-SEMAEV-001 on seeds 5–6 reproduces the qualitative outcome (rho solves everywhere; gb decomposition only where independently certified) in ≥7/8 cells; ≥80% line coverage on the new harness modules.
- **Test boundary / scope:** Toy fields 8–14 bits, replication seeds 5–6 against the 2026-07-23 seeds 3–4 baseline; fault suite of ≥12 seeded bad artifacts; validator coverage scoped to modules added or touched by G30-025 and G30-026. No new curves, no new math.
- **Primary metric:** fault-detection rate on the injected-fault suite / **Secondary metrics:** false-positive count on honest re-runs, replication-cell agreement rate, new-module line coverage, wall-clock overhead of replication vs original run (target ≤2x), number of promotion-path gate violations caught in a retroactive sweep of the 34-claim matrix.
- **Controls:** Positive controls: fault-injected artifacts with known defects must be flagged. Negative controls: honest fresh-seed re-runs must pass without flag; any flag there is a protocol defect. Matched baseline: pre-protocol manual review outcome on the same artifacts. Held-out rule: a held-out subset of fault classes is injected by an agent that did not write the detector, to prevent teaching-to-the-test.
- **Falsification criteria:** Any fault class in the public suite undetected after the protocol run; any unexplained false positive on honest re-runs; coverage below the 80% target; a claim reaching `replicated` in a test ledger without passing the encoded promotion gate.
- **Negative-outcome value:** If the protocol cannot achieve zero false positives, the promotion path stays manual-review-only and no claim advances to `replicated` via automation — a deliberate governance tightening, not a mathematical result. If replication of EXP-SEMAEV-001 disagrees beyond tolerance, the baseline itself is quarantined and EXP-SEMAEV-001-derived evidence is downgraded until reconciled via CORR-* records.
- **Budget:** wall_clock 16h, memory 4GiB, max_runs 80
- **Stopping rule:** Stop when the fault suite and honest suite both pass twice consecutively and the coverage target is met, or when the budget is exhausted. Any immutability regression in CI halts the goal immediately and is reported as an evidence-integrity failure.
- **Harness dependency:** Builds on existing tools/check_run_immutability.py, tools/validate_ledger.py, tests/test_harness.py (14 tests); commissions a new tools/replicate.py. Covers modules delivered by G30-025 (registry, Sage env capture) and G30-026 (measure_sm_decomposition, instance table).
- **Claim tier:** infrastructure
- **Dependencies:** G30-025 (hard); G30-026 (soft — validator coverage for its modules can follow the measurement delivery).
