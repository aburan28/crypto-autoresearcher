  conventions_chosen_before_computing:
    timing: >-
      Each reading below was fixed in the docstring of the program that applies
      it (relcount.py, cells.py) before that program first ran on panel data;
      the format facts it relies on were established first by survey_rows.py and
      survey_orient.py, which compute no relation count. relcount.py was written
      and started at about 14:35-14:36Z, cells.py written before it ran. No
      relation count of this experiment existed in this session before then.
    CONV-1_TB_relation_unit:
      reading: >-
        A TB relation is carried only by a (base element, tail) pair: the star
        pairs (1, j) of a TB x-group, whose first element is always the base
        element (survey: every TB row is (base, tail)). Tail-tail pairs (i, j),
        2 <= i < j, of a TB x-group are TT pairs and are not counted in TB.
      reason: >-
        TB is the tail-base coincidence class. In L1's TB setting the stored set
        adds the unit vectors e_b to the tails; counting tail-tail pairs as TB
        would make TB contain TT, against the planning means (TB3 about 0.2 vs
        TT3 about 100 relations per instance, power_analysis) and CC-4 (a
        relation is counted in each class whose PAIRS carry it; a tail-tail pair
        is a TT pair). The README the card names for class definitions holds no
        harvester class definition (finding), so the text gives no other rule.
      secondary_reading_reported: >-
        TB-B: literal CC-1 over the whole TB group (adds row_j - row_i for
        2 <= i < j). The survey found 21 TB groups with 2 star rows and 2302
        with >= 6 (the latter in known_log instances), so TB-B can differ from
        CONV-1 only on those groups.
    CONV-2_pair_relations_and_orientation:
      reading: >-
        Pair (1, j) carries row_j; pair (i, j) carries row_j - row_i, rows as
        recorded. 4.1% of TT rows are stored second-minus-first (eps = -1), but
        orientation is constant within every x-group (survey_orient:
        groups_with_mixed_eps empty), so row_j - row_i equals +-(sigma_i u_i -
        sigma_j u_j), the coincidence relation of elements i and j (L1's pair
        map), projectively. Had a group mixed orientations, the literal and the
        oriented reading would differ; none does.
    CONV-3_vector_and_monic_form:
      reading: >-
        v = (c_0, ..., c_{s-1}, kcoef, rhs), base indices 0-based in the bases
        file order, ascending, then kcoef, then rhs (rhs as recorded in the row
        identity sum c_i F_i + kcoef Q = rhs P). Each coordinate reduced mod N
        into [0, N); the zero vector is a formal duplicate and dropped; monic =
        multiplied by the inverse mod N of the first nonzero coordinate in that
        order. A distinct relation is a distinct monic vector.
      reason: CC-1 verbatim; the only choice is the index base (0-based as stored), which cannot change a count.
    CONV-4_SS_sequence_scope:
      reading: >-
        A row's 'seq' is the formally-distinct sequence number of the row's
        second (newer) element; the first element is older. at_X_fix keeps
        exactly the rows with seq < X_fix = 20 * isqrt(N); x-groups and all
        pairs are formed among the kept rows only; a pair (i, j) is in scope iff
        both its star rows are kept. Rows with seq >= X_fix (at_stop) are
        dropped.
      reason: >-
        EC-3: each formally distinct encoding gets a 0-based sequence number in
        recording order; a pair is in scope iff both encodings are < X_fix. The
        row's first element always precedes its second, so 'both < X_fix' is
        'second < X_fix'. Format facts: seq strictly increasing in file order
        within every instance; rows with seq >= X_fix occur only in the
        instance's last attempt (survey_rows); X_fix of design.json equals
        20 * isqrt(N) on all 4500 design curves.
      open_point: >-
        The row format records one seq per row, not one per element; the
        identification of seq with the newer element is an inference from the
        format facts, not from a definition in the text.
    CONV-5_formal_basis:
      reading: >-
        known_log: F_i = (i+1) P for 0-based i (verified: bases of c = 10 rebuilt
        by factor_base.known_log equal the archived points, G4-R B5); a vector is
        formal iff kcoef = rhs = 0 (mod N) and sum_i (i+1) c_i = 0 (mod N), i.e.
        it lies in span{e_j - j e_1} (1-based j). Every other arm: empty basis,
        formal iff zero (dropped by CONV-3). Counts entering z are nonformal.
    CONV-6_CC6_drops:
      reading: >-
        (a) unmatched_size: the census fb_size of A differs from the common
        fb_size of A's three randoms on curve j (or the randoms disagree) ->
        curve j dropped from A's cell only; C_A, C_R and V of that cell are
        computed over the cell's remaining curves (paired, CC-5). (b) any arm of
        the family as run on that panel and m (planted_sub only on table m 3)
        with status != completed_valid or with no census row on curve j ->
        curve j dropped from every cell of the family for that (class, m, rung).
        A cell keeping < 80% of its design curves is flagged incomplete.
      reason: CC-6 verbatim; 'dropped for A in that cell' read as dropping the curve from the paired sums of that cell.
    CONV-7_statistic_and_band:
      reading: >-
        CC-8 verbatim over the band (30 and 32 bits pooled, CC-10): C_A = sum_j
        n_A,j; C_R = (1/3) sum_r sum_j n_r,j; kappa_rel = C_A / C_R; s_j^2 =
        sample variance (ddof 1) of the three random counts on curve j; V =
        max(sum_j s_j^2, C_R); SD_null = sqrt(4V/3); z = (C_A - C_R) / SD_null.
        The known-null and planted arms take A's place against the same randoms.
    CONV-8_multiplicity: M_r = number of pairs of the (instance, class, scope) carrying the distinct monic vector r; histograms are over NONFORMAL distinct relations, summed over the completed_valid band instances of each (arm, class, m).
    CONV-9_R_star: distinct monic nonformal vectors among the star pairs (1, j) only.
    CONV-10_PC1: >-
      raw = distinct monic relations INCLUDING formal ones (CC-1 only); the
      ratio is sum over curves 10..19 of known_log raw / ((1/3) sum over r0..r2
      and the same curves of random_sub raw), per bits (20, 24) and pooled, for
      TT, TB and TT + TB separately (A5R does not name the class); nonformal
      count per instance reported.
    CONV-11_planted_recovery: >-
      Planted relations taken from FactorBase.planted(E, s_sub, seed = c + 8000)
      (factor_base.py, construction only; the census field planted_relations is
      NOT read: its name contains 'relations' and the whitelist's forbidden
      rule excludes it), cross-checked with the whitelisted census fb_params
      n_tt, n_tb, skipped_tuples. A planted relation v = sum signs_i e_{indices_i}
      is recovered iff monic(v) is in the instance's nonformal set of its own
      class (TT plant in TT; TB plant in TB under CONV-1); the union is also
      reported. Declared planted total of a cell = sum over its curves of n_tt
      (TT) or n_tb (TB).
    CONV-12_universe: >-
      The instance universe is the union of the jobs-spec expected_keys of R12
      and R13 attempt-1; an instance with no harvest row in a class has n = 0;
      m is taken from the job record (the census row carries no 'm' key).
    CONV-13_Q6_dispersion: >-
      D = sum_j s_j^2 / sum_j nbar_j over the band curves kept in the family's
      cells (nbar_j = mean of the three randoms), per (family, class, m) and
      pooled over both families (sums of numerators and denominators).
    CC-1b_sign_only: secondary, reported in the counts file only; v normalised to the lexicographically smaller of v and -v mod N (decided by the first nonzero coordinate).
  open_points_and_findings_before_seal:
    - README.md (index_calculus) contains no harvester class definition or row convention, though the card names it for them; the TB unit (CONV-1), SS seq scope (CONV-4) and orientation (CONV-2) were therefore fixed from the specification text and the raw-row format.
    - The census rows carry no 'm' field (key names only were listed under the whitelist's key_name_discovery clause); m is taken from the job record.
    - field-whitelist.yaml lists planted_relations under nested_subkeys while its forbidden rule excludes any name containing 'relations'; the forbidden rule governed and the field was not read (census-fields schema files record it as dropped).
    - A5R's PC-1 'raw relation count' names no class; CONV-10 reports TT, TB and TT + TB.
