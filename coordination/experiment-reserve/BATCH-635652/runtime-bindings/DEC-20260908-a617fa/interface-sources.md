# Interface sources for a prospective group-OOM supervisor

Retrieved by the root Coordinator on 2026-09-09 UTC through web search and page reads. These are interface documentation, not observations of the local runtime.

- provenance: retrieved; https://docs.kernel.org/admin-guide/cgroup-v2.html — The memory.oom.group setting defaults to0. Value1 makes an OOM kill apply to the group and descendants together, except tasks protected by oom_score_adj=-1000. memory.events exposes oom, oom_kill and oom_group_kill counters. Children inherit their parent membership; writing a process ID to cgroup.procs moves it. Enabling a domain controller below a populated non-root cgroup requires moving its direct processes first. These facts motivate a separate supervisor subgroup and a worker subgroup configured before worker migration. The documentation does not prove the local Docker delegation is writable or that any control passed.
- provenance: retrieved; https://docs.docker.com/engine/containers/runmetrics/ — Docker documents cgroup-v2 paths as /sys/fs/cgroup/docker/<full-container-id> for cgroupfs and /sys/fs/cgroup/system.slice/docker-<full-container-id>.scope for systemd. The cgroup namespace defaults to private on v2, and --oom-kill-disable is discarded on v2. Use actual membership and inspected identity, not a guessed short ID.
- provenance: retrieved; https://docs.docker.com/engine/storage/bind-mounts/ — Bind sources belong to the daemon host. Docker Desktop runs the daemon in a Linux VM. Explicit --mount fails for a missing source instead of creating it. A writable bind can modify its source; the proposed helper must restrict every cgroup write to its own verified task-created container subtree.
