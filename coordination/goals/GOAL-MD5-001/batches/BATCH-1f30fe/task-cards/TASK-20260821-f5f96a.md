### 3. The search instrument: `harness/run_md5_calib.py`

A single module, runnable as a script, that IS the instrument the two runs
execute:
- a standalone MD5 implementation written FROM the RFC 1321 text (section
  3.3 step function, 3.4 round constants, Merkle-Damgard padding and
  chaining) — the solver core must NOT import hashlib (the pinned pair in
  harness/runner.py is used ONLY for certificate verification, never for
  the search);
- a BOUNDED differential/MTM collision-path search for a 2-block MD5
  collision (full 128-bit digest equality, hex-encoded 512-bit blocks),
  with a DECLARED strategy: what it searches (e.g. a windowed biclique /
  meet-in-the-middle fragment search over the 64-step schedule), the
  window, the memory ceiling, the stopping rule — all in the module
  docstring, fixed BEFORE any run (fixed_before_acquisition);
- deterministic: a single `--seed` argument (the runs use seed 0), every
  stochastic element seeded from it;
- a `--variant-shift N` argument (default 0): the round constants used are
  T[(i+N) mod 64] — N=0 is standard MD5, N=16 is the BCP-2 null variant.
  The variant is the ONLY difference between the target and null runs;
- cost instrumentation: the run is charged via `run_wrapped` from
  harness/runner.py (wrapper-measured wall_seconds); the module reports
  internal counters (fragments tried, table sizes, partial results) in its
  raw result;
- a search report writer: emits a machine-readable result — outcome
  (SUCCESS with the two messages + digest for certificate verification /
  FAIL), the search space explored, the strongest partial result
  (longest matching prefix of state/digest bits achieved, and at what
  cost), and the counters;
- a 900 s wall ceiling is enforced by the CALLER (run_wrapped + the
  declared ceiling), not the module; the module must check a monotonic
  clock against `--deadline` each major iteration and stop cleanly,
  reporting where it stopped.
