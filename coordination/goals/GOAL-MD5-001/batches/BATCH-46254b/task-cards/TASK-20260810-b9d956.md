## YOUR TARGET IS BCP-1 ITSELF, NOT MD5

Find every way a calibration run could **pass BCP-1's blind-scoring rule without
having searched**: leakage routes the firewall does not close, scoring rules that
reward recall, invalidity conditions that a determined — or merely careless —
agent can satisfy while consuming the answer, and charging conventions that make a
cheap run look like an expensive one.

Why now: **a protocol that fails before any calibration is run costs one review,
while a protocol that fails afterwards invalidates the calibration and everything
the five dependent goals priced on it.** The cheap version of that discovery is
the valuable one, and the closing decision TASK-20260810-ccfeb4 is explicitly
instructed to record a "partial" or "ceremonial" verdict as **the result of this
batch** rather than smoothing it into a pass.

## Attack at least these five surfaces

- **(i) LEAKAGE.** Can the quarantined payload reach a calibration run through
  corpus staging, git history, a `search_knowledge` result, a prior session
  transcript, a diff, or a PR body?
- **(ii) SCORING.** Can a run that **recalls** the published path satisfy the
  rediscovery rule? Does the rule distinguish **rediscovering** a path from
  **recognising** one?
- **(iii) THE INPUT MANIFEST.** Is it actually complete, or does it cover only what
  the wrapper chose to hash? This is the firewall's one supposedly-checked element;
  if it is not complete, the firewall is declaration all the way down.
- **(iv) CHARGING.** Can the declared clock be gamed by moving work outside the
  measured window, or by reporting compute-only time against an
  authoring-inclusive budget?
- **(v) THE NULL-OBJECT CONTROL — the one the Coordinator most wants attacked.**
  BCP-1 specifies running the identical instrument, at the identical budget,
  against a **shape-matched MD5 variant with permuted round constants or message
  schedule**, on the reasoning that structure is nearly preserved and recall is
  worthless. **Does that actually discriminate?** Or does permuting the constants
  **also destroy the structure the search needs**, so that failure on the variant
  and success on genuine MD5 is exactly what you would see whether the instrument
  searched or recalled — making the control **uninformative in both directions**?
  DEC-20260810-9942ea records that the null-object control is *a discriminator, not
  a solution*, and directs you specifically at whether it discriminates at all.

Say for each surface whether the attack **succeeds, fails, or is untested**. An
attack route you did not test is a **hypothesis about the protocol, labelled as
one**.

## Judge the residual-risk concession itself, in both directions

The batch record concedes that model prior knowledge is **irreducible** —
published MD5 collision paths are in the training data of any model this harness
can resolve, the contaminated channel is the model's parameters, and no
file-system mechanism reaches it — and concludes that a calibration **failure** is
clean while a calibration **success** is permanently confounded. Attack that
concession **both ways**:

- Is it **too pessimistic**, so that a real success would be undersold?
- Is it **too optimistic**, so that BCP-1 still lets a confounded success be
  recorded as a pass?
