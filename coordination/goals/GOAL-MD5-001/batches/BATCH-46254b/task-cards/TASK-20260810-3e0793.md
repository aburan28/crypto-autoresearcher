## Why two implementations, and why this is a requirement rather than a luxury

RQ-MDFIVE-6870c1 makes independent re-verification part of what a collision
certificate **is**: certificates must be literal pairs re-verified independently.
One implementation cannot re-verify itself, and **two builds of the same source
are not two implementations**. The second implementation exists so that a
certificate can be checked by code that did not produce it.

## Produce exactly two declared files

### 1. `.../tasks/TASK-20260810-3e0793/implementation-pin.yaml`

For **each** of the two implementations, record concretely:

- **source and origin** (what it is and where it came from);
- **exact version or commit**;
- **build or interpreter toolchain and version**;
- **how independence was established** — what you actually checked.

**If genuine independence cannot be established with what is installed, say so and
record the pair as NOT INDEPENDENT rather than describing it as independent.** The
whole point of the second implementation is destroyed by an unnoticed shared core:
a shared compression-function core, a vendored source file, or one common upstream
project means a certificate "re-verified" under that pair is re-verified by itself.
TASK-20260810-23e0ea is directed to challenge this determination concretely rather
than inherit it, so an honest "not established" costs you nothing and an
overstated "independent" costs the campaign its certificate discipline.

Also record here the **measured hash throughput** for each implementation, with
its **exact command, input size, repetition count and machine description**. This
is the unit every later collision budget in this campaign needs, and no record in
this campaign currently has one.

### 2. `.../tasks/TASK-20260810-3e0793/test-vector-report.json`

Every RFC 1321 published test vector, for **both** implementations, each with:

- the vector as given in the RFC text;
- the **expected** digest;
- the **observed** digest;
- pass/mismatch.

**A partial pass is a partial pass; do not summarise it as a pass.** Any mismatch
is reported, not smoothed away. Take the vectors **from the RFC 1321 text itself,
not from recollection** — a recalled test vector that happens to be wrong would
silently validate a broken implementation.
