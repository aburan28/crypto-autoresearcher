## Why this is first in time — an ordering that cannot be recovered later

Blindness is a property of the **information state at run time**, and information
states are monotone: a corpus can gain the published collision path but can never
un-learn it. RANK 3 (TASK-20260810-bde128) deliberately imports that path. Once it
is filed and reachable, no protocol written afterwards can restore the
pre-acquisition state — it can only ASSERT blindness, unfalsifiably. Concretely:
it is BCP-1 that defines the quarantine marker RANK 3 must apply, so in the other
order the entry is filed unmarked and the marker has nothing to attach to.

**Write it to be attacked.** It is the primary target of TASK-20260810-b9d956,
whose brief is to find how the blind calibration could be gamed. A protocol that
fails before any calibration is run costs one review; the same protocol failing
afterwards invalidates the calibration and everything five dependent goals priced
on it.

## Invalidity conditions to enumerate

- No input manifest, or one that does not cover every file the solver could read.
- The quarantined payload's digest appears in the input manifest. This is
  **consumption**, and it is `invalid` rather than a weaker pass.
- Any declared-before-run field — encoding, solver identity and version, seed,
  wall-clock ceiling — absent, or altered after the run began.
- The encoding was authored in a session that had read the quarantined payload,
  per the required encoding-provenance declaration.

## State the residual risk rather than engineering around it

Model prior knowledge is **irreducible in this program**: published MD5 collision
paths have been in the public record for two decades and are therefore in the
training data of any model this harness can resolve. The contaminated channel is
the model's parameters, and no read scope, input manifest, quarantine marker or
file-system arrangement reaches it. Record both consequences:

- **THE CALIBRATION IS EVIDENTIALLY ASYMMETRIC.** A FAILURE is a clean statement
  about the instrument, because recall could only have helped. A SUCCESS is
  confounded by prior exposure and can never be fully de-confounded here. This is
  an independent reason GOAL-MD5-001's own completion criterion is right to call
  the failure outcome the more important one.
- **THE ONLY DISCRIMINATOR AVAILABLE IS A NULL-OBJECT CONTROL** in the sense of
  `docs/inventor-protocol.md`: the identical instrument, at the identical budget,
  against a shape-matched MD5 variant whose round constants or message schedule are
  permuted, so that structure is nearly preserved and recall is worthless. BCP-1
  specifies that control. **This batch does not run it and claims nothing from it**,
  and TASK-20260810-b9d956 is directed to attack whether it discriminates at all.
