# CORR-B003-002 — record location, and the `run.code.command` schema gap

- **Author:** coordinator · **Date:** 2026-07-26
- **Supersedes:** the placement of the BATCH-003 evidence and decision records
  in `ledger/`, as first committed in `4450c5c3`
- **Does not supersede:** any observation, number, verdict, caveat or review.
  The record contents are unchanged; only their path and the surrounding
  bookkeeping move.

## 1. Evidence and decision move out of `ledger/`

`4450c5c3` wrote `ledger/evidence/EV-GOAL-DREG-001-B003.yaml` and
`ledger/decisions/DEC-GOAL-DREG-001-B003.yaml`. Running the repository validator
showed that placement is not viable, because three constraints in this harness
cannot be satisfied at once:

| Constraint | Requires |
|---|---|
| `tools/research_dispatch.py::_validate_ledger_archive` | a `kind: ledger` task must own paths under `ledger/evidence/` and `ledger/decisions/` |
| `tools/validate_ledger.py` | evidence IDs match `^EV-[A-Z]+-\d{3}$`, decision IDs match `^DEC-\d{8}-\d{3}$` |
| `GOAL-DREG-001` ISOLATION note | this campaign mints **no** shared-ledger `EV-DREG-NNN` / `DEC-YYYYMMDD-NNN` IDs, deferring them to the Coordinator-of-record at merge |

Goal-scoped IDs (`EV-GOAL-DREG-001-B003`) satisfy the dispatcher's substring
match and the isolation note, but violate the validator's ID grammar. Conforming
IDs would satisfy the validator and the dispatcher but breach isolation — and the
co-driver is actively consuming that namespace (`DEC-20260726-027` was already
taken on 2026-07-26, and an untracked `ledger/EV-DREG-004.yaml` exists in its
worktree).

Placing them in `ledger/evidence/` also produced two further errors —
`evidence references unknown experiment 'EXP-DREG-001'` and `unknown hypothesis
'H-DREG-001'` — because the validator resolves those from the modern
`ledger/hypotheses/` directory, while this campaign's `H-DREG-001.yaml` is a
legacy **root-level** record.

**Resolution: follow this campaign's own precedent.** BATCH-002 placed its
decision at `coordination/goals/GOAL-DREG-001/batches/BATCH-002/decision.yaml`,
not in `ledger/`, and produced zero validator errors. BATCH-003 now does the
same:

- `coordination/goals/GOAL-DREG-001/batches/BATCH-003/evidence.yaml`
- `coordination/goals/GOAL-DREG-001/batches/BATCH-003/decision.yaml`

The record IDs `EV-GOAL-DREG-001-B003` and `DEC-GOAL-DREG-001-B003` are retained
as internal identifiers. `ledger/goals/GOAL-DREG-001.yaml` — this campaign's own
goal record — remains the only file this batch writes under `ledger/`.

**Effect:** validator errors introduced by BATCH-003 drop from 5 to 1.

**Open issue for the Coordinator-of-record.** The dispatcher's ledger-archive
schema is unsatisfiable under isolation. Either it needs to accept goal-scoped
archive paths, or isolated campaigns need a sanctioned ID namespace. Recorded
here rather than worked around silently a second time; the queue's own notes
block already flags that BATCH-002's v1 JSON declared `ledger/evidence/EV-DREG-004.yaml`
and `ledger/decisions/DEC-20260721-001.yaml` and then correctly minted neither.

## 2. `run.code.command` is missing from the CTRL-B manifest

`validate_ledger.py` requires an inline `run.code.command`. The manifest of
`RUN-DREG-001-CTRLB-N12-D6` records `command_file: command.txt` instead, matching
the shape BATCH-002's `d6-null/manifest.yaml` uses.

**Why this surfaced only now:** the validator indexes `runs/<RUN-ID>/manifest.yaml`
at one level. BATCH-002's cells live one level deeper
(`runs/RUN-DREG-001-MEASURE-N12-D6/d6-null/manifest.yaml`) and were therefore
never checked. `RUN-DREG-001-CTRLB-N12-D6` is the first run in EXP-DREG-001 that
the validator actually examines. The gap is inherited from the BATCH-002
template, not introduced by the executor's judgement.

**Not fixed by editing the manifest.** It is a committed, immutable run record
(`8302c83a`). Per AGENTS.md rule 4 this correction supersedes rather than
overwrites.

**Reproducibility is not actually lost:** `command.txt` sits beside the manifest
and holds the literal command line, and `code/ctrlb_restricted_rank.py` is
committed with its SHA-256 recorded in `run.code.driver_sha256`. Carry
`VAL-CTRLB.md` caveat **V3** with it: `command.txt` records only invocation 1's
line, so the `--chunk-force 11404` resume of invocation 2 (deviation `DEV-2`) is
recoverable from `manifest.yaml` `deviations` and `chunk-coverage.log`, not from
`command.txt` alone.

**Standing instruction:** future EXP-DREG-001 runs must set `run.code.command`
inline in addition to `command_file`, and should be written at
`runs/<RUN-ID>/manifest.yaml` so the validator sees them.
