1. THE QUANTITY AS STATED
======================================================================
TOTAL(n) = min over m in 2..16, s in 0..floor(m/2), real d of
           log2( 2^PROBE + 2^FILL + 2^LA )
PROBE = relations x trials_per_relation x oracle_time
  relations           = |F| = 2^d
  trials_per_relation = 1/p,  p = |F|^m / (m! N)
  oracle_time         = |F|^(m-s)  at store |F|^s
FILL  = |F|^s   (one operation per table entry)
LA    = |F|^2
N     = ell (ECC2K-130 prime subgroup order) at n = 131; N = 2^n otherwise
margin(n) = TOTAL(n) - log2(0.886 sqrt(N))
SIGN CONVENTION: positive margin = the index-calculus total costs MORE than
the rho baseline.
UNIT: abstract operations, exactly as the statement charges them (one per
oracle step, one per table entry, |F|^2 for LA). No conversion to bit
operations or field multiplications. Memory is not part of TOTAL; it is
reported alongside (store = |F|^s entries).

======================================================================
3. ALGEBRA
======================================================================
Let L = log2(m!) + log2(N). In log2 units:
  log2 PROBE = d + (L - m d) + (m - s) d = L + (1 - s) d
  log2 FILL  = s d
  log2 LA    = 2 d
  log2(total trials) = log2(relations x trials_per_relation) = L - (m - 1) d
  log2(trials_per_relation) = L - m d   (p > 1 exactly when this is < 0)
The script builds PROBE from the three factors and asserts it equals the
closed form; max abs discrepancy 8e-59.

TOTAL(d) is a log-sum-exp of affine functions of d, so it is convex in d.
That justifies golden-section search and also makes the derivative's sign
change unique.
  s = 0: PROBE = L + d, increasing. Minimum at d = 0, value ~ L > log2 N.
  s = 1: PROBE = L, constant. Minimum at d = 0, value ~ L.
  s >= 2: PROBE decreases in d at slope (s-1); FILL and LA increase.
    Stationary point: (s-1) 2^PROBE = s 2^FILL + 2*2^LA.
    For s >= 3 (LA negligible):
      d* = (L - log2(s/(s-1))) / (2s - 1)
      TOTAL* = s d* + log2((2s-1)/(s-1))
      log2(total trials at d*) = L - (m-1) d*
    With m = 2s this gives log2(total trials) = log2(s/(s-1)) > 0, so the
    optimum lies just INSIDE the feasible region (total trials = s/(s-1)).
    With m > 2s (odd m, or s < m/2) the optimum lies in the excluded region.

STRUCTURAL LOWER BOUND (holds for every n, independent of the scan):
  For s >= 2: TOTAL >= max(L - (s-1)d, s d) >= s L / (2s - 1) > L/2.
  For s <= 1: TOTAL >= L.
  Since m >= 2, L/2 >= (1 + log2 N)/2, while log2(0.886 sqrt N) =
  log2(N)/2 - 0.17455. So margin > 0.67 bits for EVERY (m, s, d) and every
  N. Under this cost model, index calculus cannot beat the 0.886 sqrt(N)
  baseline at any size. Because s <= 8, TOTAL >= (8/15) L, so the margin
  grows at least like (1/30) log2 N. The positive margins below are a
  property of the model, not of the particular degrees.

4. EXCLUSION CONVENTIONS (stated as the task requires)
======================================================================
The statement says: when trials_per_relation x relations < 1, flag and
exclude that cell.
  C1 PRIMARY (pointwise): a cell is a point (m, s, d). Points with
     L - (m-1) d < 0 are excluded, so d is restricted to [0, L/(m-1)].
     An (m, s) pair is FLAGGED when its unconstrained minimiser falls in
     the excluded region; its reported value is then the constrained
     boundary minimum.
  C2 (pairwise): flagged (m, s) pairs are dropped entirely.
  C0 (no exclusion): computed for transparency only.
  C3 SENSITIVITY, NOT IN THE STATEMENT: additionally require p <= 1
     (trials_per_relation >= 1), i.e. d <= L/m.
  C4 SENSITIVITY, NOT IN THE STATEMENT: C1 with integer d.
Lower bound d >= 0. It binds only for s <= 1 pairs, which are never optimal.

Flagged (m, s) pairs (the same set at every degree; 42 pairs):
  every (m, s) with 2 <= s and 2s < m, i.e.
  (5,2) (6,2) (7,2) (7,3) (8,2) (8,3) (9,2..4) (10,2..4) (11,2..5)
  (12,2..5) (13,2..6) (14,2..6) (15,2..7) (16,2..7).
  Pairs with s <= 1 are not flagged: their minimum is at d = 0, where total
  trials = 2^L. Pairs with m = 2s are not flagged: see section 3.

7. FINDINGS ABOUT THE QUANTITY ITSELF (for the Coordinator)
======================================================================
F1. The stated exclusion does not bind at any global optimum. Every
    optimum has m = 2s and total trials = s/(s-1), between 1.17 and 1.5,
    which is just above the exclusion threshold of 1.
F2. Every optimum sits where p > 1: p = |F| (s-1)/s, between 2^17.28
    (n=109) and 2^46.48 (n=571).
    The decomposition-probability formula p = |F|^m/(m! N) is being used
    where it exceeds 1. The cost then describes one MITM enumeration of
    ~1.2-1.5 targets that each decompose ~|F| ways. The statement does not
    say whether ~|F| decompositions of ONE target are |F| linearly useful
    relations. That is an unverified modelling assumption carried by the
    optimum. If p <= 1 is imposed (C3), every margin grows.
F3. The optimum always uses maximal store (s = m/2), with memory
    |F|^(m/2) between 1.12 and 1.32 bits below TOTAL. TOTAL charges only time.
    A rho baseline that charges no memory against an IC side whose store
    is ~ its time is the comparison as stated; flagged, not adjudicated.
F4. The structural bound in section 3 makes margin > 0 a theorem of this
    cost model for every N. A producer report claiming a negative margin
    under this model would be an arithmetic error, not a finding.
F5. FILL counts |F|^s ordered table entries. Counting multisets
    (~ |F|^s / s!) would lower FILL by log2(s!) bits. This was not
    computed. It does not affect F4: PROBE's lower bound alone keeps
    margin > 0 unless FILL is dropped entirely.
