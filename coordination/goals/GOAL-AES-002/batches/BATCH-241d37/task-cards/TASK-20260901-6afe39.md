## OBJECTIVE

Author a SUPERSEDING v2 of the C2 paired heuristic-validation design, fixing exactly the two load-bearing defects RT-20260901-1af5d9 objections 5 and 6 established. The v1 file (BATCH-286bcd TASK-20260901-354ef5/c2-paired-validation-design.yaml) is IMMUTABLE and must not be edited; v2 is a new file that supersedes it and names, verbatim, each v1 block it replaces.

DEFECT 1 — SEED_POLICY CONTRADICTS ARM-NULL's OWN CLAIM. v1's seed_policy defines SEED(key_size, arm, tier) as ARM-INDEXED, "used ONLY for that (key_size, arm, tier) combination's KEY draws; no seed is shared or reused across combinations". That means ARM-REAL (arm_idx=0) and ARM-NULL (arm_idx=1) draw K, K' from DIFFERENT INDEPENDENT streams, so their (K,K') values almost certainly differ. But the arms.ARM-NULL block asserts state_0 is "BYTE-IDENTICAL, sample for sample, to state_0 in ARM-REAL for the same (K,K') pair." As literally specified those two cannot both hold, and the design's central confound-control logic — holding the one nuisance variable constant across arms so a difference is attributable to the round-key CORRELATION STRUCTURE under test rather than to a different starting point — is false as written. An executor following seed_policy exactly would not be running the design the prose describes. RESOLVE IT — do not merely flag it. The red team's suggested shape, offered as a starting point and not a conclusion: draw K and K' from a SINGLE arm-independent stream per (key_size, tier, sample index), and reserve a SEPARATE arm-specific stream only for the additional 2*R round-key draws ARM-NULL alone needs. Verify that whatever you adopt actually delivers byte-identical state_0 across arms, and state how an executor would CHECK that at run time.

DEFECT 2 — THE DECAY CHECK DOES NOT CATCH A FLAT EXCESS. invalidation_rules item 1, labelled this design's central invalidation rule, is worded "TVD_{r+1}(arm) must not exceed TVD_r(arm) + tau(N)" — a round-to-round JUMP/re-emergence detector, not a did-this-series-ever-decay detector. A FLAT, persistently-elevated, never-increasing TVD series passes it cleanly. item 4 is clearly intended to route an ARM-NULL failure to "instrument flag", but its trigger text points back at item 1's narrow jump test, so a flat ARM-NULL excess trips nothing. Meanwhile falsification_criterion's three enumerated outcomes do not explicitly cover "ARM-NULL alone fails to converge while ARM-REAL converges normally" — the mirror image of outcome (ii), distinct from outcome (iii)'s "both persist together". EXTEND the rule so that case routes to one of the three named falsification outcomes (or to a fourth you name explicitly), and make item 4 trigger on ANY failure of ARM-NULL to reach and remain at-or-below tau(N) by the convergence window falsification_criterion already applies to ARM-REAL.

## WHAT UNCERTAINTY THIS REDUCES

Whether C2's paired design can be stated so that its confound control is real rather than asserted, and so that a null-control failure cannot pass undetected. Until both hold the design is not approvable for dispatch.
