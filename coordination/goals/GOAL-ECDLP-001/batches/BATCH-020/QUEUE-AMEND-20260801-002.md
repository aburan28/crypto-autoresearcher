# QUEUE-AMEND-20260801-002

Commit-set amendment to the TASK-20260731-045 snapshot declaration in
`coordination/goals/GOAL-ECDLP-001/batches/BATCH-020/dispatch_queue.json`.
Companion record: `ledger/decisions/DEC-20260801-002.yaml`.

Made **before** the TASK-20260731-045 commit, not after it. Nothing here
describes already-committed history, so this is not a correction of the
QUEUE-AMEND-20260801-001 class.

## What was added

`declared_commit_sets.TASK-20260731-045_snapshot` goes from 12 paths to 14:

| Path | Status |
|---|---|
| `experiments/EXP-DS-001/implementation/ds001_ctrl_unplanted.py` | NEW file — the control driver actually executed for RUN-DS-001-ctrl-unplanted |
| `experiments/EXP-DS-001/implementation/implementation.md` | MODIFIED — control appendix appended; nothing rewritten |

Two consequential edits accompany it:

- `TASK-20260731-044.artifact_paths` gains the same two paths (11 -> 13).
  This is forced by `tools/research_dispatch.py`, which computes an archive
  task's expected commit scope as
  `archive_task.artifact_paths | source_task.artifact_paths` and does not read
  `declared_commit_sets` at all. Amending only the declared set would leave the
  verifier expecting 12 paths against a 14-path commit and the archive would be
  rejected as scope-expanding — the exact failure this amendment exists to
  avoid. TASK-20260731-044's `handoff` block (objective, constraints,
  deliverables, handoff `artifact_paths`, completion gate, budget, inference) is
  left byte-for-byte as the Executor received it.
- TASK-20260731-045's handoff `constraints` gains two clarifying lines so
  "Stage exactly `declared_commit_sets.TASK-20260731-045_snapshot`" remains a
  true and sufficient instruction: one naming the 14-path content, one
  restating that `ds001_driver.py` and `verify_certificates.py` must **not** be
  staged. The commit-message constraint is unchanged.

## Why

The run package's own reproducibility pointers reference the new driver:

- `experiments/EXP-DS-001/runs/RUN-DS-001-ctrl-unplanted/command.txt` invokes
  `experiments/EXP-DS-001/implementation/ds001_ctrl_unplanted.py`;
- `manifest.json` references it in three places — `code.driver`,
  `code.driver_sha256`
  (`3ee4f68f4da6d7732e8d904243bd469d42c3bca527fa0c470e6216bfb9031d05`), and
  `code.command` / `code.argv`.

The Executor recorded `code.commit: 4e62780c6a141d629c0b51becef3ebe920e7f154`
with `code.dirty: true` for precisely this reason: the driver was not in any
commit. A snapshot staging only the original 12 paths would attest, under the
Coordinator's own signature, a run package whose exact-command artifact points
at a file the repository does not contain at that commit. That is the defect
class `tools/validate_ledger.py` already reports 90 times elsewhere in this
repository as `run.code.command missing (not reproducible)`; the EXP-DS-001 /
GOAL-ECDLP-001 chain is currently free of validator errors and this amendment
keeps it that way. Under AGENTS.md "Durable research commits", every produced
artifact must be assigned to exactly one archival task; before this amendment
these two files were assigned to none.

## Nothing unauthorized is being legitimized after the fact

Both files were written inside TASK-20260731-044's **already-authorized**
`write_scope`, whose entry `experiments/EXP-DS-001/implementation` was set when
the task was issued and is unchanged here. The Executor disclosed them at
`supporting_files_written_in_write_scope_beyond_declared_artifacts` in
`.../tasks/TASK-20260731-044/execution_report.yaml` and recorded PD-6, stating
that `ds001_ctrl_unplanted.py` is additive and that the pre-existing
`ds001_driver.py` was **not** modified (corroborated by
`manifest.code.shared_backend_module_modified: false` and the recorded
`shared_backend_module_sha256`). This amendment widens no write scope, grants no
new permission, and ratifies no out-of-scope write; it declares for archival two
in-scope, already-disclosed files.
