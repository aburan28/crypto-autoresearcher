# QUEUE-AMEND-20260731-005 — declare the instrument in TASK-20260731-045's snapshot

Recorded 2026-07-31 under `CORR-20260731-463`. Amends
`coordination/goals/GOAL-ECDLP-001/batches/BATCH-020/dispatch_queue.json` only.

## Why

`TASK-20260731-044`'s `write_scope` already contained
`experiments/EXP-DS-001/implementation`, so the executor was authorised to
modify the driver — and it did, adding `--mode ctrl-unplanted` (787 insertions,
2 deletions). But `TASK-20260731-045`'s declared commit set named only the
eleven run/result deliverables plus its own receipt.

Because `tools/research_dispatch.py` requires an archive commit to change
**exactly** the declared set, the batch as drafted admitted **no legal
outcome**:

- staging the driver → `extra ['experiments/EXP-DS-001/implementation/ds001_driver.py']`
- omitting it → the run artifacts are committed **without the code that produced
  them**, breaking the manifest's code binding and the reproducibility rule in
  `docs/claims-and-verification.md`

Declaring the instrument is the only resolution that keeps artifacts and
generating code in one immutable snapshot — and it is the only way the
independent reviewers can read the code behind the numbers they review.

## The two changes

| Field | Before | After |
|---|---|---|
| `TASK-20260731-044.artifact_paths` | 11 paths | 12 paths (`+ experiments/EXP-DS-001/implementation/ds001_driver.py`) |
| `declared_commit_sets.TASK-20260731-045_snapshot` | 12 paths | 13 paths (same addition) |

The snapshot commit therefore changes **12** paths; the receipt lands one commit
later per `INT-BATCH007-T`, exactly as for `TASK-20260731-041`.

`--mode` choices list gaining `ctrl-unplanted`, and `if args.mode != "finalize"`
rewritten as the semantically identical `if args.mode not in ("finalize",)`.
`BACKEND_ID` and the cost/search/null primitives are reused unchanged.

## Disclosure — read this before treating the amendment as routine

**This amendment accommodates a change made by the orchestrating session's own
subagent.** The instrument that produced every number in this run was written by
the same session that ran it, within the same task, and has had **no independent
review**. Producer-authored measurement code is the highest-risk item in this
batch. It is the first thing `TASK-20260731-046` (Validator) and
`TASK-20260731-047` (Red Team) should attack, specifically:

1. Does `harvest_real_unplanted` genuinely draw targets with **no** planted
   decomposition witness (`T = k·P`, `k` uniform in `[1, n-1]`)?
2. Is the live `/4` plant companion free of the synthetic known-answer shortcut
   that `CTRL-RT025-UNPLANTED.yaml` forbids?
3. Are the charged-unit and null-arm paths byte-identical in behaviour to the
   planted package, so `BACKEND_ID` is still truthful?
