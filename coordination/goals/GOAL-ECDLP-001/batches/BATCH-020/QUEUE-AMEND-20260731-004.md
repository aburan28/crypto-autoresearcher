# QUEUE-AMEND-20260731-004 — rebind TASK-20260731-041 to the decision path its commit actually contains

Recorded 2026-07-31 under `CORR-20260731-007`. Amends
`coordination/goals/GOAL-ECDLP-001/batches/BATCH-020/dispatch_queue.json` only.

## Why

`tools/research_dispatch.py` refused the whole BATCH-020 queue:

```
dispatch error: archive task TASK-20260731-041 commit must change exactly
declared archive and source artifacts
(missing ['ledger/decisions/DEC-20260731-019.yaml'];
 extra   ['ledger/decisions/DEC-20260731-010.yaml'])
```

With no rendered plan, **no BATCH-020 task was dispatchable at all** — including
`TASK-20260731-044`, the next action named in the goal record.

Cause: archive `TASK-20260731-041` is bound to commit
`cac4d8b459a44f1561d3f47835562824f7767765`, which created the decision at
`ledger/decisions/DEC-20260731-010.yaml`. Merge `da6f4fda` later renamed that
record to `DEC-20260731-019` to clear an ID collision with `origin/main`, and
the queue's binding fields were updated to the new ID. A pushed, merged commit
cannot be rewritten, so those fields described a tree that does not exist at the
bound commit.

## The four changes

| Field | Before | After |
|---|---|---|
| `TASK-20260731-040.artifact_paths[]` | `ledger/decisions/DEC-20260731-019.yaml` | `ledger/decisions/DEC-20260731-010.yaml` |
| `TASK-20260731-040.write_scope[]` | `ledger/decisions/DEC-20260731-019.yaml` | `ledger/decisions/DEC-20260731-010.yaml` |
| `TASK-20260731-041.archive.path_sha256` key | `ledger/decisions/DEC-20260731-019.yaml` | `ledger/decisions/DEC-20260731-010.yaml` |
| `TASK-20260731-041.archive.record_ids[]` | `DEC-20260731-019` | `DEC-20260731-010` |

**No hash value changes.** The recorded hash
`b76b7f915cf5625ada84e9e933bfd9919c592e9cd2eb1ec0f4d563820097189e` was already
the sha256 of `DEC-20260731-010.yaml` inside commit `cac4d8b4`; only the key
beside it was wrong. That is the proof of identification, not an assumption.

`record_ids` follows the same logic: the verifier requires each id to appear
literally in the bound commit message, and that message reads
`... DEC-20260731-010 GOAL-ECDLP-001 BATCH-020`. It names `-010` and never `-019`.

The `write_scope` entry is the fourth: once `artifact_paths` named `-010`, the
renderer refused again with `tasks[0].artifact_paths must be inside its
write_scope`. Both fields describe what the completed producer was permitted to
write and did write, and at that time it was `-010`.

## Everything else is deliberately left naming the live record

The renderer binds on the **top-level** `artifact_paths`, `write_scope`,
`archive.path_sha256` and `archive.record_ids` only. Eight other
`DEC-20260731-019` references remain in this queue — `authorization_status`,
`declared_commit_sets.TASK-20260731-041_snapshot[4]`, the `tasks[0]`/`tasks[1]`
handoff objectives and constraints, `tasks[0].handoff.deliverables[4]`,
`tasks[0].handoff.artifact_paths[4]`, and `tasks[2].handoff.inputs[4]`. Those
are prose or worker-facing mirrors and they correctly denote the **live**
record. This queue is therefore **internally split by design**: binding fields
name the blob inside `cac4d8b4`; everything else names the live decision.
Rewriting the mirrors was rejected as over-reach into a queue another session
authored.

## What this amendment does not do

- **No ledger decision record is moved, renamed, edited or reverted.**
  `DEC-20260731-019.yaml` remains the live ECDLP/`EXP-DS-001` `revise` decision.
  `DEC-20260731-010.yaml` remains `main`'s unrelated AES/FAEST `approve` decision.
- No task state is changed, no run is authorized, no hypothesis or claim tier
  moves, and no completion criterion is met.
- The `da6f4fda` remap is **not** undone. It was correct and it stands.

## The trap, recorded rather than hidden

After this amendment the queue names `ledger/decisions/DEC-20260731-010.yaml`,
and **the file at that path in the working tree is not the record the queue
means** — it is `main`'s AES/FAEST decision. The entry refers to the blob at
that path *inside commit `cac4d8b4` only*. The live ECDLP decision this archive
produced is `DEC-20260731-019`.

## Structural note for the Coordinator

Any ID remap that renames a ledger record already named in a **completed**
archive's binding fields breaks that archive's verification permanently, since
the commit is immutable. Two sibling goals are refusing to render for their own
binding defects as of this date and are **not** repaired here:
`GOAL-CRYPTO-001` BATCH-013 (`completed archive task TASK-20260731-002 requires
archive.commit_sha`) and `GOAL-DREG-001` BATCH-003 (`tasks[0].handoff.inputs
must be a nonempty text list`).
