## Falsifiable hypothesis

Encode pair endpoints as public w-bit keys whose predecessor/successor around a target-derived query isolates the complementary source bucket. Fusion-node bit sketches and parallel comparisons would give exact restricted source replay, relations, and blind descent below rho and BSGS.

## Mechanism-new operation

Fusion trees compress distinguishing key bits and compare multiple supplied w-bit integers in parallel on a word RAM, giving sublogarithmic predecessor queries. It counts only if keys are DLP-free endpoint invariants, order proximity is biconditional with exact elliptic compatibility, and stored satellites are not a source catalogue. Indexing explicit pair/scalar keys is a control.

## Assumptions

1. A target-independent injective ordered w-bit key exists for every signed and exceptional endpoint occurrence.
2. Key generation, word size/instructions, sketches, node build, restrictions, satellites, replay, rank, logs, descent, bit time, and memory are charged.
3. Predecessor/successor identifies exact nonempty support, not merely a nearby endpoint.
4. Equal keys and arbitrary restrictions preserve occurrence ancestry without rebuilding the dictionary.
5. The same index serves fresh blind targets without scalar residues or hidden DLP advice.

## Full rho/BSGS cost model

Let n be stored keys, w word bits, U=2^w, C_key key work, Q_R restrictions, and C_inv satellite inversion. A fusion tree uses O(n) words, predecessor O(log_w n) word operations, and build at least linear key access; bit-operation and multiplication tables are charged. Set a=log_N(T_keys+n C_key+T_build), a_m=log_N(nw+M_tables), q=log_N(Q_R(C_query log_w n+C_inv+T_restrict)+T_replay), and q_m=log_N(nw+M_query+M_inv). With beta=1/5 and delta,delta_t,r,o,u,ell,ell_m:

lambda=max(a,beta+delta+q-r+o,ell,delta_t+q+o+u,beta)

mu=max(a_m,q_m,beta+o,ell_m,u), 0<=r<=o.

Require setup/state <=B^(9/4+o(1)), complete fresh work <=N^(0.25+o(1))=B^(5/4+o(1)), lambda,mu<=0.45, and four increasing-B one-sided 95% bounds. Rho and BSGS are 0.50.

## Likely fatal obstruction

A useful total order on prime-order elliptic points is not compatible with group addition; scalar-order keys are partial DLPs. Faithful pair keys/satellites materialize the source dictionary, while coordinate keys make predecessor proximity unrelated to exact equality. Arbitrary restrictions require persistent source labels or rebuilds. This merges with pre-ID C02/E07 and IDEA-374.

## Proof track

Construct a DLP-free endpoint key/order with exact restricted predecessor/source biconditional and close word/bit, satellite, replay, rank, and descent costs.

## Disproof track

Show one key uses scalar coordinates, give adjacent coordinate keys with different compatibility, or expose pair-source satellites/dictionary state.

## Positive and negative controls

- Positive: supplied integer keys with a unique labelled predecessor.
- Negative: coordinate-near but group-incompatible points, equal keys with different ancestry, deletion-heavy restrictions, exceptional and blind targets.
- Baselines: pre-ID C02/E07, IDEA-374, explicit pair dictionaries, P1553 R4, rho, BSGS.

## Quantitative promotion and falsification gates

- Promote only with DLP-free endpoint keys, exact restriction-stable predecessor/source inversion, rank d_FB, 100 blind descents, both caps, and lambda,mu<=0.45.
- Falsify on scalar/source-bearing keys, one neighbor/source mismatch, rebuild beyond cap, or complete exponent >=0.50.
