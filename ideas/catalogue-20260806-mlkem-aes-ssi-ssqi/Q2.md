### 0.2 Tracked objects and the lossy-projection test

Three objects are shared across entries. Each is checked against the requirement that the
projection be **structurally** lossy, not a change of coordinates (the `KN-LIT-7595` (Δ,Π) failure
mode: a pair recoverable from the original, therefore a repackaging).

**TO-MASS — the degree-graded mass profile of the table.**
Projection: `L(E,X,B) ↦ (mass(t))_{t ≤ X}` where `mass(t) = #{entries of degree ≤ t}`.
*Discards*: every curve, every kernel, every witness, and the identity of every entry; it keeps a
scalar function of one variable. *Fibre*: the set of tables with a given profile is astronomically
large — mass(t) is a 50-number summary of a 2^{93.28}-entry object. *Compatible with the
operations?* Yes: Algorithm 1 extends an entry of degree d to degree dℓ (L143–L152), so the profile
evolves by a deterministic transport `mass ↦ mass ∘ (t/ℓ)` summed over admissible ℓ; and
Algorithm 2's decision (L167, L177–L185) is a statement about *degrees* — `deg ψ ≤ X`,
`deg η ≤ X`, `deg ψ · deg η = deg φ` — so the correctness condition factors through the profile
plus the divisor set of deg φ. *Not invertible*: nothing about which curve sits where survives.
**Verdict: passes.** TO-MASS is the object Q2-1 optimises over and Q2-7 and Q2-9 consume.

**TO-FIBRE — the walk-choice coordinate.**
Projection: `(entry ψ of degree d) ↦ (the sequence of root-choices made at each ℓ-step)`, i.e. the
index of ψ inside the fibre over its degree. *Discards*: the degree itself, the codomain, and all
field data. This is **exactly the complement of C1's TO-MULT**, which discards the fibre and keeps
the multiset of primes; C1 states that "the discarded data is precisely what C2 tracks". This
slice takes ownership of it. *Why it is the right object for F3*: `M = Ψ(X,B)·X` (L230) is
(#smooth degrees) × (fibre size ≈ d, from "the number of isogenies of degree d is at least d"), so
**of the exponent 1/3, one half — p^{1/6} — is the fibre and one half is the degree count.** The
fibre is where the algorithm has free choice and where a restriction can be applied without
touching the smoothness argument. *Not invertible*: the degree is unrecoverable from the choice
sequence alone (the same choice pattern occurs over every degree of the same factorisation shape).
**Verdict: passes.** Q2-10 is a measurement on TO-FIBRE; Q2-4 truncates its image.

**TO-ACCESS — the access trace.**
Projection: `(a run of Algorithm 2) ↦ the sequence of (storage-tier, block, timestamp) triples it
issues`. *Discards*: every value, every field operation, every mathematical fact — it keeps only
the shape of the memory traffic. *Compatible?* Yes, trivially: the trace is what a machine
executes. *Not invertible*: the trace of a correct run and of a run on random data are identical
in distribution, which is precisely why an access-trace statement is a statement about machines
and never about mathematics. **Verdict: passes, with the standing caveat that no TO-ACCESS result
may ever be read as a statement about the paper's theorem.** Q2-2, Q2-3 and Q2-6 track it.

### Q2-1. The reciprocal-straddle threshold: store the *low-degree* side only, because table mass is quadratically top-weighted and every admissible split has one small half

**Tracked object** — TO-MASS, specialised to the two-parameter family `(X′, τ)`: `X′` is the
radius of the list that is *generated and streamed*, `τ ≤ X′` the degree threshold below which
entries are *stored*. **Discards**: every curve, kernel and witness; keeps only `mass(t)` and the
divisor set of `deg φ`. The discard is structural — the fibre over a profile is the whole table —
and it is exactly the data Q2-10 tracks, so the two entries are complementary rather than nested.

**Mechanism** — Lemma 3.4 (L177–L185) proves the *greedy* split works, but any divisor `d` of
`D = deg φ` with `D/X ≤ d ≤ X` yields a valid pair (ψ of degree `d`, χ = η̂^{(p)} of degree `D/d`),
and Algorithm 2's lookup is symmetric in the two members (iterating over (E′^{(p)}, χ) and testing
`(E′^{(p)})^{(p)} = E′` finds the same pair). Since `d · (D/d) = D`, **every admissible split has
one member ≤ √D and one ≥ √D**. Therefore it suffices to *store* `L(E,τ,B)` and *stream*
`L(E,X′,B)`, with success requiring a divisor of `D` in the window `[D/τ, X′]` of multiplicative
width `W(X′,τ) = X′τ/D`. Two facts make this a real trade rather than bookkeeping:
1. **Mass is quadratically top-weighted.** With `#{isogenies of degree d} ≈ d` (L230) and smooth
   density `ρ(u(t))` slowly varying, `mass(t) ≈ κ·t²·ρ(log t/log B)`. So halving `log τ` costs a
   **quadratic** factor of memory while the window shrinks only **linearly**.
2. **The window is consumed logarithmically, not multiplicatively.** Success needs one divisor in
   a log-window of width `log W`; with golden-claw multiplicity `R ≈ τ(D)/u ≈ 2^5.4…2^11.4`
   (C2-3, MODELED-HERE and deliberately wide) spread log-uniformly over the full 14.2-octave
   window, a **1-octave** window still expects `R/14.2 ≈ 3…190` divisors.

**Prediction (MODELED-HERE, can fail)** — At NIST-I with `log2 X = 49.6`, `log2 D = 85`,
`log2 B_opt = 14.2`, Dickman `ρ(2.563) = 0.115`, `ρ(2.993) = 0.0493`, `ρ(3.493) = 0.0165`:
- `τ = X/√B = 2^{42.5}` (window 7.1 octaves, half the incumbent): memory
  `M·2^{−14.2}·(0.0493/0.0165) = M·2^{−12.62} = 2^{80.66}`, time unchanged at `M/P0 = 2^{108.73}`,
  success cost ≤ 1 bit.
- `τ = 2D/X = 2^{36.4}` (window exactly 1 octave, the floor): memory
  `M·2^{−26.4}·(0.115/0.0165) = M·2^{−23.6} = 2^{69.68}`, time unchanged, success cost
  `−log2(1−e^{−3}) = 0.07` bits if `R = 2^{5.4}`.
- **Frontier position**: vOW at `w = 2^{69.68}` costs `M^{3/2}/w^{1/2}/P0 = 2^{120.53}` under the
  vOW-consistent form, so this point sits **11.8 bits below the vOW curve at equal memory**. Under
  C2-1's form (a) the comparison changes and both must be printed.
- **Hard floor, stated as the entry's own ceiling**: `τ ≥ D/X` forces memory
  `≥ mass(D/X) = M/B²·(ρ ratio) = 2^{67.7}`. Memory exponent stays **1/3** because `B = p^{o(1)}`;
  the time exponent is untouched at every point. This is an o(1)-shape lever and nothing else.

**Minimal discriminating test** — Pure integer arithmetic; no curves, no isogenies, no network.
(i) For `D` ranging over B-smooth integers near `2^{40}, 2^{48}, 2^{56}` with `B` set so
`u ∈ {3, 3.5, 4}`, enumerate all divisors and measure `N_div(W)` = count in a window of
multiplicative width `W` positioned at `[D/τ, X′]`, for `log2 W ∈ {0.5, 1, 2, 4, 7.1, 14.2}`.
(ii) Emit `success(W) = Pr[N_div(W) ≥ 1]` and the resulting (time, memory) frontier under both
vOW anchors and both cost laws. (iii) Verify `mass(t) ≈ κt²ρ(u(t))` on an exhaustively enumerated
toy table at `log2 p ∈ [20, 32]`, `B ≤ 100`, `ℓ ≤ 7` (no Φ_ℓ fetch needed).
**Known-answer gate** — at `W = X²/D = B` the window is the incumbent's and `N_div` must reproduce
C2-3's `R = τ(D)/u` to within its stated band; and at `τ = X′` the construction must return the
incumbent's memory `mass(X)` **exactly**. Machinery that cannot reproduce the point it generalises

**Falsifier (numeric)** — `Pr[N_div(1 octave) ≥ 1] < 0.5` at the predicted τ ⇒ the free window is

**Charged cost** — implementation low (~200 lines: smooth enumeration, divisor enumeration, window

### Q2-2. One memory axis is one too few: fast memory and total storage are different resources, and the external-memory branch of the claw has never been plotted

**Tracked object** — TO-ACCESS, projected to the pair `(w_fast, S_total)` = (working set that must
support random access at unit cost, total bytes that must exist at all). **Discards**: all
mathematics, all values, all arithmetic — it keeps two scalars per algorithm. The discard is
structural: two algorithms with identical `(w_fast, S_total)` can compute entirely different
things, and no map recovers the computation from the pair.

**Mechanism** — Every curve the campaign plots — the incumbent full-memory point, vOW
`M^{3/2}/w^{1/2}`, C2-1's streaming control `M²/w`, C2-11's re-optimised curve, Q2-1's threshold
point — is *storage-honest*: it uses `w` bytes and no more. That is a coincidence of which
algorithms were considered, and it hides a branch that is by a wide margin the fastest known way
to execute Algorithm 2's matching step on a real machine: **materialise all M entries in slow
storage and do a sort-merge (or partition-hash) join.** In the external-memory model with fast
memory `w` records and block `b` records, the join costs `Θ((M/b)·log_{w/b}(M/b))` I/Os, not
`M^{3/2}/w^{1/2}` evaluations. The two branches occupy incomparable points of a **three-axis**
frontier `(time, w_fast, S_total)`, and the campaign's single-`w` projection makes them look like
alternatives on one curve when they are not.

**Prediction (MODELED-HERE)** — At NIST-I with `M = 2^{93.28}` records, a 64-byte key
(`j ∈ F_{p^2}` at log2 p = 256), `b = 2^{12}` records per 256 KB block, `w = 2^{30}` records:
`log_{w/b}(M/b) = 81.28/18 = 4.52` passes; I/O cost `2·4.52·M/b = 2^{84.5}` block transfers
`= 2^{96.5}` record transfers; against vOW at the same `w`, `2^{120.5}` (vOW-consistent anchor) or
`2^{93.7}+overhead` (form (a)) function evaluations. **Under the vOW-consistent anchor the
external-memory branch is ≈ 24 bits cheaper in operations and requires `S_total = 2^{99.3}` bytes
against vOW's `2^{36}`.** The honest reading is therefore the reverse of a speedup claim: it shows
that **the binding physical resource for this algorithm was never time and was never fast memory —
it is total storage**, and every margin the campaign has quoted is a margin in the one resource
that is not binding. Predicted deliverable: a Pareto set in three axes at all five field sizes, in
which the incumbent, vOW, streaming, Q2-1 and sort-merge each own a region, and no single number
"the cost of the attack" survives.

**Minimal discriminating test** — Zero compute. (i) Emit the three-axis table for five field sizes
× {incumbent, vOW at `w ∈ {2^30, 2^40, 2^50}`, streaming `M²/w`, Q2-1's threshold point,

### Q2-3. "Parallelizes perfectly" has an unstated validity range in n: derive the parallelism ceiling in house, and emit the wall-clock floor that no processor count can beat

**Tracked object** — TO-ACCESS, projected to the **in-flight chain census**: the number of chains
alive at each instant, together with the arrival rate of distinguished points at the shared store.
**Discards**: which chains, which points, every field element, the entire mathematics. Structural:
the census of a real run and of a run on a random function are identical objects.

**Mechanism** — L39 says the algorithm "parallelizes perfectly" (a statement about arithmetic) and
L41 gives `p^{1/2+o(1)}/(w^{1/2}·n)` for the vOW branch, **linear in n with no stated range**. The
vOW source is unreachable and its own validity range in `(w, n, θ)` is untranscribed (C2's open
direction (iii)). Rather than assert the range, derive candidate constraints from self-contained
arguments and let the audit decide which binds:
- **N1 — abandoned-chain waste.** Each of `n` processors abandons one partial chain of mean length
  `1/θ` at termination, so wasted work is `n/θ` and efficiency requires `n/θ ≤ εT`, i.e.
  **`n ≤ εθT`**.
- **N2 — store insert bandwidth.** The shared distinguished-point store receives `nθ` inserts per
  step and can absorb `β`, so **`n ≤ β/θ`**.
- **N3 — collision-detection latency.** A golden collision is invisible until both chains have
  reached their next distinguished point, adding `O(1/θ)` to the wall clock — a floor independent
  of `n`.
Optimising θ against N1∧N2 gives **`n ≤ √(εβT)`** and hence a wall-clock floor
**`T_wall ≥ √(T/(εβ))`** that no processor count removes. `β = 1` models a single serialised
store; `β = w` models a fully distributed one, and the gap between them is the entry's most
useful output because it prices the interconnect design choice directly.

**Prediction (MODELED-HERE)** — At NIST-I, vOW-consistent anchor, `w = 2^{30}`, `T = 2^{140.4}`,
`ε = 1/2`: `β = 1` ⇒ `n ≤ 2^{69.7}` and `T_wall ≥ 2^{70.7}`; `β = w = 2^{30}` ⇒ `n ≤ 2^{84.7}` and
`T_wall ≥ 2^{55.7}`. So **the parallel attack has a wall-clock floor of 2^{56}–2^{71} steps
regardless of budget**, and the line-41 formula is being used 30–70 bits outside any range this
derivation supports. Direction: **against the attack**, which is why it must be reported with the
same weight as any pro-attack correction — and equally, if the simulation shows efficiency holding
past `√(βT)`, the paper's unqualified formula gains a control it currently lacks.

**Minimal discriminating test** — A synthetic parallel-vOW simulation; no isogenies. On a random
function over `N ∈ {2^18, 2^20, 2^22}` with one planted golden collision, at memory
`w ∈ {2^8, 2^10, 2^12}`, sweep `n ∈ {1, 2, 4, …, 2^12}` and `θ ∈ {2^{-4} … 2^{-10}}`; measure total
function evaluations and wall-clock steps; emit parallel efficiency `E(n) = T(1)/(n·T(n))` and
locate the `n` at which `E` first falls below 0.9. Compare against the predicted `√(εβT)` scaled to
the simulated sizes. **Known-answer gate** — at `n = 1` the simulator must reproduce the serial
distinguished-point cost `≈2.5·√(N³/w)`; at `θ = 1` (every point distinguished) memory usage must
equal the step count until the store fills, and efficiency must be 1 for all `n` up to the store
bandwidth. A simulator failing either gate is void and nothing downstream is readable.

**Falsifier (numeric)** — `E(n) ≥ 0.9` all the way to `n = N/w` at every simulated size ⇒ neither
N1 nor N2 binds in the tested regime, the parallelism ceiling is an artifact of the derivation, and
the entry closes in the attack's favour. `E(n)` falling below 0.5 at `n ≈ √(βT)` in the simulation,
with the location tracking `√(βT)` across three sizes ⇒ the ceiling is real and the wall-clock floor
above must be carried in every threat statement.

**Charged cost** — implementation medium (a correct distinguished-point simulator with a modelled
shared store; ≈400 lines, and it is the *same* simulator C2-3 needs, so the two should share one
build). Compute low, ≤ 3 CPU-hours, pure Python. **Charged**: the simulation charges store inserts
and lookups as operations, not as free; a run that charges only function evaluations is measuring
the wrong thing and must be rejected at review.

**Ceiling** — `toy` (synthetic, `N ≤ 2^22`, no isogenies). The extrapolation from a synthetic
random function to the real key map is exactly what C2-10 tests and may not be assumed here. Risk
band: **conservative**.

**Nearest prior-art neighbour** — **C2-6** (`charge_the_machine_not_the_RAM`) and **C2-8**

### Q2-4. Memory is counted in entries and paid in bits: the fingerprint-truncated table and the false-positive recomputation curve

**Tracked object** — TO-FIBRE's image under a **t-bit fingerprint**: `entry ↦ (H_t(key), seed)`
where `H_t` is a t-bit hash of the codomain and `seed` regenerates the walk. **Discards**: `2 log p
− t` bits of the key and the entire explicit witness (Algorithm 1 already represents entries as
*sequences of curves*, L147 — several hundred to a few thousand bits each). The fibre over a
fingerprint has expected size `M/2^t`, and the discarded bits are **not** recoverable without
re-running the walk, which is precisely the cost the construction pays. Structurally lossy, and the
loss is the mechanism.

**Mechanism** — The committed memory figure `2^{92.5}`/`2^{93.28}` counts **entries**, and §4.1
(L230) says "the memory cost of the algorithm is ≈ M" in the same breath as counting F_{p^2}
operations. An entry is not a bit. Storing a full j-invariant costs `2 log2 p = 512` bits at
NIST-I; storing the witness as a sequence of curves costs `Ω(deg ψ)·512 ≈ 1792` bits at
`Ω ≈ 3.5`. A collision *detector* needs only enough bits to make false positives rare, plus a seed
to reconstruct on a hit. Then memory in bits is `M·(t + |seed|)` and time acquires a second term
`M·(M/2^t)·C_rec`, where `C_rec = Ω(deg)` steps is the cost of regenerating a witness from its
seed. Optimising: `2^{t*} = M·C_rec`.

**Prediction (MODELED-HERE)** — At NIST-I: `C_rec ≈ 2^{3.3}` steps (Ω(deg ψ) for a B_opt-smooth
`deg ψ ≤ 2^{49.6}`), so `t* = 93.28 + 3.3 = 96.6` bits, giving false-positive work
`M²/2^{t*}·C_rec = M = 2^{93.28}` — i.e. exactly a doubling of the time, 1.0 bit, by construction
of the optimum. Memory in bits falls from `M·1792` to `M·(96.6 + |seed|)`; with `|seed| = 64`,
that is `2^{93.28+10.81} = 2^{104.09}` bits → `2^{93.28+7.33} = 2^{100.61}` bits, a **3.5-bit**
memory saving for **1.0 bit** of time. Two consequences larger than the saving itself:
(i) **the committed memory figure understates physical memory by `log2(bits per entry)` = 9.0–10.8
bits**, and every byte-denominated statement in the campaign (including Q2-2's `S_total`) inherits
it; (ii) **C2-6's area–time computation charges `M` cells, where a cell is 512–1792 bits** — its
2-D area is understated by the same 9.0–10.8 bits, which shifts `AT = M^{3/2}` by `1.5×` that
amount unless the cell size is charged. That second consequence is a correction to a committed
sibling entry, not a new attack, and is the main reason this entry exists.

**Minimal discriminating test** — (i) Arithmetic: emit memory-in-bits and the
`(t, memory_bits, time)` curve for `t ∈ {log2 M − 8, …, log2 M + 32}` at five field sizes, under
both cost laws. (ii) Toy measurement of `C_rec`: on the exhaustive toy table (`log2 p ∈ [20,32]`,
`B ≤ 100`, `ℓ ≤ 7`), measure the mean and tail of `Ω(deg ψ)` weighted by entry count, and the
measured false-positive rate of a t-bit fingerprint against the modelled `M/2^t`.
**Known-answer gate** — at `t = 2 log2 p` (no truncation) the false-positive term must be **exactly
zero** and memory must reproduce the naive `M·2 log2 p` bits; and the measured false-positive rate
at `t = log2 M` must equal `1/2` per full-table scan to within binomial error. An instrument that
misses either is void.

**Falsifier (numeric)** — Measured `Ω(deg ψ)` entry-weighted below 2 ⇒ `C_rec` is smaller than
modelled, `t*` drops, and the saving grows (an outcome *favourable* to the attack, to be reported
with equal weight). Measured false-positive rate exceeding the modelled `M/2^t` by more than 2× at
any `t` ⇒ the codomain keys are not uniform under `H_t`, which is a C2-10-shaped structural signal
and must be escalated there rather than absorbed here. If bits-per-entry turns out already to be
charged somewhere in the committed model, the whole entry collapses to a pointer — checkable in
ten minutes by grepping `cost_model.py` for a bits-per-entry constant.

**Charged cost** — implementation low; compute ≤ 1 CPU-hour on the shared toy table.
**Charged and not waived**: the seed must determine the walk *deterministically*, which forbids any
adaptive choice during table construction; and the recomputation on a hit must be charged at the
**measured** per-step law with its 21.1–25.9-bit overhead, not at §4.1's one-operation convention.

**Ceiling** — `toy` for `C_rec` and the false-positive rate; model substitution with **no claim
tier** for the bit-denominated table. Risk band: **representation_changing** (the table is
re-represented as fingerprints plus seeds; correctness is preserved only up to the false-positive
recheck, and the entry stands or falls on that recheck being charged).

**Nearest prior-art neighbour** — **C2-4** (`frobenius_orbit_quotient | exactly_1.0_bit_ceiling`).
**Why it is not that**: C2-4 halves the number of *entries* by quotienting the key space by an
order-2 automorphism; Q2-4 leaves the entry count untouched and changes the number of *bits per
entry*, buying memory with recomputation. The two compose (a canonical-form fingerprint is both)
and their savings add rather than overlap.

### Q2-5. Is there a proximity sketch for the isogeny metric? The near-neighbour relaxation of the claw, and the expansion obstruction that is expected to close it

**Tracked object** — a **sketch** `S: j ↦ {0,1}^s` from a pre-declared finite family, tracked
through its two collision probabilities: `q_r = Pr[S(j₁) = S(j₂) | dist(j₁,j₂) ≤ r]` and
`q₀ = Pr[S(j₁) = S(j₂)]` for independent uniform supersingular `j`. **Discards**: everything about
the curve except `s` bits; the fibre of `S` has size `≈ (p/12)/2^s`. Structurally lossy for any
`s ≪ log p`, and the entry's whole content is whether the retained bits can carry *metric*
information.

**Mechanism** — Algorithm 2's comparison is an **exact** equality test, and exact matching by
hashing is already optimal — there is nothing for locality-sensitivity to do. The place where LSH
could enter is the **relaxation**: accept a pair whose codomains are within distance `r` in the
ℓ-isogeny graph instead of equal. This is not idle: the classical [24,26] method (L53) is exactly
the `r = 1` case (draw walks until `E′` is *adjacent* to `E′^{(p)}`). Relaxing to radius `r`
multiplies the number of acceptable pairs by the ball size `≈ ℓ^r` — but the composed isogeny then
has degree `deg ψ · ℓ^r · deg χ`, i.e. the relaxation is an increase of the covered degree range
by `ℓ^r`, which is **the same object as increasing X** and would be a mere change of coordinates
if that were all. It is not all, because the *storage* of a ball can in principle be sublinear in
its size: a ball is determined by its centre. So the sharp question, and the only one worth an
experiment, is: **does there exist an `s`-bit sketch, computable from `j` alone in `o(ball)` time,
with `log(1/q_r)/log(1/q₀) < 1 − δ` for a fixed `δ > 0`?** The expected answer is no, with a
statable mechanism: in a Ramanujan graph the ball of radius `r` has `≈ ℓ^r` vertices for every `r`
up to `log_ℓ(p)`, so the metric has **doubling dimension Θ(log p)** — maximal — and a space whose
doubling dimension matches its log-cardinality has no non-trivial locality-sensitive family; the
same expansion that makes CGL-style hashing sound is what forbids the sketch.

**Prediction** — For every member of the declared family, the measured LSH exponent
`ρ_LSH = log(1/q_r)/log(1/q₀) ≥ 1 − O(1/log p)`, with no member reaching `ρ_LSH ≤ 0.9` at any
`r ≥ 1`. **Expected verdict: CLOSED**, and that is the point of running it — it converts "LSH on
the list comparison" from an unexamined direction into a closed one with a named mechanism, and it
names what would have to change (a *non-expanding* auxiliary graph, i.e. lever N5's oriented or
prescribed-torsion targets, not this graph).

**Minimal discriminating test** — Declared family, fixed before the run: `S₁` = low `s` bits of
`Tr(j) = j + j^p`; `S₂` = low `s` bits of `N(j) = j^{1+p}`; `S₃` = the multiset of roots of
`Φ_2(j, y)` hashed σ-stably; `S₄` = a random linear functional of the `F_p`-coordinates of `j`;
`S₅` = the identity (control). At toy `p` with `log2 p ∈ [20, 32]`, build the full 2-isogeny graph,
sample pairs at exact distances `r ∈ {0,1,2,3,4}` and uniform pairs, and measure `q_r`, `q₀`,
`ρ_LSH` with bootstrap intervals, for `s ∈ {4, 8, 12, 16}`.
**Known-answer gate** — `S₅` (identity) must return `q_0 = 1`, `q_{r>0} = 0` and `ρ_LSH = 1`
exactly. **Positive control**: run the identical instrument on a graph that *is* LSH-able — a cycle
`C_n` with `S = ⌊position/k⌋` — and confirm it reports `ρ_LSH < 0.5`. An instrument that cannot see
locality where locality exists has no power and its negatives mean nothing.

**Falsifier (numeric)** — Any declared sketch achieving `ρ_LSH ≤ 0.9` at `r ≥ 2` with evaluation
cost `o(ℓ^r)` falsifies the expansion argument at the tested scale and becomes a hypothesis
immediately (and, per C2-12's discipline, would require independent review before any further
work, since a metric shortcut on this graph is adjacent to a partial break). All members at
`ρ_LSH ≥ 0.99` with the cycle control firing ⇒ CLOSED for the declared family at the tested scale,
scoped exactly that far (AGENTS.md rule 6), never restated as "no sketch exists".

**Charged cost** — implementation medium (graph construction at `log2 p ≤ 32` with `ℓ = 2` only;
no Φ_ℓ fetch beyond `Φ_2`, so no network dependency). Compute ≤ 4 CPU-hours. **Charged**: sketch
evaluation time is measured per call and any sketch whose evaluation is `Ω(ball)` is disqualified
**before** its `ρ_LSH` is read — otherwise the test rewards sketches that are secretly enumerating
the ball.

**Ceiling** — `toy`, hard: five sketches on 2-isogeny graphs at `log2 p ≤ 32`. Risk band:
**high_risk**.

**Nearest prior-art neighbour** — **IDEA-20260806-d5a34e**
(`isogeny_graph_query_model | girth_excludes_Fp_locus`) and **C2-12**
(`non_materialised_claw_search | predictor_computable_from_j(E)_alone`). **Why it is not those**:
d5a34e asks for a *query lower bound* on the whole algorithm in a stated oracle model; C2-12 asks
whether a predictor computed from `j(E)` concentrates the *middle key* of a specific instance.
Q2-5 asks neither — it asks whether the **pairwise metric** on table keys admits a sublinear
proximity index, which is a property of the graph rather than of an instance, and whose obstruction
is expansion rather than query counting or circularity.

### Q2-6. The quantum advantage is a function of the parallelism budget: compute the total-machine-budget crossover W\* and report which side of it every field size sits on

**Tracked object** — TO-ACCESS, projected to the **budget allocation vector** `(w, n, Q)` = (shared

**Mechanism, with its inheritance stated first** — Every quantum input below is
**UNVERIFIED-RELAYED**: primary sources are unreachable, and C2-9 already records that the

**Prediction (MODELED-HERE, from relayed inputs)** — The curves cross at
**`W* = p^{1/6}`**, independent of the constants: `p^{1/2}/W^{3/2} = p^{1/3}/W^{1/2} ⟺ W = p^{1/6}`.

computation may only be advantageous to reduce the amount of memory, with the same time

exponent.

field size ⇒ the crossover is unreachable, the quantum branch dominates at all realistic budgets,

### Q2-7. The table is a replayable prefix tree: enumeration costs zero memory, so all M words are join buffer — and the replay branch is charged at the cheap step law

**Tracked object** — the **DFS frontier**: the stack of at most `depth` partial walks held during a
depth-first traversal of `L(E,X,B)`, projected from the full table. **Discards**: every entry not
on the current root-path — i.e. `M − O(depth·B)` of them. This is the sharpest lossy projection in
the slice: the discarded entries are recoverable *only by recomputation*, and pricing that
recomputation is the entry's content.

**Mechanism** — Algorithm 1 (L143–L152) builds entries by **extension**, and L147 says entries may
be represented as *sequences of elliptic curves*. So `L(E,X,B)` is a prefix-closed set of walks —
a tree with `M` leaves — and a depth-first traversal enumerates all `M` entries holding only the
root-path plus the sibling frontier: `depth ≤ log2 X = 49.6` levels × `≤ ℓ+1 ≤ 2^{14.2}` siblings
= `2^{19.8}` entries at NIST-I. **Therefore the algorithm's `2^{93.28}`-entry memory requirement is
100 % join buffer and 0 % generation requirement**, and the honest low-memory object is not vOW at
all but a **replayed streaming join**: partition the key space into `M/w` buckets and make one full
DFS pass per bucket, keeping only in-bucket entries. That is the `M²/w` curve C2-1 uses as an
ordering control — but with a decisive difference C2-1 cannot see: **replay steps are chained
extension steps (the cheap, amortised law), whereas vOW steps are fresh independent samples (the
expensive law, 13.5–16 bits more per step by C2-2's measurement)**. The two branches are charged in
incommensurable units, and the crossover in `w` follows from setting them equal.

**Prediction (MODELED-HERE)** — `M²/w · c_cheap = M^{3/2}w^{−1/2}·c_exp ⟺ (M/w)^{1/2} =
c_exp/c_cheap = 2^{13.5…16} ⟺ w = M/2^{27…32} = 2^{61.3}…2^{66.3}` at NIST-I. So **above
`w ≈ 2^{61}–2^{66}` the replay branch beats vOW, and below it vOW wins** — a crossover 31–36 bits
above the campaign's headline `w = 2^{30}`, which has never been computed. Combined with Q2-1 the
frontier has three regimes: flat at `T = M/P0` for `w ≥ mass(τ) = 2^{69.7}` (Q2-1's threshold
point), replay-streaming for `2^{61…66} ≤ w < 2^{69.7}`, vOW below. Second prediction, testable and
cheap: the DFS frontier is `≤ 2^{19.8}` entries at NIST-I, so **no memory statement about this
algorithm may attribute any part of `M` to table construction** — a correction to the phrasing in
every margin row, not to any number.

**Minimal discriminating test** — (i) Toy verification of the frontier bound: build
`L(E,X,B)` at `log2 p ∈ [20,32]`, `B ≤ 100`, `ℓ ≤ 7` twice — once materialised, once by DFS —

multiset** of entries as the materialised build (a set-equality assertion, not a statistic).
(iii) Zero-compute arithmetic for the three-regime frontier under both vOW anchors, both cost laws
and the 18 committed γ readings. **Known-answer gate** — the DFS peak must be `≤ depth·(B+1)` and

**Falsifier (numeric)** — DFS peak exceeding `depth·(B+1)` by more than 2× ⇒ the tree model of

**Charged cost** — implementation low–medium (a DFS builder over the existing toy harness);

### Q2-8. The toy tables are in the wrong regime and it is computable how wrong: the coverage ratio ρ = 12M/p, and the ρ-stability test every toy statistic in this slice must pass

**Tracked object** — the **occupancy histogram** of the codomain key space: `(n_k)_{k≥0}` where
`n_k` = number of supersingular `j`-invariants that are the codomain of exactly `k` table entries.
**Discards**: which curve, which entry, which degree, the entire algebra — it keeps a histogram.

**Mechanism** — Every toy experiment on the search side of this campaign — C2-5's filter survival,

exhaustively at `log2 p ≤ 40` and measures a **collision-flavoured** statistic on it. Collision
statistics are functions of `ρ`. With `X = B^{1/2}(p/2)^{1/6}` and `M ≈ Ψ(X,B)·X`, we get
`ρ ≈ B·p^{−2/3+o(1)}` — so `ρ` is not a free knob, it is pinned by `p` and `B`, and it decays like
`p^{−2/3}`. At crypto scale `ρ = 2^{93.28−252.42} = 2^{−159.14}`; at the reachable toy scales it is

`B = 100`, `M ≈ 2^{18.4}`). **The gap is 141–154 octaves and no reachable `p` closes it**: driving
`ρ` to `2^{−159}` needs `p ≥ B^{3/2}·2^{238.7}`, i.e. only at cryptographic size, by construction. The sting that makes this operational rather than
pedantic: expected *ordinary* collisions in the table are `M²/(2·p/12)`, which is
**`2^{4.6} ≈ 24` at `p = 2^{20}`** and **`2^{−66.9}` at NIST-I**. An ordinary collision (two
distinct cyclic entries sharing a codomain) yields a non-scalar endomorphism directly — so **the
toy object solves OneEnd by accident dozens of times per build, and the cryptographic object never
does.** Any statistic that touches collisions is measuring a saturated regime the attack does not
occupy.

**Prediction** — Partition the statistics in play into `ρ`-stable and `ρ`-unstable. Predicted

the classification **with a measurement behind each row**, not the opinion.

`ρ′ ∈ {ρ, ρ/4, ρ/16, …, ρ/2^{10}}` compute each statistic on a uniform random **subsample** of the
entries of the corresponding size, with 200 bootstrap resamples per level, and fit each statistic's
dependence on `log ρ′`. A statistic whose fitted slope is indistinguishable from 0 across three
field sizes is declared `ρ`-stable **for the tested range only**; any other is declared
non-extrapolable and every downstream use must carry the label. **Known-answer gate** — the
expected number of ordinary collisions in a subsample of size `m` must follow the exact
hypergeometric/binomial prediction `m(m−1)/(2·p/12)` to within its interval at every level; an
instrument that misses the one quantity whose law is known in closed form has no power over the
ones whose law is not. **Second gate**: at `ρ′ = ρ` every statistic must reproduce its committed
full-table value bit-for-bit.

**Falsifier (numeric)** — All statistics `ρ`-stable with slope within `2σ` of 0 at all three field
sizes, with the hypergeometric gate passing ⇒ the concern is void, toy results in this slice
transfer in this respect, and the campaign gains a validity control it does not currently have.

### Q2-9. Two roots, not one: the covering exponent 1/3 and the birthday exponent 1/2 live in the same table, and the birthday branch is a heuristic-free baseline chargeable in the campaign's own units

**Tracked object** — TO-MASS again, read through a single scalar: the **expected number of
unordered entry pairs sharing a codomain**, `C(M) = M²/(2·p/12)`, as a function of the list size

structure. Structurally lossy; `C(M)` is one number summarising `M²/2` pairs.

**Mechanism** — Algorithm 2 succeeds by a **covering** argument: the table is *designed* to contain
the two halves of the specific minimal isogeny `φ`, which requires (a) Theorem 1.5's bound
`deg φ ≤ (p/2)^{1/3}` (L81), (b) `deg φ` B-smooth — Heuristic 1, contributing `P0 = 2^{−15.45}` —
and (c) the split lemma. That is where `θ = 1/3` comes from. But the same table supports a second,
completely independent success mechanism: **any** two distinct cyclic entries `ψ₁ ≠ ψ₂` sharing a
codomain give `ψ̂₂ ∘ ψ₁ ∈ End(E)`, non-scalar for `ψ₁ ≠ ±ψ₂` because both are cyclic of smooth
degree — which is an output of **OneEnd**, the very problem being solved. This branch needs
**no Heuristic 1, no GRH, and no Theorem 1.5**; it needs only `C(M) ≥ 1`, i.e. `M ≥ √(p/12)`,
`θ = 1/2`. So the algorithm's own table carries two roots — a **covering root at 1/3** and a
**birthday root at 1/2** — and the campaign has only ever costed the first.

### Q2-10. Measure the alignment exponent: the L2/A4 exchange rate has two pre-computed nulls and no measurement, and the fibre is where a restriction can be aligned or not

**Tracked object** — TO-FIBRE with a **declared restriction predicate** attached:
`R: (walk-choice sequence) ↦ {keep, drop}`, tracked through the triple
`(Pr[ψ kept], Pr[χ kept], Pr[both kept])` over the golden pairs. **Discards**: the degree, the
codomain, the field data, and everything about *which* entry — it keeps three probabilities per
predicate. Structurally lossy: the fibre over a triple is the entire family of tables realising it.

**Mechanism** — DEC-20260805-2be965 records that the generic list-restriction exchange rate is
`e = 2δ` (worse than the 1:1 the original obstruction field assumed), and pre-computes **both**
nulls: **independent** ⇒ strictly worse than 1/3, **aligned** ⇒ **exact break-even at 1/3 for every
δ**. The open problem it leaves is stated in the goal record verbatim: *is there any restriction
whose exchange rate beats the aligned null's exact break-even?* Every candidate must therefore be
placed on the interval `e ∈ [1, 2]`, and **`e` has never been measured for any concrete family**.
The natural home for such a family is the fibre: a restriction on *walk choices* shrinks the list
without touching the degree, so it leaves the smoothness argument (C1's TO-MULT) completely
unchanged and isolates the alignment question. The pair `(ψ, χ)` is the golden pair of Lemma 3.4;
`ψ` is a **prefix** of `φ` and `χ = η̂^{(p)}` is the conjugate of its **suffix**, so there is no
a-priori reason for their choice sequences to be correlated — and no a-priori proof that they are
not. That is exactly what a measurement is for.

**Prediction** — For the walk-choice family, `e` measured at `2.0 ± 0.05` (independent), i.e. the
fibre offers **no** alignment and the aligned null is unreachable through TO-FIBRE. Expected
verdict: **CLOSED with a mechanism** — "walk-choice restrictions are independent across the prefix
and the conjugated suffix, so they realise the worse of the two pre-computed nulls." The single
outcome that would overturn it, and the reason the experiment is worth running, is `e ≤ 1.5` for
any declared member, which would be the first measured evidence that lever L2/A4 has a
better-than-generic exchange rate available anywhere.

**Minimal discriminating test** — Declared family, frozen before the run, **walk-choice only** (any
predicate reading the codomain belongs to C2-5 and is used here as a control, not as a candidate):
`R₁` = keep entries whose ℓ-step root index is even at every step (`f = 2^{−n_ψ}`);
`R₂` = keep the `k` smallest roots (fixed F_{p^2} ordering) at each step, `k ∈ {1, 2, 4}`;
`R₃` = keep entries whose choice sequence hashes into a prescribed `2^{−t}` fraction;
`R₄` = keep entries whose primes are used in non-decreasing order. On the shared toy table at
`log2 p ∈ [20, 32]`, `B ≤ 100`, `ℓ ≤ 7`, locate **all** golden pairs by exhaustive matching, then
for each predicate measure the three probabilities and fit
`e = log Pr[both kept] / log Pr[one kept]` with bootstrap intervals.
**Known-answer gate — two-sided.** (a) **Positive control at `e = 1`**: a σ-stable predicate on the
codomain key (C2-4's object — e.g. low bits of `Tr(j)`) must return `e = 1.00 ± 0.05`, because
`ψ` and `χ` have keys `E′` and `E′^{(p)}` and a σ-stable predicate keeps both or neither *by
construction*. If the instrument does not return 1 there, it cannot measure alignment and the run
stops. (b) **Negative control at `e = 2`**: a predicate driven by an independent per-entry random
seed must return `e = 2.00 ± 0.05`. An instrument that cannot separate 1 from 2 on the two cases
whose answers are known in advance has no power over the cases whose answers are not.

**Falsifier (numeric)** — Every declared walk-choice predicate returning `e ≥ 1.9` with both gates
passing ⇒ CLOSED for the declared family at the tested scale, with forward guidance naming the
surviving routes (σ-stable key predicates, which are C2-5's and are free only down to `f = 1/R`;
and multi-instance amortisation A5/A7, which is a different composition entirely). Any predicate
returning `e ≤ 1.5` with both gates passing ⇒ promote to a hypothesis and re-measure at a second
field size before anything else is done with it. `e` outside `[1, 2]` ⇒ instrument fault, not a
finding.

**Charged cost** — implementation medium (predicate harness over the shared exhaustive toy table
with all golden pairs located; the table build is the batch's cost, not this entry's). Compute
≤ 3 CPU-hours. **Charged and not waived**: a walk-choice predicate prunes at *build* time, so it
buys time as well as memory **only if it is per-step prunable** — `R₁`, `R₂` and `R₄` are, `R₃` is
not, and the report must separate them and never net them (this is C2-5's prunability distinction,
consumed here, not re-derived). Charged also: the sampling of golden pairs must be exhaustive, not
truncated — EV-SSIQ-48d274 establishes at derivation tier that budget-truncated searches bias the
returned value **upward**, and a truncated pair census would bias `e` in an uncontrolled direction.

**Ceiling** — `toy`, hard: four predicates on tables at `log2 p ≤ 32`. Risk band: **high_risk**.

**Nearest prior-art neighbour** — **C2-5** (`sigma_stable_prunable_filter | spend_R_multiplicity_on_density_f | free_exchange_down_to_f=1/R`).
**Why it is not that**: C2-5 filters the **key space**, prices the filter against the golden-claw
multiplicity `R`, and asks whether a per-step prunable σ-stable predicate exists. Q2-10 filters the
