# Prospective solver-validation and baseline comparison contract

25 October 2026. Same-session prospective review. This is a recommendation for the new source/input freeze, not an approval, independent scientific review, execution receipt or measured result. No scientific cohort was run for this note. The earlier frozen sources and observations are unchanged.

## Objective and experimental unit

Establish a checked working solver, then measure its cost against explicit baselines. Correctness, incremental improvement and novelty are separate questions. Credit an improvement at the scope actually measured.

The finalized draft has 48 fresh ordinary, non-anomalous, non-special-j curves: twelve at each subgroup size 12/14/16/18 bits, split six unrestricted-ordinary and six p=1 mod 5 curves. Sixteen independently uniform canonical scalars per curve give 768 confirmation targets. Public generation/rejection history, public cardinality/subgroup certificates, public target manifests and withheld-label commitments must be source-bound before measurement. Reject prior curves by (p,a,b), not merely by fixture ID. Forced k=0,1,r-1 and malformed/outside-subgroup cases belong to a separate fixed correctness suite.

This increases both subgroup sizes and sample count: twice the curves and four times the targets of the previous 24-curve/192-target follow-up. The root Coordinator has confirmed the full 768-target panel as primary; bind that choice in the prospective admission package. A fixed nested core contains the first three curves in each size/stratum cell and their first eight target ordinals: 24 curves/192 targets. The remaining 576 targets are the extension (192 later targets on core curves plus 384 targets on the other 24 curves). Freeze this index-based selection before opening outputs. Core and full-panel results overlap and are not independent evidence to combine. Curves are the independent replication units; targets share curve arithmetic and preprocessing.

## Frozen candidate and named arms

The primary candidate configuration is x_mod_7, exact public prefixes, beam width 8, four public offset views, 2,048 training samples and the existing fixed training/tie domains. This choice is explicitly informed by the old toy results; the new curves are its fresh confirmation cohort. Do not choose a different winning configuration after opening these results.

1. **Candidate alone:** the frozen bounded candidate list and its actual public-equation checks. A miss is an ordinary bounded-candidate miss. It is neither a malformed output nor a complete solver success.
2. **Rho:** the actual upstream AutoRho implementation and its pinned source adapter, with its stated negation/cycle policy, table construction, restart rules, seed and real verification work.
3. **Primary complete hybrid:** exactly the primary candidate, followed on a miss by the same rho implementation and same target-specific random stream as the paired rho arm. A candidate hit ends the hybrid after verification. A candidate miss does not alter the rho walk, seed, restart sequence or collision handling.
4. **Bernstein-Lange precomputation:** include the actual documented implementation/adapter when ready, with table parameters, construction limits and reuse count frozen. Preserve table-build and online failures. Do not relabel BSGS as cube-root precomputation. If this arm is unavailable, name that missing comparison and continue the runnable arms without claiming a result against it.
5. **BSGS:** a separately named exact reference with its real memory footprint. It is not an unreported rescue path for rho or Bernstein-Lange. If any declared complete solver internally includes BSGS rescue, name the combined algorithm and charge that rescue explicitly.

The remaining feature/mode/beam combinations are secondary confirmation observations. Their union is not the primary candidate's success rate, and their execution cost is not silently assigned to or omitted from the primary solver.

## Correctness and preservation criteria

Every public returned scalar must be canonical and satisfy [k]P=Q in separately coded arithmetic that does not import the solver's group operations. The output checker recompiles/replays that check and verifies code/input/output digests. Private scalar labels and generation seeds are not candidate or verifier inputs. Describe source-enforced separation honestly; it is not an OS-isolated blindness certificate.

Before launch, fixed development tests must cover identity, inverse points, doubling exceptions, nontrivial cofactors, malformed/noncanonical inputs, nonmember targets and known wrong witness mutations. The independent verifier must reject deliberately corrupted witnesses and points. A wrong output invalidates the affected implementation/measurement; a prefix miss is a valid recorded miss; a watchdog/resource stop is censored. A bounded rho/restart or online-precomputation miss must remain visible even if another separately named arm solves that target.

The working-solver milestone is all 768 random targets plus the separate correctness suite returning checked answers for each declared complete arm within the actual run. Report solved/failed/censored/invalid/not-applicable counts, not only successful averages. Achieving complete hybrid correctness via fallback does not establish that the candidate alone solves every target; retain the origin of every answer as candidate or fallback.

## Matching, randomness and caches

Use the same public targets, arithmetic backend, C++ compiler/flags, subgroup certificates, scalar range and thread count. Freeze baseline tuning on development inputs. Give every primary arm its own fresh Ops object, caches and required state. In the old matrix, later features can reuse the Tonelli nonresidue cache; those incremental feature costs are not standalone cold costs. Run the primary hybrid separately with only its own primary feature/kernel.

Derive independent public seed domains for arm order, input generation, candidate training/views and solver random walks. The paired rho/hybrid fallback intentionally share the same target-specific rho seed and restart sequence. Do not reuse a rho r-adding table for free: its Q-dependent construction belongs to each solve/fallback invocation. Base-specific fixed-base tables may be shared only under the declared per-curve reuse model, with construction charged once to each algorithm.

Randomize paired arm order using the frozen order stream. Preserve all seeds. Include the declared fresh-state, identical-seed rho A/A repeats as repeatability controls: check equal answers and deterministic work counters, and retain CPU/wall differences. An exact same-seed baseline rerun is an A/A repeatability check, not a new stochastic replicate. Independent-seed robustness probes, if added, must be declared before freeze and reported separately; targets repeated with new solver coins are not new independent curves or extra distinct targets for amortization.

## Primary cost definition

Record full algorithm CPU time and its stage decomposition, plus the complete operation vector. With three concurrent curve workers, wall intervals are descriptive unless controlled placement and A/A evidence justify a wall-time comparison. Per-arm process CPU intervals can be taken around solver construction/work/verification in its otherwise single-threaded process; if an imported library spawns threads, include their CPU and state its thread count. Place timing boundaries outside JSON/log formatting and input-custody/report work. Do not subtract guessed diagnostic overhead from an interval that actually executed it.

Group-add calls, scalar-mul calls, field operations, powers/inversions, DP terms, logarithms, sorting/hash work and allocation bytes have different units. Scalar multiplication already invokes group operations; inversions/powers invoke field multiplies. Do not add those nested counters as disjoint primitive work. Field-multiply-only or group-add-only savings are component observations because the candidate's DP/log/sort cost can dominate full CPU cost.

Let A_c be actual required algorithm setup for curve c and W_ci the actual target work through final verification. For the hybrid, W_ci includes views, search, every candidate check, and all fallback table/walk/restart/recovery/check work on a miss. Report:

* Cold target cost C_ci = A_c + W_ci for every target i. These are counterfactual cold-use totals reconstructed from measured stage costs unless setup was actually rerun for each target; label that distinction.
* Sixteen-target full batch cost B_c = A_c + sum_i W_ci, with exactly m=16 targets. For the predeclared nested core only, compute its separate eight-target batch with m=8 on the 24 core curves.
* Full-panel amortized cost B_c/16 and online-only W_ci beside setup; the nested core has its own B_core,c/8 total and is not an extra independent replication. Do not amortize over secondary configurations or robustness reruns as though they were additional target logarithms.
* Paired per-curve hybrid/rho ratios B_hybrid,c / B_rho,c for full CPU cost and separately named component counters. Rho setup must be assigned consistently: target-specific setup belongs in W, reusable base-only setup in A.
* Bernstein-Lange cold, online and m=16 full-panel / m=8 nested-core batch totals with its actual one-time table. Its documented n^(1/3) online regime is not a single-target cold-cost assertion.

Separate fully retained **study overhead** from required algorithm work: input certification/cohort generation, independent output replay, heldout calibration, Dobrushin diagnostics, secondary configurations and plotting. Required constructor/kernel training, target generation used by the algorithm, all failed candidate checks and all solver verification remain algorithm work. If the primary implementation always computes diagnostics during its constructor, charge the actual executed constructor interval or remove that diagnostic path prospectively without changing its trained kernel/candidates. A fresh train(...,diagnostics=false) API can be checked for identical development kernels/lists before freeze.

Persistent advice/table bytes, peak live algorithm payload and real process RSS are separate fields. A process-wide RSS high-water mark spanning sequential arms is not an individual arm's peak; use isolated arm processes or label that limitation. Vector payload formulas are lower bounds unless object/capacity/allocator overhead is also measured. Preserve preprocessing tables/checkpoints or their exact reconstruction bindings and content hashes.

## Estimators, uncertainty and interpretation

Print every per-target outcome and per-curve total. Primary paired summaries give each curve equal weight. Require finite, strictly positive CPU denominators and numerators for a CPU ratio. A zero-duration interval can be below timer resolution rather than a mathematical failure; preserve it as unresolved timing, do not divide by zero, fabricate a floor or call it infinite speedup. Invalid outputs have no qualified performance ratio. Report the full requested count and the comparable-pair count, with every exclusion named. For each size, report all twelve full-panel curve ratios, their geometric mean and range; strata each have six curves. Separately report the predeclared core with six curves per size and three per stratum, labeling its coarser uncertainty. For the whole panel, report the equal-curve geometric mean with each size equally represented. Use m=16 only for full-panel reuse, m=8 only for the fixed core; do not select whichever amortization makes an arm look best after seeing results. Also retain raw arithmetic sums, so ratio-of-sums and mean-of-ratios cannot be confused.

A fixed-seed curve-cluster bootstrap may give descriptive 95% intervals by resampling curves within size/stratum; predeclare its seed and replicate count (for example 10,000). It does not repair the very small number of clusters or turn repeated targets into independent observations. Report the identical-seed rho A/A CPU-ratio/difference spread beside the hybrid comparison; do not silently subtract it from candidate costs or retrofit a gain threshold to it. If the apparent difference is comparable with repeatability noise, say so. There is no power claim without an explicit calculation. If any denominator is zero, if outputs are invalid, or if censoring affects a pair, retain it and avoid a successful-only qualified speed ratio. Report the actual consumed work and outcomes; use a separately justified model before extrapolating censored full costs. A valid-pair-only descriptive ratio must state its subset and cannot qualify a full-panel gain while other requested pairs are censored or invalid.

Do not make a binary performance direction part of completion. Correctness/custody completion is successful even when cost ratios exceed one or intervals cross one. An observed gain at these sizes is progress at this measured scope; an uncertain comparison is uncertain, and a measured slowdown applies to this frozen candidate/regime. A claimed qualified performance gain needs the repository's matched evidence record and independent review. Neither this note nor a child agent's same-session check supplies that review.

Descriptive measured scaling at 12/14/16/18 subgroup bits is a useful output of this study. No asymptotic exponent follows from those four small sizes. An exploratory fit, if separately declared, must state its model and tested range and remain distinct from a proved n^(1/4) algorithm or a verified n^(1/3) baseline scaling law. More importantly for the next iteration, record the measured dominant stage, answer origin, memory/reuse tradeoff and the next concrete implementation change. Novelty remains a separate assessment.

## Operational envelope

Use no more than three independent curve workers plus the driver under the four-core/16 GiB host allocation, with a declared memory limit below that allocation and one solver thread per worker. No scientific process starts before the actual exact-byte admission, published approval and live ownership claim required by the unchanged runner. Per-job/trial watchdogs protect the host and classify censoring; they are not mathematical stopping theorems or lifetime research spending caps.

The expanded secondary matrix can approach 12,288 target rows plus kernel/NA rows before baseline and verification streams; freeze serialization and enough part slots for that larger volume. Keep the complete parts manifest below the canonical 1 MiB JSON-metadata threshold rather than assuming the old 256 slots suffice. Preserve complete JSONL outputs in reconstructable <=60 KiB parts, with logical stream hashes/lengths/row counts and all empty/failed outcomes retained. The exact producer and verifier streams, stdout/stderr, commands, compiler/source/binary identities, timing units and actual resource observations must be sealed before analysis. Never edit the old run, silently change a frozen parameter, prewrite an approval or manufacture a completed receipt.
