# Six-class native routing and trail audit, exploratory run

Question: do the new native Rust routing counts reconcile with class visits, and can an independent restricted container replay the published secp256k1 DP from its deterministic start?

Workloads and controls: the planted p25 public job at SHA-256 `c938c2d2ce5f08369fb106ff2c7b02d352519ab2656b8c541e92739b6955e69f`, 100 maximum walkers, two deterministic baseline/six-class/baseline trials; and the already published isolated secp256k1 public job at SHA-256 `81bd38d6e82cc3f04428e770835539a06832e6a2c2850cfd844366f1a07c99eb`, walker 0, step 9. No new private scalar or challenge was generated. The p25 protocol and results were published together; this is exploratory, not a held-out H1 test.

Commands: build `crypto` revision `f6eb34d02` with `cargo build --release --bin six_class_rho --bin six_class_compare`; run `python -m harness.sixclass_paired --job harness/fixtures/sixclass_p25.json --binary /home/ec2-user/crypto-sixclass-rho-20261023/target/release/six_class_compare --walkers 100 --trials 2 --sudo --out harness/evidence/sixclass-paired-routing-p25-20261024.json`; run `python -m harness.sixclass_isolated --sudo audit` on the published public secp256k1 job and `first-dp.json`, then `--sudo run` on that same job with one walker. The latter automatically launched a second container for trail replay. All containers used the digest-pinned Debian bookworm image in the raw receipts, no network, a read-only root, and no private audit mount for worker or auditor.

Environment: x86-64 Intel Xeon 6975P-C, 32 visible CPUs; Rust 1.99.1; Docker 25.0.14. The compare binary SHA-256 is `ca0cfae9f5b5d50b5704616ad2f8fa722f998dd4aef732e67bda5676ec451a72`; the worker binary SHA-256 is `281f4bac4ef92ab0e0559c04c8f836669158143ee5ee29699a974f3f2e7b3363`. The harness source was branch `codex/sixclass-rho-20261023` after commit `b7b670e03b`, with the trail-audit addition in the working tree during execution.

Raw evidence: [paired routing receipt](sixclass-paired-routing-p25-20261024.json), SHA-256 `0a69e0386b3db36f444b7ef775e1dce8c88d289a50b5f58e39de5e147db1f7ef`; [sample trail audit](sixclass-isolated-secp256k1-20261024/trail-audit-receipt.json), SHA-256 `455ef496ba01430229a01c1805b5adfc2b9fbf002082823f255f69dfb87955a1`; [automatic worker/audit receipt](sixclass-isolated-secp256k1-20261024/worker-receipt-trail-audited.json); [H1 coverage](sixclass-h1-routing-and-trail-20261024.json). The prior public job, DP, and original worker receipt remain unchanged. The audit checks the record hash and job hash, then recomputes the full deterministic trail in native Rust.

Observations: both p25 trials recorded 1,683 six-class visits, and the sum of all six-by-32 routing cells equals 1,683 in each. Baseline-before / candidate / baseline-after times were 982,429 / 1,670,261 / 954,421 ns and 953,364 / 1,647,511 / 936,615 ns. Candidate time divided by the bracketed baseline mean was 1.725 and 1.743, respectively: a loss in this small diagnostic. The original secp256k1 DP replayed successfully at walker 0, step 9 in a separate container, and the new one-walker run produced the same endpoint with an automatic native replay. The harness's independent point equation check and all eight targeted methodology/challenge tests passed.

Limits: the two p25 rows repeat one deterministic job and do not estimate collision success. Walk visits within a trail are correlated, so routing counts alone do not validate bit independence or twist uniformity. One secp256k1 trail replay establishes that endpoint's provenance, not a distributional return bound. Field primitive costs, allocator and memory high-water, network/coordinator work, success amplification, and production-scale collision CDF remain unpriced or unmeasured. The five-clause H1 ledger therefore leaves every clause open and `production_claim_admissible=false`.
