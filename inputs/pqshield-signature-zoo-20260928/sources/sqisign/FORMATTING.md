# Code formatting

This project formats all C code with [`clang-format`](https://clang.llvm.org/docs/ClangFormat.html) 18.1.6, using the
style in [`.clang-format`](.clang-format). CI rejects incorrectly formatted code. The version is pinned because
different clang-format releases format the same code differently.

## Quick start

Run this once per clone:

```
pre-commit install --install-hooks
```

It downloads the right clang-format for you, so you do **not** need to install clang-format yourself. If you don't have
`pre-commit`, see [Installing pre-commit](#installing-pre-commit).

## The commit blocker

`git commit` now reformats the `.c` and `.h` files you have staged, and refuses the commit if it changed anything:

```
$ git commit -m "Add widget"
clang-format.............................................................Failed
- hook id: clang-format
- files were modified by this hook
```

**Your files have already been fixed** — the corrected versions are sitting in your working tree, unstaged. Stage them
and commit again:

```
$ git add -u
$ git commit -m "Add widget"
```

Notes:

- Only **staged** files are looked at, so a badly formatted file elsewhere in the tree will never block your commit.
- Git hooks are not part of the repository, so every fresh clone needs the quick start command run again.
- `git commit --no-verify` (or `SKIP=clang-format git commit`) bypasses the hook. CI will still complain.
- **Do not run `pre-commit autoupdate`** — it installs a newer clang version, and CI will fail from now on.

## Installing pre-commit

Any of these work; pick the first one that applies to you.

```
pipx install pre-commit
uv tool install pre-commit
conda install -c conda-forge pre-commit
brew install pre-commit                  # macOS / Linuxbrew
sudo apt install pre-commit              # Debian 12+, Ubuntu 24.04+
sudo dnf install pre-commit              # Fedora
sudo pacman -S python-pre-commit         # Arch
sudo zypper install python3-pre-commit   # openSUSE
```

`pip install --user pre-commit` is refused with `error: externally-managed-environment` on recent Python installations;
use one of the above, or a virtual environment.

## Formatting the whole tree

From inside your build directory:

```
make format          # reformat everything in place
make check-format    # report problems, change nothing
```

equivalently `cmake --build build --target format` / `--target check-format`, or directly:

```
scripts/format.sh                  # reformat everything
scripts/format.sh --check          # report problems, change nothing
scripts/format.sh src/gf src/ec    # restrict to certain paths
```

These use the clang-format that `pre-commit` downloaded, so the quick start above is the only prerequisite —
you don't need to install clang-format yourself. To use a different binary (it must still be 18.x):

```
CLANG_FORMAT=/opt/homebrew/opt/llvm@18/bin/clang-format scripts/format.sh --check
```

## Installing clang-format 18.1.6 yourself

Only needed if you want your editor to format on save; the hook and the commands above get it from `pre-commit`.

```
uv tool install clang-format==18.1.6
pipx install clang-format==18.1.6
conda install -c conda-forge clang-format=18.1.6
sudo apt install clang-format-18      # some 18.1.x, which is fine
brew install llvm@18                  # NOT `brew install clang-format`, which installs the latest
```

Homebrew's `llvm@18` is not linked into `PATH`; its binary is at `/opt/homebrew/opt/llvm@18/bin/clang-format`.

## Why 18.1.6

It is what [`.pre-commit-config.yaml`](.pre-commit-config.yaml) pins, what CI installs, and the version
[`.clang-format`](.clang-format) was generated by. Any 18.1.x is fine; other major versions are not — for instance,
clang-format 22 reformats roughly 60% more lines of this tree than 18 does.

## What is not formatted

Vendored and generated code, listed under `exclude:` in [`.pre-commit-config.yaml`](.pre-commit-config.yaml), which is
the single source of truth for the hook, the build targets and CI alike:

- `src/precomp/`
- `src/gf/ref/lvl{1,3,5}/fp_p*.c`
- `include/sqisign_namespace.h`
- `src/quaternion/ref/lvlx/internal_quaternion_headers/dpe.h`
- `src/common/ref/aes_c.c`, `src/common/ref/include/aes.h`
- `src/common/ref/randombytes_ctrdrbg.c`
- `src/common/generic/fips202.c`, `src/common/generic/include/fips202.h`
- `src/common/generic/randombytes_system.c`
- `src/common/generic/include/bench_macos.h`
- `apps/PQCgenKAT_sign.c`, `apps/PQCgenKAT_sign_pqm4.c`
- `test/test_kat.c`

Assembly files (`.S`) are not formatted: clang-format does not understand GAS syntax. For individual regions that must
keep their hand-made layout, wrap them in guards:

```c
// clang-format off
    ...
// clang-format on
```
